# QA シミュレーション結果

ヘッドレス自動プレイ（`src/qa/bot.ts` のヒューリスティック bot）による長時間シミュレーションの結果。
`SIM_FULL=1 npx vitest run src/qa/simulation.test.ts` で生成。

- 実行: 30 seed（50000〜50029） × 装備 3 パターン（empty / rareLoadout / uniqueLoadout） × 60,000 ステップ（≒1000 秒）= 90 run
- 生成日時: 2026-09-22T21:50:06.350Z（このリポジトリ上での実測値。以後のコード変更で数値は変わり得る）
- bot について: 最寄りの交戦中の敵に照準して距離に応じ近接/射撃、windup・strike を検知したら 70% の確率で逆方向にダッシュ回避（30% は「人間らしい」見逃し）、敵がいなければタイルグリッド上の BFS 経路で未クリア部屋 → 階段の順に移動する。祝福（boon）3 択が出た場合は bot 専用 RNG で 1 枚をランダムに選ぶ。パーフェクトプレイはしないため、死亡率や到達 depth は「人間の上手いプレイヤー」の指標ではなく、あくまで一定水準の自動プレイでの相対比較（装備差・キーストーン差・depth 別難度）として読むこと。
- **途中経過のメモ**: 開発中に祝福 3 択（`state.boonChoice`）が追加され、選択するまで `step` が他の更新を止める仕様になったため、bot が階段を降りた直後の 3 択で恒久的に停止し、フル版の到達 depth が 2 で頭打ちになる不具合が一時発生した。`botInput` の先頭で `state.boonChoice` を最優先チェックし、`skill1Pressed`（1枚目）/`skill2Pressed`（2枚目）/`attackPressed`（3枚目）のいずれかを bot 専用 RNG で 1 回だけ選んで押し続けるよう修正済み（`src/qa/bot.ts` の `boonChoiceInput`）。本レポートの数値はこの修正後のもの。

## 1. 例外

90 run すべてで例外は 0 件。

## 2. 不変条件違反（NaN / 壁めり込み / floorItems id 重複）

NaN 混入・floorItems の id 重複は 0 件。壁めり込みは 90 run 中 7 run（8%）で検出されたが、調査の結果すべて次の 2 パターンに分類できた。

### 2-1. wisp の壁抜け（バグではない）

`wisp`（`src/data/enemies.ts` の `phasing: true`）は仕様上「壁をすり抜けて移動する」敵なので、`overlapsWall` が true になるのは意図通り。QA 側の判定 (`src/qa/simulation.test.ts` の `anyEnemyInWall`) では `phasing` な敵を除外して数えている。

### 2-2. ドアタイル上でロックされた敵が「壁の中」判定になる（軽微な不整合、要確認）

上記を除外しても発生する。以下の条件で固定再現できた（2 パターンで確認、いずれも同一原因）。

- **再現1**: seed=50000, uniqueLoadout。ステップ 27431（tick=25329, depth=5）。`knight`（id=2865, elite="hasted", phase="windup", roomIndex=4）がドアタイル上で発生。
- **再現2**: seed=50001, rareLoadout。ステップ 38478（tick=35485, depth=7）。`boar`（phase="chase"）がドアタイル上で発生。
- **現象**: 敵が部屋の **ドアタイル** の上に立っている瞬間に、プレイヤーが部屋の内側に入り `lockRoom`（`src/system/floor.ts`）が呼ばれる。ロックによりそのドアタイルが `state.lockedTiles` に追加される。`isSolidTile`（`src/system/physics.ts`）は「壁タイル (`Tile.Wall`)」と「ロック中のタイル」を区別せずどちらも solid 扱いにするため、たまたまドアタイル上にいた敵はその瞬間から `overlapsWall` 的には壁に埋まった扱いになる。
- **影響の推測**: 見た目のグラフィック破綻や即死は確認していない。ただし `moveEnemy`/`moveBody` は移動先候補だけを `overlapsWall` で判定するため、この状態になった敵がその後そのタイル付近に留まろうとする移動（`separate` によるノックバック等）を試みた場合に動けなくなる可能性がある。プレイヤー自身は `enterMargin` / `ENTER_PROBES`（`insideRoom`）でドアを跨いでいる間はロックされない配慮があるが、敵の側には同様の配慮がない非対称性がある。
- **頻度**: 90 run 中 7 run（8%。前回計測時は 18/90＝20%で、今回のbot改善や祝福による進行の違いで発生数は変動する）。

この 2-2 は今回のタスクの所有ファイル外（`src/system/physics.ts` / `src/system/floor.ts`）のため修正はしていない。バグとして扱うか仕様内の許容範囲とするかはチームの判断を仰ぎたい。

## 8. バランス所見

- **depth 2 が最大のボトルネック**: 死亡の 3 割強（25/79 件）が depth 2 で発生している。slime・bat・boar が絡む死亡が目立ち、depth 2 での敵密度・種類構成が急に厳しくなっている可能性がある。
- **死因の主役は依然として Reaper**: 全死亡の 44% に Reaper が絡む。bot はフロアクリアに時間がかかるほど Reaper の追跡から逃げ切れず倒れており、探索・戦闘の遅さがそのまま Reaper 落ちに直結する設計になっている。
- **装備差は到達depthにはっきり出ている**: 素手 2.33 → rare 5.43 → unique 4.67 と、装備を持つだけで到達 depth がほぼ倍〜2倍以上になる。rare と unique の順位が逆転している点（5.43 > 4.67）は、unique 装備の組み合わせがこの bot のプレイスタイル（distance 40px 境界での撃つ/近接判断など）と噛み合っていない可能性があり、単純な強さの序列としては読めない点に注意。
- **祝福（boon）追加により到達depthと生存率が明確に改善**: 前回計測（祝福導入前）と比較して平均到達depthが全プロフィールで上昇し（例: rareLoadout 3.20→5.43）、死亡率も下がった（rareLoadout 96.7%→80.0%）。祝福システムはランの継続力を底上げする方向に効いている。
- **キーストーンはこの bot のプレイでは概ねプラス**: 事故死を増やしている様子はなく、むしろ生存に寄与している（4章）。
- **パフォーマンスは全く問題ない**: 平均 0.02ms/step で 60fps 予算に対して余裕。

## 9. 提案

1. **depth 2 の難度カーブを緩和する**: 死亡が集中している。`enemiesPerDepth` / `depthHpScale`（`src/data/enemies.ts`）や depth 2 で解禁される敵構成を見直し、depth 1→2 の難度ジャンプを緩やかにする。
2. **Reaper 絡みの死亡が多い点への対処**: `REAPER.appearAfter` / `warnAfter` の猶予秒数を、平均フロア滞在秒（6章: depth 3 以降は 100 秒超）と突き合わせて再調整するか、Reaper を振り切りやすくする調整を検討する。
3. **unique 装備が rare 装備より到達depthで下回った点を確認する**: 8章の通り uniqueLoadout(4.67) が rareLoadout(5.43) を下回った。unique 固定キーストーンとこの bot の立ち回り（撃つ/近づく境界など）の相性が悪いのか、あるいは unique 自体の数値バランスに課題があるのか切り分けを推奨する。
4. **ドアタイルの `lockedTiles` 判定を敵にも配慮する**: 2-2 で見つけた「敵がドアタイル上でロックされると壁の中判定になる」問題。プレイヤー向けの `enterMargin`/`insideRoom` のような猶予を敵の位置にも適用するか、影響が無視できるなら「許容する既知の挙動」としてコメントを残すことを検討する。
5. **QA bot 自体の限界を踏まえた継続計測**: 今回の bot は windup/strike 検知からの回避に 30% の意図的な失敗率を入れているため、死亡率が高め（80〜100%）に出る。今後バランス調整をしたら同じ bot・同じ seed set で再計測し、死亡率や到達depthの変化を差分で見るのが良い（絶対値よりトレンドが有用）。
