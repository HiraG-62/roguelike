## 提案

1. depth 3 前後の敵密度・HPスケーリング（enemiesPerDepth / depthHpScale）を見直し、難度の急上昇を緩和する。
2. 死因トップの敵（kingSlime）の windup 時間や被弾判定の猶予を見直し、回避余地を増やす。
3. rare / unique 装備の有無で到達depthに大きな差が出ていない場合、レアアフィックスの倍率調整でビルドの手応えを強める。
4. キーストーンつき装備が事故死を増やしている場合は、リスクに見合ったリターン（回復・被ダメ軽減の代替経路）を補強する。
5. Reaper 出現後に倒しきれず時間切れで死ぬケースが目立つ場合は、warnAfter / appearAfter の猶予時間を調整する。

### スキル威力 +30% でスキル由来与ダメ比率が動かない（48.0% → 49.6%）のは「過剰ダメージを数えない」計測のため

- 根拠: `src/qa/simulation.test.ts` の `damageEnemy` の差し替えは `dealt = before − max(0, hp)`（実際に減った生命）を数える。生命の少ない敵をスキルで倒すとき、威力を上げても数える量は敵の残り生命で頭打ちになる（過剰ダメージは捨てられる）。序盤の敵（生命 12〜50）にグレネード 33.8 / 撃ち抜き 39 は既に過剰なので、基礎威力をさらに上げても比率は伸びない
- 動かすなら: 比率は「スキルが触れた敵の数 × その敵の残り生命」で決まるので、(a) 気力回収（`MANA` の撃破・命中の回収、`skills/tuning.ts` の `manaCost`）を上げて発動回数を増やす、(b) 旋風斬りのような多段・範囲スキルを QA 標準ビルドに増やす、(c) 計測を「過剰分を含む生の威力」に変える（ただし実効の比率としては今の数え方が正しい）。担当は balance-tuner（`skills/tuning.ts` / `data/tuning.ts` の `MANA`）か QA（`simulation.test.ts`）
- あわせて怯み発生回数が 4626 → 3911（−15%）に減っている。今回のバッチのどれが交戦頻度を下げたかは未切り分け（候補: 泥の減速で敵の到達が遅い、強欲のが遺物を拾って逃げる、二度突きの猪、祝福 18 種のルール化で 1 ステップ末にずれた効果）
