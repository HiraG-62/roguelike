## 提案

1. depth 2 前後の敵密度・HPスケーリング（enemiesPerDepth / depthHpScale）を見直し、難度の急上昇を緩和する。
2. 死因トップの敵（boar）の windup 時間や被弾判定の猶予を見直し、回避余地を増やす。
3. rare / unique 装備の有無で到達depthに大きな差が出ていない場合、レアアフィックスの倍率調整でビルドの手応えを強める。
4. キーストーンつき装備が事故死を増やしている場合は、リスクに見合ったリターン（回復・被ダメ軽減の代替経路）を補強する。
5. Reaper 出現後に倒しきれず時間切れで死ぬケースが目立つ場合は、warnAfter / appearAfter の猶予時間を調整する。

### 「同時攻撃の上限超過」の計測方法はメトリクス側で切り分け済み（対応済み、本レポートのデータには未反映）

- 前回メモ: 上の「攻撃ジャンル・属性・防御の効き」節の「同時に phase===strike だった敵数の最大」は 0.0.9α（本レポートの前回版）で `全 run 中の最大 3`（上限超過 run 2 件、50007/dominantLoadout, 50017/dominantLoadout）。今回も `全 run 中の最大 3`（上限超過 2 件、50000/uniqueLoadout, 50005/uniqueLoadout）で同じ傾向が続いている。
- 対応済み: この QA を実行するために作った隔離 worktree の作成後、本体 main には `a515610`（コミットメッセージ「QA の同時攻撃計測をボス除外で切り分け」）が積まれ、`src/qa/simulation.test.ts` に `countStrikers` / `maxConcurrentNonBossStrikers` が追加され、上限超過判定を非ボス数（`system/enemies.ts` の `strikeSlotsFull` と同じ基準）でのみ行うよう修正済み。あわせて単体テストで「ボス1体+非ボスが上限いっぱい」は超過扱いにしないことを固定している。
- 未反映の理由: 本 QA 実行は手順どおり `git worktree add ... HEAD` した時点（コミット `c2cb173`）のスナップショットで走らせており、その後に main へ積まれた `a515610` は含まれていない（並行レーンの作業のため）。したがって上の指標行は旧方式（ボス込み単純カウント）のままで、前回メモの推測（ボス+取り巻きの合算で見かけ上超過している）が正しかったことは `a515610` のテストで裏付けられたが、実際に非ボスだけで上限を超えているかどうかは次回 QA（`a515610` 以降のコミットを含む状態）で再計測して確認する必要がある。
- 直すなら誰が: 計測はすでに直っている。次回 QA 担当は新しい 2 行形式（非ボス数の最大 / ボス込み総数）が出ることを確認し、非ボス側の上限超過が実際に 0 件かどうかを報告する。
