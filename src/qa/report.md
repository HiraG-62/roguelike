## 提案

1. depth 3 前後の敵密度・HPスケーリング（enemiesPerDepth / depthHpScale）を見直し、難度の急上昇を緩和する。
2. 死因トップの敵（kingSlime）の windup 時間や被弾判定の猶予を見直し、回避余地を増やす。
3. rare / unique 装備の有無で到達depthに大きな差が出ていない場合、レアアフィックスの倍率調整でビルドの手応えを強める。
4. キーストーンつき装備が事故死を増やしている場合は、リスクに見合ったリターン（回復・被ダメ軽減の代替経路）を補強する。
5. Reaper 出現後に倒しきれず時間切れで死ぬケースが目立つ場合は、warnAfter / appearAfter の猶予時間を調整する。

### スキルコスト -15% はほぼ狙いどおり効いた（要フォローアップ）

- **スキル由来の与ダメ比率**: 49.6% → 54.5%（目標 55〜65% にほぼ到達、あと 0.5pt）。マナ不足の不発回数はむしろ 54 回 → 38 回に減少（渋くなりすぎていない）。1 対 1 被弾数は 8.87 → 8.96 とほぼ変化なし。
- `system/mana.test.ts` の「序盤は満タンから既定コスト（マナ型の平均）で 3〜4 発」「自然回復だけでは平均コスト 1 発ぶんに 10 秒以上かかる」は両方通過を確認済み（マナ型スキル全 10 種の平均コストは 186.2 → 177.9、ユーザー方針「序盤の気力は渋く」は崩していない）。
- 次に踏み込むなら、あと 1 段（このコストをさらに 5〜10% 下げる、または `MANA.onKill` を上げる）で 55% ラインに届く見込み。踏み込みすぎると 65% を超えて通常攻撃が空気になるので、次回は幅を半分（5〜8%）にとどめるのが安全。

### ドロップ率の絞り込みは効果が薄い（未解決、要構造調査）

- 全深度 ×0.8 の変更にもかかわらず、拾得アイテムの合計数はほぼ動かなかった（レアリティ分布合計: 1797 個 → 1742 個、**-3.1% のみ**。狙いは -20〜30% 台）。装備パターン別の平均拾得数も一貫して減っておらず（rareLoadout 9.7 → 10.9、dualLoadout 9.8 → 11.6 のように増えたパターンすらある）。
- 推測される原因（切り分けは未実施、次のレーンへの引き継ぎ事項）:
  1. スキルコスト引き下げでプレイヤーが強くなり、平均到達 depth が全パターンでやや伸びた（例: empty 2.37→2.27 は誤差だが rare 3.10→3.20、unique 3.37→3.53）。到達 depth が伸びるとドロップ機会（部屋制圧・階層到達・撃破数）も増え、`mobDropMulByDepth` / `roomClearChanceByDepth` の削減分を相殺している可能性がある。
  2. 0.0.10α のメモに「増加の主因は `LOOT_DROP` 自体の変更ではなく、契約・流れ星まわりの乱数消費順が変わったことによる seed ごとの抽選結果の振れ」とあり、通常敵ドロップ・部屋制圧以外の経路（契約報酬、流れ星、強欲のが落とす分、名のある遺物の確定ドロップ）が拾得数の大半を占めている可能性がある。
- 次にやること: `src/system/loot.ts` の `enemyDropChance` 以外のドロップ経路（`system/contractors.ts` の契約報酬、流れ星、`ELITE_GREEDY` の詰み込み分）を QA でも内訳計測できるようにしてから、どの経路が拾得数を支配しているか特定する。それが分かるまでは `mobDropMulByDepth` をさらに下げても同じ結果になる可能性が高い。

### 怯み発生 −15%（0.0.10α比 4626→3911）の原因切り分け: 指定 3 候補はいずれも否定、むしろ逆方向

同一コード（HEAD `fcc3717`）から定数だけ切り替えて比較した（各 1 回のフル QA、30 seed × 6 装備 × 60,000 step）。

| 条件 | 怯み発生回数（合計） | baseline比 |
| --- | --- | --- |
| baseline（変更なし、HEAD） | 3957 | - |
| 泥の減速を無効化（`TERRAIN_MUD_SMOKE.mud.moveMul` を 0.6→1） | 3639 | -8.0% |
| 精鋭「強欲の」を抽選から除外（`ELITE_KINDS` から `greedy` を削除） | 3977 | +0.5%（誤差範囲） |
| 祝福の提示を完全に無効化（`offerBoons` を no-op 化） | 3498 | -11.6% |

- **候補 3 つとも「無くすとさらに怯みが減る」という、当初の仮説（これらが怯みを減らした）とは逆方向の結果**になった。つまり泥の減速・強欲の・祝福（ルール化含む祝福全体）はいずれも怯み発生を **増やす方向** に寄与している。0.0.10α→0.0.11α の怯み減少（4626→3911）の真因は、この 3 候補ではなく、0.0.11α で入った他の要素（二度突きの猪、変身 5 種による戦闘スタイルの変化、発見の報酬まわりの探索行動の変化、装備トリガー移行に伴う交戦頻度の変化など）の可能性が高い。
- 副次的な発見: 今回のスキルコスト削減（final 版、上表参照）で怯み発生回数が 3957 → 4300（**+8.7%**）に増えた。スキルの発動回数が増えると poise 蓄積の機会も増えるため、「怯み発生回数」は敵の行動よりもプレイヤー側の攻撃頻度に強く連動している可能性がある。0.0.10α→0.0.11α の減少も、まずプレイヤー側の攻撃頻度（交戦時間・スキル/近接の発動回数）の変化を疑うのが筋が良い。
- 次にやること: 交戦時間そのもの（`oneVOneSeconds` や `countEngagedEnemies` が拾っている交戦継続時間）を 0.0.10α と 0.0.11α で比較する。もし交戦時間自体が減っていれば「敵と対峙する機会が減った」が真因、変わっていなければ「1 交戦あたりの手数が減った」が真因、という切り分けができる。

### QA の観測の盲点だったカウンタを追加（`src/qa/simulation.test.ts`）

- 追加: 地形種別ごとのプレイヤー踏み込み回数（泥・煙を含む全 9 種 + 煙レイヤー別）、精鋭修飾子 21 種の出現数、SYNERGY イベント上限到達回数（`state.ruleRun.droppedEvents` の増分を検出）。状態異常の「0 件だった種類」は既存の集計から一覧を明示するようにした。
- 実測（今回の変更込みの QA、上表参照）: 精鋭は 21 種すべて 1 回以上観測（0 件なし。ただし「迅速の」が 1165 件と他の 10〜20 倍多く出ており、抽選重みの偏りの可能性がある。要確認）。地形は氷床・毒沼が多く、泥は 392 回、煙は 32 回と少なめ（`TERRAIN_MUD_SMOKE.mud.genMinDepth=2` で深度 2 以降にしか出ないため、bot の到達 depth の浅さが影響している）。状態異常の 0 件 7 種（崩勢・宣告・吸魔・彩痕・硬化・怒気・激昂）は変わらず未解決（QA 標準ビルド・装備パターンがこれらの付与経路を踏まない。担当は該当経路を実装した Agent か QA 側）。SYNERGY イベント上限到達は 180 run 中 1 回のみで、ほぼ問題ない水準。
- **注意**: このカウンタは `src/core/events.ts` の `RuleRunState.droppedEvents`（統一ルール文法移行レーンが追加中、本レポート作成時点で未コミット）に依存する。そのレーンの変更が入る前の HEAD だけで `npm run check` を回すと型エラーになるので、統合時は `core/events.ts` のマージ後に確認すること。
