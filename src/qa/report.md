## バランス所見

- depth 2 での死亡が最多（52 件 / 155 件中）。この階の難度がボトルネックになっている可能性がある。
- 死因として最も多く推測されたのは "reaper"（64 件）。
- 平均到達depth: 素手 1.63 / rare装備 5.73 / unique装備 4.60。
- キーストーン所持時の平均到達depthは非所持時より 0.52 高い（正なら強化、負ならリスクが上回っている）。
- 1 ステップの平均処理時間は 0.029ms（60fps 予算 16.6ms に対し余裕あり）。
- 平均到達depth（色配合）: 単色寄せ 3.57 / 2色 4.57 / 5色散光 5.10。

## 提案

1. depth 2 前後の敵密度・HPスケーリング（enemiesPerDepth / depthHpScale）を見直し、難度の急上昇を緩和する。
2. 死因トップの敵（reaper）の windup 時間や被弾判定の猶予を見直し、回避余地を増やす。
3. rare / unique 装備の有無で到達depthに大きな差が出ていない場合、レアアフィックスの倍率調整でビルドの手応えを強める。
4. キーストーンつき装備が事故死を増やしている場合は、リスクに見合ったリターン（回復・被ダメ軽減の代替経路）を補強する。
5. Reaper 出現後に倒しきれず時間切れで死ぬケースが目立つ場合は、warnAfter / appearAfter の猶予時間を調整する。

### ドアタイル上でロックされた敵が「壁の中」判定になる（未解消、今回は非検出。継続監視）

- **状況**: 前回のフル版（戦闘再設計 段階 1 コミット後、180 run）では `overlapsWall`（lockedTiles
  込み、`src/system/physics.ts`）判定で 3 件（1.7%）の壁めり込みを検出していた。今回のフル版
  （L6: bot の 4 スロット・マナ対応後、180 run）では **0 件**。ただし `anyEnemyInWall` の判定
  ロジック自体は前回から変更していない（`src/qa/simulation.test.ts` の定義は据え置き）。
- **0 件だった理由の推測**: 今回は bot がマナ/スキル主体で戦うよう変わり、敵の突破経路・戦闘の
  滞在時間・死亡深度の分布が前回と変わった（例: 平均到達depth 5.83→4.14 相当に低下、死因トップの
  内訳も変化）ため、問題の起きやすい経路（ドアタイル上でロックされた敵が壁扱いになる状況）に
  bot が到達する回数自体が減った可能性が高い。**根本原因（`src/system/floor.ts` の `lockRoom` /
  `src/system/physics.ts` の `isSolidTile` の非対称）は未修正のまま**なので、発生頻度が下がった
  だけで直ったとは断定できない。次回以降のフル版でも壁めり込み検出が 0 件かどうかを継続して見る
  こと（複数回 0 件が続けば経路依存の低頻度化、たまに検出されれば依然バグとして残っている根拠になる）。
- **担当**: `src/system/floor.ts`（`lockRoom` 時にドアタイル上の敵へ猶予を与える／室内側へ押し出す）
  または `src/system/physics.ts`（`isSolidTile` の壁とロックの扱いを分ける）。前回報告した固定の
  再現手順（seed=50020/50025/50028、rareLoadout/dualLoadout、特定 step の bat/eye/knight）は
  今回の装備・スキル・bot 挙動の変更で経路がずれ、再現しなかった。新しい固定 seed の再現手順は
  今回得られていない（0 件のため）。
