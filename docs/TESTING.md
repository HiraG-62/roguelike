# テストの書き方（数値の調整で壊れないテスト）

バランスの数値（`src/data/balance/**/*.json`）は手で何度も動かす。数値を変えるたびにテストを貼り直すのは調整の邪魔で、
落ちたテストが「壊れた」のか「数値が変わっただけ」なのかも見分けられなくなる（2026-10-05、小数を 1.1 倍しただけで 558 件落ちた）。
そこで **テストは数値を守らない。数値の間の関係と仕組みを守る**。数値の良し悪しは計測（`pnpm run qa:probe` / `qa:gear` / `qa:full`）で見る。

## 4 種類のテストと扱い

| 種類 | 例 | 扱い |
| --- | --- | --- |
| 制約 | 当たり判定が刃先を越えない（`data/meleeReach.test.ts`）、確率の合計が 1、上限を超えない、JSON の形（`data/balance/validate.test.ts`） | **残す**。調整のミスを捕まえる本物の価値。失敗メッセージに JSON のパス（`weapons.WEAPON.movesets.sword.steps[0].reach`）と破った制約を出す |
| 数値の写し | `expect(SCALE).toBe(0.6)`、JSON の表をテストに貼った `PINNED`、「QA 日付の値と一致」 | **書かない**。関係（下）に書き直すか消す。数値の記録は JSON 自身・`docs/BALANCE_DICTIONARY.md`・`src/qa/probe.md` が持つ |
| 指紋・黄金 | 出力全体のハッシュ、500 ステップ後の state の文字列 | **書かない**。決定性は「同じ入力を 2 回回して一致」（`core/replay.test.ts`）で見る。期待値に固定のハッシュを置かない |
| 仕組み（振る舞い） | 「輪が戻ってから振る」「怯み値が溜まると怯む」 | **数値から切り離す**。`withTuning` で数値をテストの中に固定するか、待ち時間・距離を JSON の値から計算する |

## 関係に書き直す

数値そのものではなく、調整しても保たれるべき関係を書く。

- 大小・順序: 「溜めは通常の段より威力が大きい」「深いほど強い（単調増加）」「上振れの平均はほぼ 1」
- 範囲（設計の決まり）: 「Σ係数は 0.3 以上」「下限 ×0.7 を下回らない」。範囲の端は設計資料（`docs/STATS_AND_SCALING.md` など）の決まりから取り、今の値の ±数% にしない
- 式の一致: 「表示の値 = 適用の値」「ツールチップの数字 = 計算に使う数字」。同じ定数を両方へ通して比べる
- 定数を読んで期待値を作る: `expect(dmg).toBeCloseTo(base * PLAYER.shoot.damageMul)`。期待値に数値リテラルを書かない（テストの中で `withTuning` で固定した値は書いてよい）

## 仕組みのテストは数値を固定する

`system/testHelpers.ts` の `withTuning(対象, 上書き, fn)` は、fn の間だけバランスのオブジェクトの値を上書きし、終わったら戻す。

```ts
withTuning(PLAYER, { shoot: { scaling: { base: 10 } } }, () => {
  // ここでは基礎値 10 として仕組みを確かめる。本番の JSON をいくら変えても結果は同じ
});
```

- ロジックが実際に読むオブジェクト（`data/tuning.ts` / `skills/data.ts` の再 export、`BULLETS` など）を渡す。入れ子は中身だけ書き換えるので、先に握った参照からも見える。配列は添字で `{ 0: { … } }`
- モジュールの読み込み時に計算済みの定数には効かない。効かないときは対象を読む側のオブジェクトへ移すか、待ち時間を値から計算する
- 回す長さ（フレーム数・秒数）は数値から計算する（`寿命 / 速さ` の何倍か）。「20 秒あれば足りる」のような固定の長さは調整で足りなくなる

## 検査: `pnpm run test:perturb`

バランス JSON の小数をすべて ×1.1（`--mul 0.9` で下げる向き、`--jitter` で項目ごとにばらばら）にして読み、テストを回す（JSON は書き換えない。`vitest.config.ts` が `BALANCE_PERTURB` を読む）。落ちたテストをファイルごとに数える。ファイルを渡すとそれだけ回す。

- **ここで落ちてよいのは制約のテストだけ**。新しいテストを書いたら、そのファイルを渡して ×1.1・`--mul 0.9`・`--jitter` の 3 通りで回す
- 一律の倍率では比（速さと寿命、威力と生命）が保たれるので、比を前提にしたテストは `--jitter` でしか落ちない（2026-10-05: 戦輪の弾の速さと寿命を別々に変えて bot のテストが落ちた）
- 制約のテストが落ちるのは「1.1 倍で制約を破った」ことなので正しい（刃先・確率の合計など）
