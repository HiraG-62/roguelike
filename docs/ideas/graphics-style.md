# ドット絵の様式書（自作スプライトの精細化・レーン D）

作成日: 2026-09-24
前提: `docs/ideas/graphics-design.md`（3 章 解像度・6 章 自作スプライト）。pixel-artist は描き始める前にこの文書を読む。

## 1. キャンバスと体の置き方

| 対象 | キャンバス | 描画部の目安 |
| --- | --- | --- |
| プレイヤー・通常敵（人型・獣） | 24x24 | 幅 14〜18、高さ 14〜22 |
| 小型（bat / wisp / rat / mite / beetle / fly） | 16x16（据え置き） | 幅 10〜14 |
| ゴーレム・鎧 | 32x32 | 幅 20〜26 |
| ボス | 48x48 | 幅 30〜40 |

- **足は最下段**（24x24 なら row 23）。歩き A / B の最下段は必ず埋める（`lift` した 2・4 枚目は 1 段上がる）。浮遊体（eye / laserEye / bat / wisp）は尾・触手の先を最下段に置く
- **頭上 2 行は空ける**（row 0〜1。原画で守る。`lift` した歩きの 2・4 枚目が 1 段食い込むのは可）。頭上の「!」・状態異常の印・精鋭名が重なるため。予備動作で武器を振りかぶっても row 2 まで
- **体の密度は中央 12px（24x24 なら col 6〜17）に寄せる**。当たり半径は 6 前後のままなので、見た目の芯（胴・頭・眼）はこの幅に収め、外側は耳・尾・ひれ・マント・武器・盾などの「薄い要素」にする。見た目に当たったのに外れた、を減らすため
- 右向きで描く（左は描画側が反転）。顔・眼・武器の先は右に寄せる
- 描画側は 24x24 でも足元を当たり半径から決める（B レーンの `spriteFeetY`）。キャンバス高に依存した位置合わせを絵の側でしない（下に余白を足して調整しない）

## 2. 輪郭・陰影・ハイライト

- **輪郭は `k`（#1a1a24）で 1px、全周を閉じる**。床（`l` #47424e）は中間トーンなので、輪郭と明部で浮かせる。輪郭の内側に色を直接接させない
- 光源は **左上**。明部は左上の面、暗部は右下と腹・足元
- **3 段**: ハイライト（`h` / `e` / `q` / `a` / `1` などの専用明色）→ 基本色（小文字 `g` / `p` / `o` / `b` / `s`）→ 暗部（大文字 `G` / `P` / `O` / `B` / `S`）。最暗部は輪郭 `k` に任せ、4 段目を作らない
- ハイライトは面の左上に 2〜4px の塊で置き、`1`（白）は艶の点（1〜2px）と眼・牙だけに使う
- 模様（毛・鱗・継ぎ目）は基本色の中に暗部色を 1px ずつ散らす程度。塊の模様は読みを悪くする
- 眼は右向きで「白 + 瞳」（`1k`）。瞳を右に置くと進行方向が読める。怒り・予備動作は瞳を細く（`kk` の眉）する

## 3. PALETTE の使い方と追加色の方針

- 既存 56 色で描く。**再配色種（`EnemyDef.recolor`）の swap 元の文字だけで体色を塗る**（例: slime は `g/G/h`、eye は `p/P/e`、boar は `o/O/q/r`、bomber は `g/G/h`、knight は `s/S/b/B/a`）。新しい中間色で体を塗ると再配色から漏れる。テスト「swap 元の文字が新原画に残っている」が検査する
- 再配色で変わってほしくない部位（眼の白 `1`、瞳 `k`、服 `W/w`、金具 `Y/y`、血色 `r`）は swap に入っていない文字で塗る
- 新色は「既存のどの色でも 3 段が組めない」ときだけ足す。1 文字キー（空き文字を grep で確認）、コメントに用途。明暗は大文字 / 小文字の対で足す
- 配布素材（0x72 DungeonTileset II 系）の主要色（石の灰褐色・木・骨・金具・松明の橙）8〜10 色は、C レーンで小物を自作に置き換える段階でまとめて足す（`graphics-design.md` 5.4）。キャラ用には足さない

## 4. フレーム構成

- **敵 1 体 = 原画 4 枚**: 歩き A / 歩き B / 予備動作 / 攻撃
  - 歩き: `walkCycle(A, B)`（`src/data/sprites/frameKit.ts`）で `[A, lift(A), B, lift(B)]` の 4 フレーム → `SPRITES[key]`
  - 予備動作: `SPRITES["<key>.windup"]`（1 フレーム）。**シルエットが変わる**こと（振りかぶる・縮む・頭を下げる・ひれを立てる・眼を見開く）。色だけの変化にしない（赤の点滅は描画側が重ねる）
  - 攻撃: `SPRITES["<key>.strike"]`（1 フレーム）。伸び・踏み込み・振り抜き。浮き上がり（最下段を空ける）は可
- キー名は `poseKey(key, "windup" | "strike")`（`frameKit.ts`）で作る。描画側は `render/sprites.ts` の `enemySpriteKey` が phase から選び、無ければ歩きに戻る。再配色種のポーズは `spriteSources` が元のポーズから作る
- 据え置き（bell）や擬態（mimic）は上下動させない。`walkCycle` を使わず `[A, A, B, B]` などで並べる
- ボス 48x48 = 通常 / 予備動作 / 攻撃 / 特殊 1（潰れ・伸び・跳躍準備など既存の状態数に合わせる）
- 小型 16x16 は歩き 2 原画のみでよい（群れで出るので予備動作は描画側の点滅で足りる）

## 5. ファイルの置き方

- 32 / 48 の大きな絵は scratchpad の作図補助（楕円・角丸矩形・手足の線分を左上光源の 3 段で塗り、外周に輪郭を足す）で下描きし、顔・武器・模様を手で足して、最後は文字列リテラルとして家族ファイルに貼る。リポジトリに作図補助は置かない

- 家族ごとに `src/data/sprites/<family>.ts`。`export const <FAMILY>_SPRITES: Record<string, SpriteFrames>` と、描き直したキーの一覧 `<FAMILY>_KEYS` を出す
- 原画は `const <NAME>_WALK_A: Frame = [...]`（24 行のリテラル。行の省略や生成で埋めない。差分で読めるように）
- `src/data/sprites.ts` は `SPRITES` の末尾に `...<FAMILY>_SPRITES` を足すだけ（同名の旧 16x16 を上書きする）。旧原画の削除は統合時にまとめて行う
- 家族ファイルは `sprites.ts` を **型だけ** import する（値を import すると循環する）
- `src/render/sprites.test.ts` の「描き直した敵」に `<FAMILY>_KEYS` を足す

## 6. 配布素材と並べて浮かない方針

0x72 DungeonTileset II は「暗い背景・彩度低めの茶灰・太めの黒輪郭・頭身低め（2〜2.5 頭身）」。自作キャラを隣に置くときは:
- 輪郭は黒系 1px で全周（0x72 と同じ）。アンチエイリアス・色付き輪郭（sel-out）はしない
- 彩度はキャラの識別色（スライムの緑・眼の紫など）1 系統だけを高くし、それ以外（服・金具・毛の暗部）は低彩度に落とす。背景より明るく、UI 色より暗く
- 頭身は 2〜3。頭（または眼・顔）を大きく、手足は 2〜3px 幅
- ディザは使わない（0x72 も平塗り + 1px の点で質感を出している）
- 床・壁を細かくしても、キャラは「輪郭 + 左上ハイライト」で浮く。床より暗い色を体の広い面に使わない
