# 装備システムのオリジナリティ: PoE の骨格から脱却する

前提: docs/LOOT_DESIGN.md / docs/ideas/build-diversity.md / src/loot/types.ts（2026-09-23 時点の実装）。
維持する価値: 無限のバリエーション、BiS が存在しないこと（トレードオフ・逓減・相互排他・trigger × condition × effect 文法・シナジー網）、永続、ビルドの多様性、ドット絵アクションとの親和性。

凡例（書き換え規模）: **S** = 既存関数への追加で済む / **M** = 型の拡張 + 生成か集計の一部を書き直す / **L** = 型・生成・永続化・UI をまとめて作り直す

---

## 1. PoE 由来の要素と「本質的に必要な機能」

「残す」のは下の表の **機能** 列だけ。表現・用語・データ構造は全部差し替えてよい。

| # | PoE 由来の要素 | 現在の実装 | 本質的に必要な機能 | 差し替えの方向 |
| --- | --- | --- | --- | --- |
| 1 | prefix / suffix | `AffixKind`、rare は 3 + 3 まで | 1 アイテムの性質数に上限を設け、攻撃系・防御系が 1 つの装備に全部載らないようにする | 性質数の上限は「器の容量」で持つ。種類の偏り防止は **色の配合**（共鳴）で表す |
| 2 | tier T1〜T5 + minLevel | `AffixTier[]`、itemLevel で高 tier が解禁 | 深層ほど強い値が出る。強い値は珍しい | 深さで **期待値が連続的に伸び**、**分散（揺らぎ）も広がる**。段階を持たない |
| 3 | rarity normal / magic / rare / unique | 性質数の帯 + 色 + 出現重み | ドロップの瞬間の興奮と、床の上での識別 | 光柱の **色 = 支配色**、**高さ = 性質数**、**ちらつき = 揺らぎ**。格付けの名前を持たない |
| 4 | unique（固定セット） | `UNIQUES` 15 種 | 手作りの個性。ビルドの起点になる物 | 「名のある遺物」: 性質は固定、**育ち方の枝が固有** |
| 5 | implicit | ベースごとの固定補正 | ベース種の個性（大剣は重い、短剣は速い） | そのまま残す。加えて **ベースに色の傾き** を持たせる |
| 6 | itemLevel | depth + 0..2 | 生成の強さを決める 1 つの入力 | 「発見深度」として残す。期待値と揺らぎ幅の入力になる |
| 7 | Chaos / Exalt / Annul（Reforge / Augment / Annul） | 通貨でリロール・追加・削除 | ドロップの再利用。外れを捨てずに済む。自分で方向を選べる | **追加は来歴（使い込み）だけ**。通貨は「色を変える・揺らぎを鎮める・移す」に限る |
| 8 | Vaal（Corrupt、以降クラフト不可） | 1 回きりの賭け | 不可逆の賭けで上振れを狙う | **煽り**（揺らぎの再抽選、反転の危険あり）に置き換える |
| 9 | 通貨の段階（dust / shard / essence / relic） | レアリティで分解先が決まる | 分解に意味を持たせる | **色ごとの残響** にする（分解したアイテムの支配色） |
| 10 | keystone（パッシブツリー用語） | `ks_` アフィックス、排他 group | 遊び方そのものを変える大型改造 | **誓約（冥色の性質）** に改名。排他 group の仕組みはそのまま |
| 11 | 2 語の rare 名（"Storm Fang"） | `names.ts` | 個体を覚えやすくする | 名前は **来歴から刻まれる銘**。拾った時点では無名 |
| 12 | 変換アフィックス（conversion） | `stage: "convert"` | 別の軸へ盛りを移す網 | そのまま残す（PoE 固有ではない一般的な仕組み） |

判定: 1〜4, 7〜9, 11 が「PoE そのもの」に見える主因。5, 6, 12 は ARPG 一般の語彙なので、名前だけ整えれば残してよい。

## 2. 骨格を変える案（7 案）

### 案 A. 面（ファセット）: アイテムは多面体

- **世界観**: 深層の鉱脈から掘り出す「結晶器」。面ごとに違う性質が浮かぶ。欠けた面は空き面として残る
- **用語**: 面（facet）、稜（面と面の境）、欠け面、研磨
- **データ構造**
  ```ts
  interface Facet { trait: AffixRoll | null; neighbors: number[] }
  interface Gem { shape: "tetra" | "cube" | "octa" | "prism5"; facets: Facet[] }
  ```
- **生成**: 形を抽選（面数 4〜8）→ 各面に性質か空き面。**稜で隣り合う面の組み合わせ** に効果（隣接ボーナス）。例: burn の面と attack speed の面が隣接で「多段着火」
- **UI**: ツールチップ左に 16x16 の回転するドット多面体。ホバーした面が光り、隣接先に線が引かれる
- **BiS を潰す仕組み**: 同じ性質でも隣接相手で価値が変わる。面数が多い形は隣接が多いが 1 面の値が低い（形ごとの予算）
- **流用**: `AffixRoll` はそのまま面に載る。隣接ボーナスの計算と形の定義を足す。**M**
- **弱点**: 小さな画面で立体を読ませるのは辛い。隣接の組み合わせ表が爆発する

### 案 B. 銘と来歴: 使うほど育ち、分岐する

- **世界観**: 武具は持ち主の戦い方を覚える。十分に覚えた武具には銘が刻まれる
- **用語**: 来歴（chronicle）、芽（bud、育ちの分岐点）、余白（margin、これ以上育てられる数）、銘（engraving）
- **データ構造**
  ```ts
  interface Chronicle { kills: Record<string, number>; justDodges: number; hitsTaken: number; deepest: number; bosses: string[] }
  interface Bud { milestone: string; options: [AffixRoll, AffixRoll] }
  ```
- **生成**: 拾った時点では性質が少なく、**余白** を持つ。装備中の出来事が節目（「boar を 30 体」「JUST 20 回」「発見深度 +3 に到達」）に達すると芽が出る。芽は 2 択で、候補は **節目の種類 × アイテム seed** から文法生成。選ばなかった枝は二度と出ない
- **UI**: ツールチップ下部に年表（「深さ 4 で拾う → slime 30 体 → JUST 20 回で芽: 回避時に衝撃波 を選択」）。芽が出たら部屋クリア時に 2 択カード
- **BiS を潰す仕組み**: 同じ seed のアイテムでも、節目に達する順番と選択で必ず別物になる。育ち切るまで何ランもかかり、1 本の完成品に全員が収束しない
- **流用**: 芽の中身は既存アフィックスとトリガー文法をそのまま使える。ラン内カウンタ（種族別撃破・JUST 回数・被弾数）は新設。**M**
- **弱点**: 単独では「拾った瞬間の興奮」が弱くなる。拾う時点の多様性は他案で補う

### 案 C. 共鳴（色の配合）

- **世界観**: 性質はそれぞれ固有の響き（色）を持つ。身に着けた装備全体の響きが重なり、一つの和音になる
- **用語**: 色（hue）、配合、支配、二重、散光
- **データ構造**
  ```ts
  type Hue = "ember" | "tide" | "gale" | "spark" | "void";
  interface AffixRoll { /* 既存 */ hue: Hue }
  ```
- **生成**: 各性質は定義に既定の色を持つ（タグから決める）。約 1 割は異色で生まれる
- **UI**: 装備画面の上に 5 色の配合バー。発現中の共鳴名を 1 行で出す
- **BiS を潰す仕組み**: 共鳴は **配合比のパターン** で決まり、同時に 1 つしか発現しない（支配 / 二重 / 散光は排他）。アイテム単体の価値が、他の 5 スロットの色に依存する
- **流用**: `computeStats` の前段に配合の計算を足すだけ。**S**
- **弱点**: 単独では「セットボーナスの言い換え」に見えやすい。比率なので説明を丁寧にする必要がある

### 案 D. 器と魂

- **世界観**: 武具（器）は空の容れ物。深層の敵は魂を落とし、器に宿すと性質を帯びる。魂には性格があり、宿した器によって振る舞いが変わる
- **用語**: 器（vessel）、魂（soul）、性格（temper: 猛・慎・狂・静 …）、宿し、剥がし
- **データ構造**
  ```ts
  interface Soul { id: string; temper: Temper; traits: AffixRoll[]; affinity: Partial<Record<Slot, number>> }
  interface Vessel { baseKey: string; slot: Slot; implicit: AffixRoll | null; soulId: string | null }
  ```
- **生成**: 器はベース + implicit のみ（ほぼ白）。魂が性質の本体。**性格 × スロット** で係数が変わる（猛の魂は武器で ×1.3、防具で ×0.7）
- **UI**: 魂は小さなドットの炎として stash に並ぶ。ホバーで性格と一言（「もっと斬らせろ」）。台詞は性格 × 状況の文法で生成
- **BiS を潰す仕組み**: 魂の最適な器がスロットごとに違い、1 つの魂は 1 つの器にしか宿らない。魂の移し替えは器を壊す（器側の implicit を失う）
- **流用**: 既存 `Item` を器と魂に 2 分割する。永続化と UI は作り直し。**L**
- **弱点**: 管理対象が 2 倍になり、stash の操作が重い

### 案 E. 揺らぎ: tier の代わりに分散

- **世界観**: 深い層の物ほど不安定。とんでもなく強いことも、壊れていることもある
- **用語**: 期待値（nominal）、揺らぎ（flux）、反転（inversion、揺らぎが -100% を超えて性質が裏返る）
- **データ構造**
  ```ts
  interface AffixRoll { key: string; nominal: number; flux: number; value: number; value2?: number }
  ```
- **生成**: 期待値は発見深度の連続関数（既存 tier 表の中央値を深度で補間して作る）。揺らぎ幅 σ は深度で広がる。深度 13 あたりから反転があり得る
- **UI**: 値の横に 5x3 ドットの波形アイコン。振幅が揺らぎの大きさ。反転は波形が黒く、文字が紫
- **BiS を潰す仕組み**: 「上位の数値」が段階ではなく連続なので、比較の基準点（T1 か否か）が消える。深層ほど外れも多く、最上振れを狙うと反転の危険を背負う
- **流用**: 生成の `rollTierIndex` / `rollAffixAtTier` を差し替え、tier 表は期待値曲線として再利用。**M**
- **弱点**: 単独では「tier を連続値にしただけ」。反転と組み合わせて初めて個性になる

### 案 F. 表裏（呪と祝の二面性）

- **世界観**: すべての性質は裏の顔を持つ。条件がそろうと裏返る
- **用語**: 表（祝）、裏（呪）、返し条件
- **データ構造**
  ```ts
  interface TwoFacedTrait { front: AffixRoll; back: AffixRoll; flipWhen: TriggerCondition }
  ```
- **生成**: 表を抽選 → 裏は表と **反対のタグ** から抽選 → 返し条件は既存の `TriggerCondition` から抽選。裏が強いほど返し条件は起きにくい
- **UI**: ツールチップで表と裏を上下に並べ、今どちらが有効かを戦闘 HUD の装備アイコンで示す（裏返ると絵が反転）
- **BiS を潰す仕組み**: 常時有効な性質が存在しない。HP 50% 未満で裏返る装備は、戦い方ごとに評価が逆転する
- **流用**: 集計が「静的な `PlayerStats`」から「状態で変わる stats」になり、戦闘側の再計算が要る。**L**
- **弱点**: 60fps の中で性質が頻繁に切り替わると読めない。`computeStats` の純関数性が崩れやすい

### 案 G. 脈（装備間の配線）

- **世界観**: 6 つの装備は身体の上で輪になり、隣り合う物同士で力が流れる
- **用語**: 起こり（trigger 口）、果て（effect 口）、脈（隣接スロット間の接続）
- **データ構造**
  ```ts
  interface Port { side: "cause" | "effect"; trigger?: TriggerKind; effect?: TriggerEffectKind; magnitude: number }
  // スロットの輪: weapon - gun - amulet - armor - boots - ring - weapon
  ```
- **生成**: トリガー文法を **半分に割って別々の装備に載せる**。武器の「JUST 回避時に」と、隣の銃の「弾を 5 発撒く」がつながって初めて成立する
- **UI**: 装備画面の 6 スロットを輪に配置し、成立した脈を光る線で描く。未接続の口は点滅
- **BiS を潰す仕組み**: 口 1 つの価値はゼロで、隣の装備との組でしか決まらない。スロットの輪が固定なので、全組み合わせを同時に満たせない
- **流用**: `TriggeredEffect` はそのまま。組み立て場所がアイテム内から装備全体に移るだけ。**M**
- **弱点**: 装備の入れ替え 1 回で複数の脈が同時に切れ、試行が重い

## 3. 推奨: 「響き・揺らぎ・来歴」（C + E + B の合体）

**一言で**: 拾った時点では「色と揺らぎを持つ未完の器」。身に着けた全体の色の配合で共鳴が決まり、使い込むほど来歴から性質が芽吹いて、銘が刻まれて完成する。

**合体の理由**: 拾う瞬間の興奮は揺らぎ（E）、組み合わせの妙は共鳴（C）、愛着と唯一性は来歴（B）が担う。3 つとも既存の `AffixRoll` / `TriggeredEffect` / `computeStats` の上に載るので、全面書き直しにならない。

### 3-1. 用語集

| 用語 | 読み / 英名 | 意味 | 置き換える PoE 要素 |

| 遺物 | relic | 装備アイテム全般 | item |
| 性（さが） | trait | アイテムに宿る 1 つの性質 | affix |
| 色 | hue | 性が持つ響き。紅 / 蒼 / 翠 / 金 / 冥 の 5 色 | prefix / suffix |

| 揺らぎ | flux | 期待値からのずれ（-130%〜+150% × σ） | tier の抽選 |

| 余白 | margin | このアイテムがまだ育てられる数 | rarity の性質数上限 |
| 来歴 | chronicle | 装備中に起きた出来事の記録 | （新規） |
| 節目 | milestone | 来歴の閾値。到達で芽が出る | （新規） |

| 銘 | engraving | 余白を使い切ったアイテムに刻まれる名前 | rare 名 |

| 名のある遺物 | named relic | 性が固定で、芽の枝が固有の遺物 | unique |
| 残響 | echo | 分解で得る、色ごとの素材 | 通貨 |

### 3-2. 型案（TypeScript）

既存の `AffixRoll` を **拡張** し、`tier` と `kind` を段階的に廃止する。`key` の体系（固定アフィックス / `tr:` / `ks_`）はそのまま使う。

```ts
// src/loot/types.ts

export const HUES = ["ember", "tide", "gale", "spark", "void"] as const;
export type Hue = (typeof HUES)[number];

export const HUE_COLOR: Readonly<Record<Hue, string>> = {
  ember: "#e8553a",
  tide: "#3a8ee8",
  gale: "#49c46b",
  spark: "#f2c84b",
  void: "#9a5ae0",
};

export type TraitOrigin = "found" | "grown" | "vow";

/** 旧 AffixRoll。key / value / value2 の意味は同じ */
export interface Trait {
  key: string;
  hue: Hue;
  /** 発見深度で決まる期待値（表示単位） */
  nominal: number;
  /** 期待値からの相対的なずれ。value = nominal * (1 + flux) */
  flux: number;
  value: number;
  value2?: number;
  origin: TraitOrigin;
}

export interface Chronicle {
  /** 敵種 key → 撃破数（装備中のみ） */
  kills: Record<string, number>;
  bosses: string[];
  justDodges: number;
  hitsTaken: number;
  roomsCleared: number;
  /** 装備中に到達した最深 */
  deepest: number;
  runs: number;
}

export interface Bud {
  milestone: MilestoneKey;
  options: readonly [Trait, Trait];
}

export interface Relic {
  id: string;
  seed: number;
  baseKey: string;
  slot: Slot;
  /** 旧 itemLevel */
  foundDepth: number;
  foundAt: number;
  implicit: Trait | null;
  traits: Trait[];
  /** 残りの成長枠 */
  margin: number;
  chronicle: Chronicle;
  /** 到達済みの節目（二度と出ない） */
  milestones: MilestoneKey[];
  /** 未選択の芽（最大 1 つ） */
  pendingBud: Bud | null;
  /** 余白 0 で刻まれる。未刻印なら null */
  engraving: string | null;
  /** 名のある遺物の key */
  namedKey: string | null;
}

export type MilestoneKey = `${MilestoneKind}:${string}`;
export type MilestoneKind = "kills" | "boss" | "just" | "hurt" | "rooms" | "depth" | "runs";

export type ResonanceKind = "apex" | "dyad" | "prism" | "none";

export interface Resonance {
  kind: ResonanceKind;
  /** apex は 1 色、dyad は 2 色、prism と none は空 */
  hues: Hue[];
  /** 0..1。配合がどれだけ条件を超えているか */
  strength: number;
}

// PlayerStats に追加
//   resonance: Resonance;
```

```ts
// src/loot/resonance.ts（新規）

/** 支配の閾値: 1 色が全体の 55% 以上 */
export const APEX_RATIO = 0.55;
/** 二重の閾値: 上位 2 色がそれぞれ 30% 以上で、差が 15% 以内 */
export const DYAD_MIN_RATIO = 0.3;
export const DYAD_MAX_GAP = 0.15;
/** 散光の閾値: 5 色すべてが 12% 以上 */
export const PRISM_MIN_RATIO = 0.12;
/** 支配中、支配色以外の性の値に掛かる係数 */
export const OFF_HUE_DAMPING = 0.75;
/** 反転した性は色の重みが 2 倍（呪いは強く響く） */
export const INVERTED_HUE_WEIGHT = 2;

export function hueWeights(traits: readonly Trait[]): Record<Hue, number>;
export function resolveResonance(weights: Readonly<Record<Hue, number>>): Resonance;
```

### 3-3. 生成手順（純関数、`generateRelic(rng, opts)`）

1. **スロットとベース**: `rollSlot` / `rollBase` / `rollImplicit` をそのまま使う
2. **性の数**: 0〜5 を抽選する（深度で少しだけ多い側に寄る）。**余白 = clamp(5 - 性の数, 1, 4)**。性が少ない遺物ほど育てる余地が大きい
3. **性の抽選**: 既存のアフィックス定義・トリガー文法・変換から、`slots` に合う物を重み付きで引く（同じ key は 1 つまで）。ベースごとの **色の傾き**（大剣は紅寄り、ブーツは翠寄り）を重みに掛ける
4. **期待値**: `nominal = nominalAt(def, foundDepth)`。既存の tier 表を「minLevel → 中央値」の点列と見なし、深度で線形補間する。tier 表のデータはそのまま使える
5. **揺らぎ**: `σ = min(0.12 + 0.05 * depth, 1.0)`、`flux ~ 三角分布(-1.3σ, 0, +1.5σ)`。`value = round(nominal * (1 + flux))`。`flux < -1` なら反転（値が負になる）。深度 13 未満では反転しない
6. **色**: 定義の既定色（タグから決める表を 1 つ置く）。10% の確率で **異色**（他の 4 色のどれか）
7. **誓約**: 性の数が 3 以上のとき 8% で、性 1 つを誓約に置き換える（色は冥固定）
8. **名前**: 銘が無い間は「{支配色の形容} {ベース名}」（例: "Ember-tinged Longsword"）。銘は余白 0 で刻む
9. **来歴**: 空で作る。`milestones` は空、`pendingBud` は null

#### 来歴と芽の手順

- ラン中に **装備中の遺物すべて** のカウンタを進める（撃破は敵種別、JUST、被弾、部屋クリア、到達深度、ボス）
- 部屋クリア時に節目の判定をする。節目表の例:

| 節目 | 閾値 | 芽の候補の傾き |
| --- | --- | --- |
| `kills:<敵種>` | 30 体（ボス以外） | その敵への有効打（boar なら knockback と壁叩きつけ） |
| `just:20` | JUST 20 回 | `onJustDodge` のトリガー、JUST 系の性 |
| `hurt:40` | 被弾 40 回 | 蒼の性、`onHurt` のトリガー |
| `rooms:25` | 部屋クリア 25 | `onRoomClear` のトリガー、ゲージ系 |
| `depth:+3` | 発見深度 +3 に到達 | 期待値を到達深度で引き直した既存の性 1 つ |
| `boss:<ボス>` | 撃破 1 回 | そのボス固有の性（名のある遺物の枝に近い） |
| `runs:5` | 5 ラン装備 | 既存の性 1 つの揺らぎを +0.2 |

- 余白が 1 以上あり、`pendingBud` が空なら、`rng = seedFrom(relic.seed, milestoneKey)` で **2 つの候補** を生成して `pendingBud` に入れる。同じアイテム・同じ節目なら同じ候補になる（純関数）が、節目に達する順番はプレイで変わる
- プレイヤーが 1 つ選ぶと、その性を `origin: "grown"` で追加し、余白を 1 減らす。選ばなかった方は消える
- 余白が 0 になったら銘を刻む。銘は来歴の最大項目から作る（"Slime-Drowner"、"Twice-Crowned"、"Unbroken"）

#### 共鳴の計算（`computeStats` の前段）

1. 装備中の全性から `hueWeights` を作る。重みは `|value / nominal|`（強く振れた性ほど強く響く）。反転した性は 2 倍
2. 比率にして、**支配 → 二重 → 散光 → なし** の順で最初に成立した 1 つを採用する
3. 支配なら、支配色以外の性の value に `OFF_HUE_DAMPING` を掛けてから既存の段階適用に渡す
4. 共鳴効果は `stats.resonance` に入れ、メカニクスは戦闘側が読む（キーストーンと同じ作り）
5. その後は既存どおり、段階適用 → ソフトキャップ → 誓約（旧キーストーン）→ 整数化

二重の共鳴は 10 組ある。

| 組 | 名前 | 効果 |
| --- | --- | --- |
| 紅 + 蒼 | 蒸気 | 燃えている敵を冷やすと破裂する |
| 紅 + 翠 | 野火 | ダッシュの軌跡が燃える |
| 紅 + 金 | 閃火 | crit で burn の残り全額を即時に与える |
| 紅 + 冥 | 焦身 | 最大 HP の 5% を払うたびに次の近接 x2 |
| 蒼 + 翠 | 潮流 | 移動中は敵弾を 20% の確率で弾く |
| 蒼 + 金 | 霜雷 | chill 中の敵への shock は連鎖 +2 |
| 蒼 + 冥 | 澱 | 被ダメを溜め、ゲージ満タン時のバーストに上乗せ |
| 翠 + 金 | 疾雷 | ダッシュ残数だけ次の射撃が連鎖する |
| 翠 + 冥 | 影歩 | ダッシュ無敵が無くなり、代わりに残像が 1 回攻撃する |
| 金 + 冥 | 賭け | crit 倍率が 1.0〜4.0 で揺らぐ |

- 波形アイコンは揺らぎの大きさ。数値比較の代わりに「振れている」ことだけを伝える

**例 2: 深さ 15 の指輪（反転あり）**

**例 3: 銘が刻まれたブーツ（完成）**

グリーブ  ダッシュ距離 +15%

### 3-5. クラフトの置き換え

原則: **ランダムに性を足す操作を無くす**。性が増える経路は来歴（芽）だけにする。

| 新しい操作 | 素材 | 中身 | 置き換える旧操作 | ゴールが無い理由 |
| --- | --- | --- | --- | --- |
| 砕く | なし | 遺物を分解し、**支配色の残響** を性の数だけ得る | salvage | 色が偏った遺物からは偏った残響しか出ない |
| 染め | 目標色の残響 3 | 性 1 つの色だけを変える。値は変わらない | Reforge（Chaos） | 共鳴は同時に 1 つなので、染めても「全部入り」にならない |
| 鎮め | 同色の残響 2 | 性 1 つの揺らぎを半分にする（0 へ寄せる）。反転は解除される | Annul の一部 | 上振れも消えるので、鎮めるほど平凡になる |
| 煽り | 冥の残響 2 | 性 1 つの揺らぎを σ x1.2 で引き直す。反転の危険がある | Corrupt（Vaal） | 期待値は上がらず、分散だけ増える |
| 削ぎ | 同色の残響 1 | 性 1 つを消し、余白を 1 戻す（初期余白が上限） | Annul | 空けた余白は来歴でしか埋まらず、どの芽が出るかは戦い方次第 |
| 移し | 冥の残響 3 | 芽吹いた性 1 つを別の遺物へ移す。**元の遺物は消える**。受け手の余白を 1 使う | Fuse | 移すたびに遺物を 1 つ失い、受け手の成長枠も減る |

旧 Augment（Exalt 相当）は廃止する。

### 3-6. PoE と何が違うか（5 行）

1. 格付け（normal / magic / rare / unique）と段階（T1〜T5）が無い。強さは深度の連続値と、そこからの揺らぎで表す
2. 深層の遺物は「強い」のではなく「荒い」。最上振れを狙うと反転の危険を背負う
3. 性は prefix / suffix ではなく **色** を持ち、装備全体の配合で同時に 1 つだけの共鳴が発現する
4. 通貨で性を足す操作は無い。性が増えるのは、装備して戦った来歴からの芽吹きだけ
5. 名前は拾った時点で決まらず、使い込んだ末に来歴から刻まれる。同じ seed でも持ち主ごとに別の遺物になる

### 3-8. BiS が成立しない理由（既存の仕組みとの関係）

- **共鳴の排他**: 支配・二重・散光は同時に成立しない。どの共鳴を選ぶかで最適な遺物が入れ替わる
- **支配の減衰**: 1 色に寄せると他の色の性が 75% になる。単色の極みと混色の器用さが常に比較の土俵に乗る
- **揺らぎと反転**: 最上振れは深層にしか無く、同じ深層で反転も出る。「最強の数値」を狙う行為に代償がある
- **来歴の分岐**: 芽は 2 択で、捨てた枝は戻らない。節目に達する順番も戦い方で変わる
- **既存の仕組みはすべて残す**: タグ逓減・ソフトキャップ・誓約（旧キーストーン）の排他 group・トリガー文法・変換は、性の中身としてそのまま動く
