## 1. 現状と課題（診断）

- **決定性という資産が、版の速さで毎日死んでいる**。`src/core/replay.ts` の `REPLAY_VERSION` は 35。git の履歴では 35 回の版上げのほとんどが直近 10 日で、9/30 だけで 15 回。一方、タグ（`scripts/bump.mjs`）は `v0.0.15` まで。版の大半にタグが無いので、記録を「その版のコード」で再生し直す手段が無い。社会性・計測・不具合報告の案はどれもこの上に立つので、**最初に直すのは案ではなく版の作法**
- **今日の挑戦が「同じ条件の勝負」になっていない**。`src/system/floor.ts` の `buildFloor` は、階の型・面積・間取りを 1 本の `state.rng` から引く（`chooseFloorKind` / `rollAreaMul` / `chooseLayout`）。戦闘やドロップも同じ流れを消費するので、1 体倒す順が違えば 2 階から地図が変わる
- **乱数の状態が写せない**。`src/core/rng.ts` の `createRng` は mulberry32 の状態をクロージャの `a` に隠している。局面の写し・中断・感想戦の土台が無い
- **パッドの照準が壊れている**。`src/core/input.ts` の `snapshot` は、ボタン 1 つでも押せば `pad.active`（`src/core/gamepad.ts` 280 行）で照準元をパッドへ切り替え、右スティックが中立なら `aimScreen` は null。ジャイロ → マウスで狙う Deck の人は、押すたびに照準を失う。自動照準を禁じたゲームで、パッドの照準の唯一の答えを自分で壊している
- **英語が無く、表示文字列の表も無い**。テスト以外の 207 ファイルに、日本語を含む文字列の直書きが約 5,000（粗い数え）。並列の実装が毎日増やしている
- **測る相手が bot だけ**。`src/qa` の計測（`combatMetrics`・`bossMetrics`・`jinMetrics`）は人の記録に掛からない。リプレイは `src/ui/replayStore.ts` の `REPLAY_LIMIT = 10` で消え、再生は 1 / 2 / 4 倍だけ（`src/ui/title.ts` の `REPLAY_SPEEDS`）。スローもこま送りもシークも無い
- **原則 8 違反の残り**: 「スコア」が HUD（`src/render/renderer.ts` 3016 行）・死亡画面（同 3301 行）・探索履歴（`src/render/titleUi.ts` 462 行）・リプレイの結果欄（`ReplayResult.score`）に残る
- **Steam の外回りが空**: Steamworks なし、クラッシュの記録なし（`electron/` に該当の処理なし）、Deck の 16:10 での見え方は未確認。一方で Electron の包み（`app://`・fuses・`%APPDATA%\BOKUEN`）は揃っている
- **社会性の案の多くが人口を前提にしている**。発売直後の同時接続は数十〜数百人。N = 1（自分だけ）と N = 配信者 + 視聴者で成り立つ物を先に、人口が要る物は発売後に回す（批評 L12 の論点 1 をこの領域の基準にする）

### 2-1. 混成操作（L11-03 + L09-07 残照）

- **何をするか**: 照準元をパッドへ切り替えるのは「右スティックを倒した時」だけにする。ボタン・左スティックでは切り替えず、最後のマウス位置を照準に残す。段 2 で、右スティックを離しても最後の向きを 0.6 秒保ち（移動を 90 度以上切り返したら早めに戻す）、照準の線を出す。Deck の 1280×800 での見え方を `map:shot` の場面 1 つで確かめる
- **なぜ面白いか・判断**: 銃の家系・書・投具は引き撃ちが核で、「下がりながら狙う」がパッドで成立して初めて、パッドの人にも位置取りの判断が生まれる。今はスティックを離した瞬間に向きが移動方向へ戻るので、引き撃ちが出来ない
- **なぜこのゲームで**: 自動照準の禁止（原則）があるので、パッドの照準は吸着でなくジャイロか保持で解くしかない。左手で完結するキー配置は、そのままパッドの左半分に写る。照準は `aimScreen` に入るので、保持してもリプレイは同じになる
- **着想元と変えた点**: Steam Input・Deck の Verified、Enter the Gungeon の照準の保持。保持は「画面の点」でなく「スティックの向き」で持つ（カメラが動いても狙いの向きがずれない）。敵へは寄せない
- **最初の一歩**: `snapshot` の切り替え条件を `pad.aimDir !== null` に絞り、「ボタン連打・左スティック移動の間もマウスの照準が保たれる」を `src/core/input.test.ts` で固定する
- **リスク**: 保持が長いと意図しない向きに撃つ。0.6 秒は仮の値で、パッドで遊んで決める。Deck は 2.67 倍の非整数倍。整数倍（960×540 を中央に置く）かにじみを許すかは、撮った絵を見て決める
- **規模**: S（段 1）+ M（段 2 の保持と線）
- **審査の要点**: 4 人とも 4〜5（producer 5「今は切り替えが壊している」）。残照は 3.25 だが、同じ `snapshot` を触る案なので同じレーンで深める方が安い

### 2-3. 実戦譜（L12-01 + L09-14 初動計 + L10-04 の写し数え + G1-05 の人の側）

- **何をするか**: `src/qa` の計測を `ReplayData` の早送り再生にも流す口（`qa:replays -- <dir>`）を作り、probe の表に「人」の列を bot の隣に並べる。列は完遂率・カウンター・見切り・受け流し・陣の決着の形・行為で進んだ段階・死因、それに標本の数。Electron 版の開発用の設定で、全部の記録を `replays/v<REPLAY_VERSION>/` へ書き出す。段 2 で、同じ口に初動計（空のセーブから最初の 1 撃・陣・死・開帳までの秒）・写し数え（鍵・市・賭けの使われ方）・鮮度（その探索で拾った物が働いている割合）の列を足す

- **リスク**: 1〜2 本の標本で判断しない（表に標本の数を必ず出す）。人の記録は開発者 1 人の手癖に偏る
- **規模**: S（段 1）+ S〜M（段 2 の列）

### 2-4. 定跡（G3-05。L12-05 詮議と対）

### 2-6. 定盤（L08-09 + L12-02 の乱数の段）

- **何をするか**: 段 0 で `Rng` に `getState()` / `setState(n)` を足す（乱数列は変わらないので版は据え置き）。段 1 で「盤」（階の型・面積・間取り・陣の配置・出口）を、`seed` と深度から作る別の流れに抜く。段 2 で「運」（ドロップ・祝福の 3 択・市）を、seed・深度・その階で引いた回数から作る流れに分ける。戦闘の揺らぎは今の 1 本のまま

- **なぜこのゲームで**: 用途ごとに乱数を派生させる作法はすでにある（`src/loot/crafting.ts` の `createRng(hashSeed(...))`、`src/loot/provenance.ts`）。それを階の生成に広げるだけ。先達・果たし状・一番勝負・御前試合・仇の再現など 6 案以上が「同じ盤」を前提にしている
- **着想元と変えた点**: Spelunky 2 のデイリー（盤は固定、中身は腕）、ボードゲームの盤と手番の分離
- **最初の一歩**: `buildFloor` の先頭 3 行（型・面積・間取り）だけを `createRng(hashSeed(\`${state.seed}|floor|${state.depth}\`))` に差し替え、`src/core/replay.test.ts` に「同じ seed なら、1 階の撃破の順を変えても 2 階の地図が同じ」のテストを足す。陣（`src/system/jinSpawn.ts`）・出口はその次
- **リスク**: `state.rng` を使うファイルは 76。一度に振り分けない。`replay.test.ts` と probe の基準値が全部動くので、レビューは opus。版上げは 2-5 の作法に従い、他の sim の段とまとめる
- **規模**: 段 0 は S、全体は L
- **審査の要点**: 平均 4.25、veteran・system が 5「今日の挑戦が 2 階から別の盤になるのは不具合」。newcomer 3 は「初見の 1 時間に効かない」で正しいので、急ぐのは段 0 と盤の段だけでよい

### 2-7. 目安箱（L11-04）

- **何をするか**: ポーズ画面の 1 キーで、ランの開始からのリプレイ・`APP_VERSION`・`REPLAY_VERSION`・`BALANCE_HASH`・**コミットのハッシュ**・OS・設定・貼り付けたひとことを 1 つの JSON にまとめる。落ちた時は main プロセスが最後の棋譜を `.crash-` の名で書き残す。受け取り側は、記録のコミットを worktree に出して止めたいフレームまで再生するスクリプト 1 本で再現する。発売前に同じ棋譜を Windows と Linux（Deck）で回し、結果のハッシュが一致するかを 1 回確かめる

- **なぜこのゲームで**: 決定性があるので「再現できない不具合」がほぼ消える。記録の中身（`loadout`・`hitstopScale`・`balance`）はすでに揃っていて、足すのは包みと受け取りの道具だけ。環境をまたぐ決定性（三角関数の差など）を確かめる場にもなり、果たし状・先達の前提を守る

- **リスク**: パス・名前など個人の情報を含めない。倉庫全体は出さない（記録の装備の写しだけ）。版が違うまま黙って再生してずれるのが最悪なので、照合を必ず先に通す
- **規模**: S
- **審査の要点**: 平均 3.75。全員が「EA の運営の要」で一致し、newcomer の「面白さには効かない」も事実。安いので早めに入れる

### 2-8. 一章体験（L11-07。試金の主を含む）

- **何をするか**: 体験版を「章 1 の 5 階 + 試金の主に作り直したスライム王 + 門前町の一部」で 1 時間の弧にする。範囲はジョブ 3・型 5〜6・祝福 4 系譜・依頼 6。倒すと章 2 の休符を覗かせて終わり、製品版へは図鑑と、名を付けた遺物の名と逸話の記録だけを引き継ぐ
- **なぜ面白いか・判断**: 教える（初陣）→ 試す（試金の主）→ 欲しがる（章 2 の顔）を戦闘の言葉で閉じる。試金の主は段階ごとに 1 つの読みを試す。黄の間に潜って殴る・赤を受け流す・陣の大将を割る
- **なぜこのゲームで**: 章の弧（休符 → 登り → 章ボス）がすでにあり、章 1 が自然に 1 本の弧になる。死亡の 7 割が章 1 で、初見が見るのも章 1〜2（newcomer）。体験版の範囲を決めること自体が「章 1 から磨く」の優先順位を全レーンに通す
- **着想元と変えた点**: Next Fest の上位作の体験版、Hollow Knight の偽りの騎士。試すのを動きでなく「読み」にした
- **最初の一歩**: 体験版で見せない層（誓約・残響・改鋳・深み）と出す型の表を 1 枚書く。スライム王の作り直しは 2-4 定跡の門を通す最初のボスにする
- **リスク**: 元案の試金の主の描写は今のコードとずれている。今のスライム王（`src/system/bossKingSlime.ts`）は、第 2 段階で分裂体を出し、王が**分裂体を**呑んで回復する（怯ませると吐き出す）。第 3 段階の膨張は分裂体が 0 体になると来る。案の「プレイヤーの吸い込みを受け流す」「膨張で大将付きの陣」は、段階の順と移る条件を作り直す話になる。体験版を「機能を削った物」に見せない。遺物の引き継ぎは約束しない（版の速さで破れる）。Steam Cloud は appid ごとに別
- **規模**: L（初陣・黄赤一致など戦闘の核の段の後）
- **審査の要点**: 平均 4.5 でこの領域の最高点。newcomer・producer が 5「Next Fest の勝負所」。ただし約束「黄は打て、赤は返せ」が手触りとして本当になってからでないと、体験版の 10 分で「言っていることと違う」になる（批評 L11）。範囲の表だけ先に書き、作るのは後

## 3. 良案（入れる時期を待つ物）

- **撮影台**（L11-13 + L14-05 試演台）: リプレイを HUD なし・自由カメラ・スロー・こま送りで 1920×1080 の連番に書き出す（`RENDER_SCALE` 4 で滲みなし）。試演台の「案の有無を左右に並べて撮る」を同じ道具のモードにする。トレーラーを撮る段（戦闘の核の後）で S から

- **二重記録の足跡**（L12-09 の段 2）: 入力列の隣に版に依らない足跡（位置・向き・階・出口・死因）を書き、先達・死絵・辞世の低精細版を版を越えて生かす。形式は `v1` を切って滅多に変えない。社会性を作る段の最初に
- **果たし状 + 先達**（L05-16 + L08-10 + L12-15）: 共有の文字列を 1 本にする。中身は seed・支度・出口と祝福の列・装備の写し・版。受けた側は同じ盤（2-6 定盤の後）に先達の朱の印と墓標を見て降りる。まず N = 1 の「自分の譜をもう一度」から。並べ比べは単一指標でなく階ごとの到達と被弾

- **変化図**（L07-05）: 記録の中の 1 つの読みを「しなかった」に差し替えて 5 秒先を比べ、読みの値を型ごとに測る開発の道具。実戦譜（2-3）の標本が貯まってから
- **三景**（L11-13 の段 2。原案の名「見得」は L01-04 見得〈ヒットストップの配り直し〉と同名なので改名した）: 終わりの画面に「読みが成功した 3 秒」を最大 3 つ並べて書き出す。`src/system/moments.ts` の判定から拾う。結末の器（道中記・絵巻起こし L11-06）を 1 本に決めてから、その中へ

## 6. ユーザーに決めてほしいこと

1. **版の作法**: `REPLAY_VERSION` を「版を切る時だけ」上げ、sim に触る変更を段ごとにまとめてよいか。並列の速度は少し落ちるが、記録・計測・不具合報告がすべてこれに乗る
2. **中断セーブ**: 「続きから」は作らない方針（`docs/ideas/title-ideas.md` 2 章）を、Deck と短い遊びのために見直すか。見直すなら、降階の確認でだけ挟む栞（L11-16）か、休符の階（6・11・16）だけの中断か
3. **単一の並び**: Steam のリーダーボードを一切持たないか、例外を 1 つ（手合 L11-09 の時間）だけ認めるか。認めるなら範囲を `docs/DESIGN_PRINCIPLES.md` に先に書く
4. **体験版**: Next Fest に出すか。出すなら範囲を章 1 に決めてよいか。製品版へ引き継ぐのは図鑑と遺物の名と逸話の記録だけでよいか
5. **英語**: EA を日本語 + 英語で出すか。固有名として残す 10〜15 語（Bokuen・Jin など）の選定。簡体字は 1.0 でよいか
6. **ストアの絵**: カプセル・キーアートを外注するか。コード内ピクセルマップの原則をストアの絵にも及ぼすか
7. **Deck の画面**: 480×270 を整数倍（960×540 を中央に置き、縁が空く）で出すか、1280×720 に非整数で広げるか（撮った絵を見てから）
