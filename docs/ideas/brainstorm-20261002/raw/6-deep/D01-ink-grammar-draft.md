## 1. 目的と、成功したかの判断

### 1-1. 目的

1. **画面と音が核の 1 文に逆らわない**。「黄は打て、赤は返せ」と矛盾する絵と音を 0 にする。今は体の点滅と範囲の予告が黄の間も赤い（3 章の衝突 1・2）
2. **どんな条件でも読める**。色が見えなくても、720p の配信・Steam Deck・ストアの縮小でも、暗い床でも、200 体の乱戦でも、黄と赤を取り違えない。色・形・動き・音の 4 本の通り道のどれか 1 本が欠けても読める
3. **看板の絵にする**。「下絵は斬れ、墨は返せ」をトレーラーの冒頭 5 秒で撮れる絵の言葉にする。ただし外へ名乗るのは筆陣の門（G6-01）を通ってから
4. **衝突させない仕組み**。AI の並列で絵と音を足し続けても、黄・赤・墨・朱・柝の意味が 1 つずつのまま保たれる表と検査を置く

遊びの判断は増やさない。黄の間に踏み込むか退くかという今ある判断を、画面が正しく起こすようにするのが目的。唯一の追加の情報は「下絵の削れ」（あと何撃で崩れるか）で、これは「1 撃で消せないなら退く」という判断の材料になる。

## 2. 仕様

### 2-1. プレイヤーから見た動き（1 回の攻撃）

1. 狼が予備動作に入る。頭の上に黄の小さな輪（○）が出て、体が攻撃の逆へわずかにのけぞり、縦に縮む（溜め）。足元から届く先まで、**全長の黄の掠れた線（下絵）** が即座に引かれる。線は途切れ途切れで、先端は必ず見える
2. 黄の間に斬る。当てるたびに下絵の欠けが増える。怯みで崩した瞬間、下絵が横へ擦れて散り（0.15 秒）、紙を擦る短い音が鳴る
3. 崩せないまま赤（コミット）に入ると、体が攻撃の向きへ 1 度伸び（張り）、頭の印が赤の塗りの点（●）に変わり、線が **暗い帯に赤い芯の太い一画（墨入れ）** になって、先端に止めの点が付く。以後、体は赤く点滅する
4. その攻撃が自分に掛かるなら、その敵の方角から拍子木の乾いた 1 打（柝頭）が鳴る。射手が画面外にいれば、その方向の画面の縁に墨の払いが 0.3 秒出る（殺気）
5. 受け流すと、板を打つ強い 1 打（附打）が鳴り、自分と相手だけが 1 コマ墨の影絵になる
6. 当たってしまったら、当てた敵から自分へ墨の一筆（被弾筋）が引かれ、0.8 秒で乾いて消える

### 2-2. 規則

| # | 規則 | 理由 |
| --- | --- | --- |
| R1 | **境は 1 つ**。下絵 = `phase === "windup"` かつ `attackCommitted(e)` が偽。墨入れ = `attackCommitted(e)` が真（コミット窓の予備動作と攻撃中）と、地面の物（着地・爆弾）。連撃の続き（`chainWindup`）は最初から墨入れ | 判定の正本は `system/poise.ts` の `attackCommitted` 1 か所。描画は別の境（例: 光線の `thinRatio`）を持たない |
| R2 | **4 本の通り道**。色（黄 / 赤）・形（途切れた細線 / 暗い帯 + 赤い芯 + 止め）・動き（溜め / 張り → 点滅）・音（無音 / 柝頭）。位置（殺気）と事後（被弾筋）は補助 | 1 本が欠けても読める。色覚と配信の圧縮は色を、乱戦は音を、画面外は位置を落とす |
| R3 | **下絵は最初のフレームから全長** | 伸びていく線は情報を遅らせる。深層の黄は 0.06 秒しかない（2-7） |
| R4 | **削れ**: 下絵の欠けの割合 = 基準 + 係数 × 怯み値の割合（`poiseRatio`）。怯み値が溜まらない間（耐性 0・障壁・怯み中）は削れない | 「あと何撃で崩れるか」を数字なしで読ませる。猪（強靭 0.25）は削れず、呼び鈴小鬼（1.5）はすぐ欠ける |
| R5 | **擦れ**: 下絵の間に怯みで予備動作が取り消されたら、線を散らして消す（0.15 秒）+ 紙擦れの音 | 「崩した」を一番気持ちよい瞬間にする。ヒットストップの間は `state.time` が止まるので、散るのは停止が明けてから |
| R6 | **墨入れ**: 暗い帯（縁）+ 赤い芯 + 先端の止め。範囲は縁の帯と薄い面で描き、床を塗りつぶさない。帯は判定の内側に描き、判定より外へ太らせない | 地形（油・水・草）を読むゲームなので床を隠さない。判定より太い絵は嘘になる |
| R7 | **地面の物は出た時から墨**。着地の影・爆弾・敵の死に際の爆発の輪は墨入れの輪で描く。中の色（属性・爆弾の種類）は芯に残し、縁を墨入れにする | 出た時点で必ず来る。敵弾の「芯は属性、縁は脅威」（L14-04）と同じ規則 |
| R8 | **頭上の印**: 黄 = 輪（○）、赤 = 塗りの止め（●）。どちらも暗い縁付き。文字の「!」はやめる | 3x3 の形の差は灰色でも縮小でも残る。字を重ねない（Sekiro の「危」は採らない） |
| R9 | **体**: 黄の間は色を重ねず「溜め」（攻撃の逆へのけぞり + 縦に縮む）。赤に入った瞬間に「張り」（攻撃の向きへ伸びる）を 0.05 秒、以後は今の赤の点滅。今の揺れ（`WINDUP_JITTER`）は溜めに置き換えて消す | 揺れは「危ない」を言うが向きを言わない。のけぞりは向きと時機を言う。黄の重ねは燃焼（#ff8030）・怯みの星（#f8d848）と紛れる |
| R10 | **「自分に掛かるか」は 1 つの純関数**（`system/threat.ts` の `threatensPlayer`）。柝頭・殺気・暗闇の上描き・後の走馬灯の帯が同じ関数を読む | 判定がばらけると、音は鳴ったのに縁は出ない、が起きる |
| R11 | **柝頭**: 敵の攻撃が赤に入った瞬間（立ち上がり）、`threatensPlayer` が真の物だけ、その時に最も早く当たる 1 体だけ、0.25 秒に 1 打まで、敵の画面上の横位置で左右に振って鳴らす | 鳴らない赤は無視してよい、が耳で分かる。鳴り続ける合図は合図にならない |
| R12 | **殺気**: 柝頭の対象のうち、敵が画面の外にいる物だけ、その方向の画面の縁に墨の払いを 0.3 秒。同時に 3 本まで（古い物から消す） | 画面内の敵は線そのものが見える。自分の周りに印を足すと、一番大事な所（自分）が汚れる |
| R13 | **被弾筋**: 被弾した瞬間、出どころ（敵、弾なら撃ち手。居なければ弾の位置）から自分へ、太い所から細る墨の一筆。赤い芯は持たない。0.8 秒（生命 3 割以下は 1.2 秒・太く）で乾いて消える。同じ出どころの筋は 1 本にまとめる。予告より下の層 | 「何に当たったか」をその場で見せる。赤い芯が無いので「これから来る物」と取り違えない |
| R14 | **附打**: 読みの成功だけに鳴らす。受け流し = 強い 1 打、見切り = 軽い 1 打、処刑・ボスのダウン・大将討ち = 3 打と間。カウンター（今の仕様では狙わずに出る）には鳴らさない。同じ附打は 0.4 秒以内に重ねない | 一番少ない読みの瞬間だけが一番強い演出を受ける |
| R15 | **層**: 予告は敵の体ごとではなく、全部の敵・自分・弾・粒の後に 1 回の描き込みでまとめて描く（浮き文字より下）。墨入れは下絵の上、墨入れ同士は早く当たる物が上。線は自分の体の上を通る所だけ切る | 今は `drawEnemy` の中で描くので、後に描かれる敵の体に予告が隠れる（3 章の衝突 7）。自分（目付の 1 段目）は線で汚さない |
| R16 | **暗闇の階**: 光の外にいる敵の墨入れのうち `threatensPlayer` が真の物は、暗闇の幕の上に描き直す。下絵は描き直さない | 暗闇の怖さ（早くは読めない）を残しつつ、「避けられない攻撃を作らない」を守る。赤は予備動作の 6 割の長さがあり返せる |
| R17 | **符号表**: 世界の層（地図・敵・弾・地面の物）の色・形・動き・音は 2-3 の表の 1 つの意味しか持たない。HUD の層（上部のバー・札・メニュー）は例外の一覧で別に扱う | 衝突は描いてから直すと高い（`lockedDoor.ts` が朱と外周の赤を個別に直した前例） |
| R18 | **決定性**: 描画は state を読むだけ。欠けの並びは `renderMath.ts` の座標ハッシュ（敵の id とセルの番号）で決め、`state.rng` も `Math.random` も使わない。被弾筋の記録だけは system が state に書くが、結果に効かない | 不変条件 1・2・3。`REPLAY_VERSION` を動かさない |

### 2-7. 暗い床・色覚・縮小での読みやすさ

**数の前提**（コードから）: 論理 480x270 を `RENDER_SCALE` 4 の 1920x1080 に描く。論理 1px = 裏の 4px。1280 幅（720p の配信・Deck の全幅）では 2.67px、ストアの縮小 460x215 では約 0.96px。黄の時間は `commitRatio` 0.6 なので予備動作の頭の 4 割。予備動作の中央値は 0.7 秒（黄 0.28 秒）、最短は蝙蝠などの 0.25 秒（深度 1 で黄 0.10 秒 = 6 フレーム）、深層の下限 `windupFloor` 0.6 倍で黄 0.06 秒（約 4 フレーム）。

**暗い床**
- 床の大半は暗い。黄（相対輝度 約 0.65）は暗い床で明るく立つ。赤（約 0.25）は暗い床で沈みやすいので、芯の幅 2 と頭の止めの光で持つ
- 明るい床（氷河・雪・砂など。どの章様式が明るいかは未確認）では黄が沈むので、下絵にも細い暗い縁（両側 0.5）を回す。墨入れの暗い帯は明るい床でも暗い床でも芯との明るさの差を作る（地図の凡例の「縁取り」と同じ考え）
- 暗闇の階（`isDark`、光の半径 90px）は R16。今は光の外の線・輪・扇が幕に覆われ、`laserEye` の溜めだけが描き直されている（`darkness.ts`）。突進の線は最長 200px なので、90px の外から来る突進は今は赤が見えない
- 深みの色相の回転・反転層の紫・血の月の重ね色は、`SIGN_CHECK` の検査の対象に入れる（L14-04 (c)）

**色覚**
- 黄と赤は明るさが大きく違うので、1 型（赤が暗く見える）・2 型でも明るさで分かれる見込み。変換行列（Brettel / Viénot）を掛けた数は未確認で、`SIGN_CHECK.readyCommitLumaMin` の検査で確かめる
- 本当の手当ては形（途切れ / 帯 + 芯 + 止め、○ / ●）と動き（溜め / 張り）と音（柝頭）。色に頼っていた人の読みは変わらない
- 配色の切り替え（標準 / 青と橙 / 白と黒。L14-04）は、形と音が入った後に当事者に見てもらってから足す（段 4）

**縮小（配信・Deck・ストア）**
- **色は幅 2 論理 px 以上の物でしか運ばない**。4:2:0 は色を 2x2 で平均するので、720p で 2.67px の細線の色はにじむ。黄の下絵（1.5）は色より明るさで読み、墨入れの芯（2）と頭の印（3）で色を運ぶ
- 欠けのセルは 3px（720p で 8px）。それより細かい掠れ（0.25px のかすれの質感）は配信と Deck で消えるので、質感は描かない。「途切れる」だけを形にする
- 頭上の印は暗い縁込みで 5x5（720p で 13px）。ストアの縮小では 5px 前後になり、○ と ● の区別はぎりぎり（未確認）。ストアの画はそもそも 1 体に寄った構図で撮る
- Deck を整数倍（960x540）にするか非整数かは 09-platform の問い。どちらでも上の幅は変えない

### 2-8. 描画の負荷

- 今の重さ: headless のソフトウェア描画で迷宮 1 フレーム 10〜15ms、うち光の層 約 3ms（`docs/HANDOFF.md`）。GPU の実機は未計測。予告の作り直しに使ってよいのは **0.5ms**
- 同時の予告の数の上限は今の規則が持っている: 新しい予備動作は 0.3 秒の間に近くで 3 つまで（`ENEMY_TEMPO.telegraphCap` / `telegraphWindow`、260px 以内）。画面の中で同時に描かれる予告は多くて 10 前後（推定。probe で数える）
- 1 本の線は「暗い縁の 1 回 + 芯の 1 回」の stroke 2 回。下絵の欠けは `setLineDash` の配列 1 つで描き、配列は（敵の id・セル数・欠けの割合を 0.1 刻みに丸めた値）で使い回す。範囲は円弧・扇の path 2〜3 回
- 使わない物: `shadowBlur`、線ごとの `lighter` の合成、フレームごとの canvas の生成、`getImageData`。光は止めの点だけ、既存の事前生成の光（`drawGlow`）を借りる
- 初回の固まりを作らない: 新しい色の染め（`tinted`）や事前生成が要る物は、読み込みの直後に作る（2026-10-01 の一瞬の固まりの教訓。`hitch:probe` で確かめる）
- 運筆予告（L14-01）の「24 方向の事前描画」は採らない（線の長さが 24〜200 で一定しない。6 章）。掠れの質感が欲しくなったら、帯の 1 枚絵（長さ 64・高さ 4 の帯を裏の密度で 1 回作り、回して並べる）を段 4 で試す

### 3-2. 衝突と解き方（コードで確かめた物）

1. **体の点滅が黄の間も赤**（`renderer.ts` 1537 行。`e.phase === "windup"` だけを見て `COLOR_TELEGRAPH` を `WINDUP_RED_ALPHA` 0.55 で重ねる）→ R9
2. **範囲の予告が常に赤**。黄 / 赤を分けているのは線（`drawStrikeLine`）・折れ線・頭上の「!」だけで、輪（`drawRingTelegraph`）・十字・扇（`drawWave3Telegraph`）・着地（`drawLanding`）は `COLOR_TELEGRAPH` 固定。ゴーレム・霜の砕き手・鎖の番人・呼び鈴小鬼・風の精・蜥蜴は、黄の間も画面が「返せ」と言っている → 段 0 で `telegraphColor` に揃える（着地は R7 で墨のまま）
3. **光線の境がずれている**。光線の溜めは `thinRatio` 0.6（溜めの 6 割の時点）で太くなるが、コミットは残りが 6 割を切った時（溜めの 4 割の時点）。太くなるのは赤に入ってから溜めの 2 割後で、色は最初から赤（#ff3030）→ 段 0 で色と太さを `attackCommitted` に従わせる
4. **黄の帯の衝突**: 怯みの星「*」とゲージ（#f8d848）は敵の頭上（予告の印と同じ場所）に出る。号令の気（#ffd040）は敵の体の周り。銭（#ffd040）・墓守の鐘や旗の敵の色（#f8d848）もある → 頭上と体の周りは胡粉か別の色相へ。銭は形で分ける例外
5. **赤の帯の衝突**: 血の粒（`COLOR_BLOOD` #ff4040）が敵の近くに散る。カウンターの文字の色 #ff9040 も近い → 血は臙脂へ。カウンターの文字は出端（L01-02）の段で文字ごと見直す
6. **音の衝突**: 受け流しの成功が `counter` の音を積む（`parry.ts`）。`enemyWindup` が全部の敵の予備動作と、鐘・旗・刻限の合図の 4 つの意味を持つ。`pushSfx` は同じフレームの同じ名前しか間引かない（`core/state.ts`）ので、乱戦では予備動作の唸りが重なり続ける → 鳴物帳（2-3）
7. **描く順**: 予告は `drawEnemy` の中で敵ごとに描かれるので、後に描かれた敵の体が前の敵の線を隠す。弾・粒・煙は予告の上に描かれる → R15
8. **暗闇の幕**: 光の外の予告は幕に覆われ、描き直しは `laserEye` の溜めだけ → R16
9. **破線**: 自分の遅延の刻印符と投げの着地が規則的な破線の円（`DELAY_DASH` [3, 3]）→ 下絵は不規則な欠けにし、周期を持たないことを検査（`SIGN_CHECK.sketchMaxRepeat`）。元案の「黄は破線」は採らない
10. **淡墨の多重の意味（案の側）**: 陣図（G6-02）の「淡墨の画」は下絵と同じ意味（大将を怯ませれば止まる）なので同じ筆致を使ってよい。残写（G3-04）の「淡墨の残像」は必ず来るので淡墨にしない。目付（L09-09）の「眠った陣は淡墨」は彩度を落とす表現へ。弔い（L02-12）の残墨・溜墨（G3-10）・墨痕（L07）は床の面で描く
11. **朱の多重の意味（案の側）**: 運筆予告の「朱の止め」→ 赤の止め。墨法の「朱は敵の確定だけ」は採らず、朱は自分の側と装飾に残して明るさで赤と分ける
12. **柝頭の判定の置き場**: 01-combat R5 と L09 の改訂は「system で判定して `pushSfx`」としている。しかし `pushSfx` は名前しか運ばず左右に振れない。L14 の改訂は「`state.sfx` に位置を添える」を 314 か所の変更として捨て、描画側の差から鳴らす経路を正にした。main が state を読んで立ち上がりで鳴らす前例（`audio/cues.ts` の `RisingEdge`、依頼の達成音）もある → main 側の `CommitEdges` で鳴らす。sim は触らない（7 章の問い 4 で確かめる）
13. **被弾の記録の置き場**: `HurtRecord` は保存される履歴にも入る（`core/hurt.ts` の冒頭の注記）。被弾筋の位置や id をそこへ足すと保存の形が変わる → `HurtLog` に別の項目 `trace` を足し、保存しない
14. **ヒットストップ**: 予告の時間・擦れ・張りは `state.time` で数えるので、停止の間は止まる。擦れが「停止明けの 0.15 秒」（L06-01）になるのはこのため。附打の止め絵（1〜2 フレーム）は停止の上に時間を足さない
15. **頭上の印の席**: 「!」の位置には怯みの「*」・精鋭の名札・状態の列（`drawEnemyStatus`）・弱点の印（`drawWeaknessMark`）・大将の三角が並ぶ。印を ○ / ● にしても席は同じなので、怯み中（印は出ない）と予備動作中（「*」は出ない）は重ならない。精鋭の名札とは今と同じ段差で避ける

## 7. 未決の問い（ユーザーに聞くこと。重要な順）

1. **黄と赤の色そのもの**は今の #ffd040 / #ff4040 のまま、形と動きと音を足す方向でよいか（推奨: はい。Tips の手の言葉「黄は打て、赤は返せ」と図解をそのまま使える）
2. **頭上の「!」を ○ / ● に替えてよいか**（推奨: はい。灰色でも縮小でも形で分かれる。「!」に慣れた目が一時的に迷う）
3. **柝頭と附打を両方とも木の音にするか**。推奨は両方とも木で、柝頭は高く乾いた小さな 1 打、附打は板の低く強い打で帯域と強さを分け、ABX で紛れたら柝頭を墨の雫へ替える。最初の 1 音ずつを耳で通してほしい
4. **柝頭の判定を main 側（`audio/cues.ts` の立ち上がりの流儀）で行ってよいか**。01-combat R5 の「system で判定して `pushSfx`」から変える。左右に振るため。sim と版には触らない
5. **殺気は画面外だけで始めてよいか**。背後 120 度（画面内）は、人の記録で背後の被弾が多いと分かってから足す
6. **色替え 4 つ**（怯みの星とゲージを胡粉へ・号令の気を黄から外す・血の粒を臙脂へ）を段 0 で入れてよいか。床の銭の黄は形で分ける例外として残してよいか
7. **予告を全部の敵の後に描く順に変えてよいか**。乱戦で予告が体に隠れなくなる代わりに、線が他の敵の体の上を通る。線は自分の体の上だけ切る
8. **暗闇の階で、光の外の「自分に掛かる墨入れ」を幕の上に描いてよいか**。暗闇の怖さが少し減る。下絵は描かないので「早くは読めない」は残る
9. **並の敵の予備動作の唸り（`enemyWindup`）を止めてよいか**。乱戦で鳴り続けている。精鋭とボスだけ残す
10. **表示の設定 3 つ**（予告の太さ・閃光を抑える・予告の音）を足してよいか。どれも今日の挑戦では固定しない
11. **出端の「弾かれ」の音**を木にしないでよいか（01-combat R3 は「低い木」）。木の家は柝頭と附打で 2 つ使っているので、3 つ目は命中音の頭を削った鈍い音を推す
12. **色覚の確認**を誰に頼むか（配色の切り替えは段 4。当事者に見てもらってから決める）
