# L12 改訂版: 決定性とリプレイを、学び・挑戦・共有へ

視点: 同じ seed と同じ入力で同じ結果になることを、学び・挑戦・共有に使う。サーバは持たない。持っても静的ファイル程度にとどめる。
批評（初見のプレイヤー兼ゲーム配信者）を受けて、3 つの軸で並べ直した。

1. **人口の段**: N = 1（自分だけ）で成り立つ案を先に置く。N = 配信者 + 視聴者で成り立つ案を次に置く。N = 人口が要る案は捨てるか、発売後に回す
2. **死亡画面の予算**: 主の操作は「再挑」1 つ、副の操作は「感想戦」1 つまで。ほかの案は死亡画面に口を持たない
3. **他レーンとの統合**: 次のとおりに寄せる
   - L09 走馬灯の稽古 → 感想戦
   - L14 走馬灯の正解の記号 → 活路
   - L14 名場面帳 → 抄録を吸収してもらう
   - L08 先達 → 影法師を吸収してもらう
   - L05 果たし状 → 束ね先とし、ここでは差分だけを書く
   - L05 縁日 → 一番勝負と並べる

## 先に決めておくこと（批評の論点 3・4・5・7・9）

- **情報の漏れ**: Spelunky の作法で受け入れる。今日の挑戦と一番勝負の本番では、墨跡・先達・他人の影を出さず、終えた後に開く。配信で地図を見てから挑む人は防げないので、「初見」の印は付けない（判定できない印は嘘になる）
- **設定と sim**: 競う場（一番勝負・御前試合・果たし状の本番）では、`hitstopScale` を既定に固定する。L05 縁日の決定に揃える。ヒットストップ 0 を好む人は、稽古として遊べば記録が残らないだけ、とする
- **借り物と永続装備**: 比べる場は借り物にする。比べない場では自分の遺物を見せる。具体的には次の 3 つ
  - 果たし状の装備付きのファイル
  - 死絵（倒れた時の自分の姿に、装備の見た目が残る）
  - 先達
  - 「拾った瞬間に永続する遺物」が社会の層から消えないようにする
- **局面写しの重さ**: 基盤の完了条件に、`hitch:probe` で写しの 1 フレームを測ることを入れる
- **Steam の板の上限**: 物差し × 流儀 × 週で板が膨らむ。板を前提にする案（番付・預け仇）は、上限を確かめるまで設計しない
- **翻訳**: 辞世・軍令・死絵の題は熟語の札なので、英語では 2〜3 語の名詞句に置く。L11 訳語台帳に同時に載せる。字面の遊びに頼る札名は作らない

### 実戦譜
- 種別: 基盤
- 領域: platform
- 一言: bot ではなく人の記録を、QA の計測に掛ける。
- 仕組み:
  - `src/qa` の計測（`combatMetrics`・`bossMetrics`・`jinMetrics` など）を、`ReplayData` の早送り再生にも流せるようにする。入口は `qa:replays -- <dir>`
  - 出力は今の probe と同じ表にし、「人」の列を bot の列の隣に並べる。列は次のとおり
    - 完遂率・カウンター・見切り・受け流し・ヒットストップの割合
    - 陣の決着の形（全滅・大将・敗走）・敗走の逃げ切り
    - 行為で進んだ段階・死因
  - 標本の貯め方（批評から）: 今は `REPLAY_LIMIT = 10` で古い記録から消える。Electron 版の開発用の設定に、全部の記録を版ごとのフォルダへ書き出す口を足す（例: `replays/v35/`）。ユーザーが通しで遊ぶたびに、標本が勝手に貯まる
  - 版の違う記録は流さず、フォルダの単位で読み分ける
- なぜこのゲームで:
  - 記録さえあれば、同じ計測を人のプレイにも掛けられる。決定性があるから、後から足した計測も過去の記録へ遡って掛けられる
  - S1「見切りはほぼ 0・受け流しは未計測（bot の限界）」、S2「行為で進む段階 0%」、「難易度は実プレイの感触で」という方針に、人の数字で答えられる
  - 下の詮議・御前試合・新参が、判断の材料としてこれを使う
- 着想元: 運営型ゲームのテレメトリ。送信するのではなく、手元の記録の再生から事後に何でも測る形にした
- 安っぽくならないための要点 / リスク:
  - 1〜2 本の標本で判断しない。表に標本の数を必ず並べる
  - 開発の作法（`docs/AI_WORKFLOW.md`）に「同じ版のうちに記録を貯める」を 1 行足す
- 規模: S
- 議論で変わった点: 全記録を版ごとのフォルダへ書き出す口を足し、標本が勝手に貯まる形にした（批評の提案）。最優先に上げた。

### 局面写し
- 種別: 基盤
- 領域: platform
- 一言: 遊んでいる最中の GameState を写し、そこへ戻せるようにする。「途中から遊ぶ」案はすべてこの上に乗る。
- 仕組み:
  - `snapshotState(state)` / `restoreState(snap)` を `core/` に置く
  - **乱数の壁**（批評から）: `Rng` に `getState()` / `setState(n)` を足す。写す時だけ mulberry32 の 32bit の状態を抜き差しする。乱数列は 1 ビットも変わらないので、`REPLAY_VERSION` は据え置ける。`Rng` を純データにする全面の書き換えはしない（呼び出し側が広すぎる）
  - state の残りは `Map` / `Set` も含めて `structuredClone` できる。関数・描画のキャッシュが紛れないことを型とテストで守る
  - 控えは小さく始める。本番のランでは次の 2 枚だけを取り、メモリ上だけに置く（保存しない）
    - 降階の頭の 1 枚
    - 30 秒ごとに上書きする 1 枚
  - 枚数は、`hitch:probe` で写しのフレームの重さを測ってから増やす
  - 控えごとに状態ハッシュ（乱数の状態・frame・プレイヤー・敵の位置と生命）を取る。リプレイには階ごとのハッシュを書き、再生のずれをフレーム単位で突き止める
  - 再生器は、区間の頭の控えへ戻してから早送りすることでシークできる
- なぜこのゲームで:
  - step が純粋で、`Math.random` を禁じている（不変条件 3）から、写しが閉じる
  - 次の案が同じ写しを使う
    - 感想戦・活路・シーク・L09 走馬灯の稽古
    - 将来のマルチ（memo 0925-1）のロールバック
- 着想元: 格闘ゲームのロールバック方式（GGPO）、エミュレータのセーブステート。プレイヤーには「どこでも保存」として開けず、内部の基盤としてだけ持つ。中断セーブを作らない方針と矛盾しない
- 安っぽくならないための要点 / リスク:
  - 完了条件 1: 全バイオーム・全ボスで次を確かめる。写す → 戻す → 600 フレーム進めた結果が、写さずに進めた結果と一致する
  - 完了条件 2: `hitch:probe` で、写しのフレームが目標の予算に収まる
  - プレイヤーに中断セーブと思わせない
- 規模: L
- 議論で変わった点: 乱数の状態がクロージャにある壁を明記し、`getState` / `setState` の小さな道を選んだ。控えを 8 枚から 2 枚に減らし、固まりの計測を完了条件に入れた。

### 感想戦
- 種別: 新要素
- 領域: ux
- 一言: 倒れた直前へ戻り、記録に残らない「もう一手」を指して確かめる。
- 仕組み:
  - **死亡画面の予算**: 主の操作は「再挑」（決定の長押し）。副の操作は「感想戦」で、別のキー 1 つ。死亡画面に選択肢を 3 つ以上並べない
  - 解放: 3 回目の死から出す。初回の死はただ悔しがらせる方が、次の 1 回を呼ぶ
  - 戻る点の既定は「死の 3 秒前」。30 秒前・10 秒前は、感想戦の中で選び直す。始まるまでの待ちは 2 秒以内に収める（30 秒ごとの控えから、早送りは最大 1,800 フレーム）
  - 再生の途中で、どのキーを押しても介入できる。介入した後は自分で動かす
  - 元の自分は墨の影として重なって進む。道が分かれた瞬間に、影へ朱の点を 1 つ打つ
  - 打ち切りは 60 秒。結果は「凌いだ」か「同じく倒れた」の 2 つだけ。何度でもやり直せる
  - 生き延びても、次のものは一切動かない。新しい保存も持たない
    - 記録・報酬・図鑑・来歴・依頼
  - 御堂の負けの後にも同じ物を置く
  - L09 走馬灯の下段の時間軸は、感想戦の中の帯として吸う。帯は、予告の色の帯 1 本と、自分の打鍵の点で描く
- 判断:
  - 「3 秒前に受け流せば済んだのか」「30 秒前にあの陣へ踏み込んだのが悪かったのか」を、自分で探す
  - ボスは `pickMove` でこちらの手を読む。違う手を指せば、ボスの答えも変わる
- なぜこのゲームで:
  - 同じ入力を続ける限り、敵は同じに動く。「同じ局面をもう一度」が、本当に同じ局面になる
  - 読みの上達の線（死因 → 予告の図解 → 仇 → 御堂）の最後の 1 ピースになる。強さは何も増えない
  - 配信では「今の、受け流せたよな？」の直後に、本当にその局面へ戻れる。視聴者は「もう一度同じ攻撃が来る」のを見届ける。他のローグライクには作れない絵になる
- 着想元: 将棋の感想戦。Celeste の即やり直しの短さも参考にした。ランの最中には使えない「死後の検討」に限った
- 安っぽくならないための要点 / リスク:
  - ランの中では絶対に使えない。「どうせ戻れる」でランの緊張を溶かさない
  - 介入した入力は捨てる（記録しない）
  - 死亡画面の予算を崩さない。他レーンの案が死亡画面へ口を足したい時は、感想戦の中へ入れる
- 規模: M
- 議論で変わった点: L09 走馬灯の稽古を統合した。次の 4 つを足した
  - 死亡画面の予算（再挑が主、感想戦が副の 1 打）
  - 3 回目の死からの解放
  - 3 秒前の既定と 2 秒以内の待ち
  - 分岐の朱の点

### 活路
- 種別: 新要素
- 領域: combat
- 一言: 感想戦の中で札を引くと、倒れた一撃を「こう受ければ止まった」がゲーム自身の検算で 1 つだけ示される。
- 仕組み:
  - 最後の被弾（`HurtRecord` の敵の一撃・射撃）の 1.5 秒前の局面から、人の指で届く小さな変化を数十通り、裏で試す。変化の種類は次の 4 つ
    - k フレーム前のダッシュ（8 方向）
    - k フレーム前の受け流し
    - 攻撃をやめて下がる
    - 背面へ回る
  - **頑健さの条件**（批評から）: 候補の入力を ±2 フレームずらした 5 通りが、すべて生き延びた時だけ採る。人の指で再現できる幅を保証する。1 フレームの隙間の解は、学びにならず苛立つだけなので出さない
  - 自動では出さない。感想戦の中の札「活路」を引いた時だけ出す。答えは 1 つ
  - 示し方: 止め絵（その瞬間の予告の線を黄 / 赤のまま）に、墨の矢印と、体言止めの札（「受け流し」「見切り」「カウンター」）を描く。秒数・割合は書かない
  - 優先の順は次のとおり。同じ敵種で同じ答えが 3 回続いたら、次の順位の答えを出す
    1. 受け流し / 黄で殴る
    2. 見切り
    3. 退避
  - 見つからなければ、10 秒前の局面まで遡って位置取りの手を探す。それも無ければ「活路なし」とだけ出す。これも 1 つの答えになる
  - 示された手は、そのまま感想戦で試せる
- なぜこのゲームで:
  - 核の一文「黄なら殴れ、赤なら受け流せ」は、今は Tips にしか無い（S1）。それを UI の説明文なしで、自分の死の場面で体に入れる
  - 結果が乱数で揺れないので、「この手なら確実に生きた」と断言できる。L14 走馬灯の「正解の記号」は人が決めた目安だが、活路は検算した答えになる。走馬灯の記号の中身として差し替えられる
- 着想元: 将棋 AI の検討モード。最善手を探さず、人が次に再現できる 1 入力の差だけに絞った
- 安っぽくならないための要点 / リスク:
  - 計算の重さ（候補 40 × ずらし 5 × 90 フレーム × 約 200 体の階）。Worker は sim 全体を載せる手間が大きい。まず `requestIdleCallback` で区切って回して測る
  - 状態異常・地形・死神での死は対象外にする
  - 初見の「自分で気付く」楽しみを奪わない。札を引くのはプレイヤーの意思だけにする
- 規模: M
- 議論で変わった点: 「手筋」から改名した（L01・L03 と衝突）。次の 4 点を変えた
  - ±2 フレームの頑健さの条件を入れた
  - 自動の表示をやめ、感想戦の中の札にした
  - 3 つ並べるのをやめ、答えを 1 つにした
  - L14 走馬灯の記号の中身とする統合先を書いた

### 詮議
- 種別: 基盤
- 領域: encounter
- 一言: 乱数の無いボスに「必ず勝てる型」が潜んでいないかを、決定的な総当たりで公開前に洗い出す開発の道具。
- 仕組み:
  - 活路と同じ探索を、ボスの側へ向ける。主の間で、単純な方針の組み合わせを数百通り回す。組み合わせの材料は次の 3 つ
    - 静止の位置（格子 8 × 8）
    - 方針（止まる・円を描く・壁を背にする・柱の陰に入る）
    - 反撃（間の終わりに左を 1 回）
  - 次のどちらかを満たす方針を「抜け道」として報告する
    - 同じ技の繰り返しに 3 周以上はまり、無傷で生命を削り続けられる
    - 段階を、行為ではなく 1 つの方針の繰り返しだけで越えられる
  - 出力は `qa:probe -- --bosses` の表に「抜け道」の列として足す。見つかった方針の短い入力列を添え、感想戦の再生器で開けるようにする
  - **設計した誘い**（柱の前で突進を誘う、など）は、表の別の列に並べて消さない。消すのは、設計していない永久の型だけ
- なぜこのゲームで:
  - 「ボスは乱数で揺らさない（覚えられるように）」は正しい決定だ。ただし裏を返すと、1 つの永久の型が見つかればボスは死ぬ。御前試合・一番勝負で記録を競わせるなら、公開の前に必ず要る
  - `BOSS_THREATS` の near / far / moving / still を段階ごとに入れ替える設計が、「止まっていては勝てない」を本当に作れているかを、bot の癖抜きで確かめられる。S2「行為で進む段階 0%」の調べにもなる
- 着想元: スピードランの AI 操作の発見、格闘ゲームの無限コンボの検証。それを開発が先回りして探す。乱数が無いので、見つかった抜け道が毎回効くと断言できる
- 安っぽくならないための要点 / リスク:
  - 抜け道を全部消すと、読みの楽しみまで消える。設計した誘いとの区別を表で守る
  - 重い実行なので、`qa:full` と同じく裏で回す
- 規模: M
- 議論で変わった点: 批評の派生案から取り込んだ。設計した誘いを別の列に分ける点を明確にした。

### 御前試合
- 種別: 拡張
- 領域: meta
- 一言: 御堂のボスに、週替わりで全員が同じ借り物で挑み、段階ごとの刻と影で競う。
- 仕組み:
  - 御堂に台を 1 つ足す。週替わりで、次の 3 つを日付から決定的に固定する
    - ボス 1 体
    - 借り物の持ち物 7 部位
    - 流儀
  - 主の間は乱数の無い手描き、ボスは乱数の無い `pickMove`。同じ入力なら同じ戦いになる
  - 段階ごとに刻（区切りの時刻）を残す。自分か取り込んだ記録の最良の影を主の間に重ね、影の側のボスも薄墨の輪郭で描く
  - 記録は「最速」と「最少被弾」の 2 本立て。段階の刻は、感想戦の帯と同じ絵で見せる
  - ヒットストップは既定に固定する
  - 週の対象に入れる条件は、次の 2 つを満たすこと
    - 詮議で抜け道が無い
    - 実戦譜で行為の段階が進んでいる
  - 鏡の騎士（34 秒で倒れる）と盗賊王は、直るまで外す
- 判断: ボスの技選び（距離・静止の秒・直前のダッシュ・背面）を逆手に取る「誘い」を探す。たとえば、静止して狙いの技を誘う、柱の前で突進を誘う。攻略が人の間で育つ
- なぜこのゲームで:
  - 「ボスは乱数を使わずにプレイヤーを読む」「主の間は seed で揺らさない」「御堂は `hallSeedText(key)` の固定 seed で `createGame`」という既に決めたことが、そのまま公平な競技の前提になる
  - 1 戦 2〜3 分は配信の 1 コーナーにちょうど良い。N = 1 でも、自分の先週の記録と比べて遊べる
  - L05 絵馬（ボスを読んだ証）と組み合わせると、競技の記録に「何を読んだか」の軸が加わる
- 着想元: スピードランのボス操作の文化、Furi のボスラッシュ。乱数が無いので「運の良い試行」が無く、記録がすべて読みの記録になる
- 安っぽくならないための要点 / リスク:
  - 最速だけにすると「被弾覚悟で殴る」が正解になる。最少被弾の板と並べる
  - 借り物は、週ごとの当たり外れを避けるため、そのボスの読みを問う構成で手で選ぶ（日付の抽選にしない）
  - 版の切り替えを週の境に揃える（二重記録の作法）
- 規模: M
- 議論で変わった点: 「奉納試合」から改名した（L05 の「奉納」と衝突）。次の 2 点を変えた
  - 詮議の通過と実戦譜の確認を、週の対象の前提にした
  - 借り物を日付の抽選から手選びに変えた

### 一番勝負
- 種別: 新要素
- 領域: run
- 一言: 今日の挑戦の短い版。1 章 5 階を同じ借り物で 1 回だけ、その日の軍令で競う。
- 仕組み:
  - 全編の今日の挑戦（L05 縁日）とは別に、毎日 1 本の短い勝負を置く。高札に 2 本並べる
  - 中身は次のとおり
    - 日替わりの 1 章（5 階 + 章ボス）
    - 日付から作った借り物（章 2 以降はその深度相当）
    - 縛り 1 つ
    - 流儀は自由
  - 1 回だけ。2 回目以降は稽古扱いで記録に残らない
  - **前日の予告**（批評から）: 章は日付で選ぶが、高札に「明日は章 3」と前日に出す。初見の人は章 1〜2 の日を待てる
  - **誤操作の救い**（批評から）: 入って 30 秒以内の死は、稽古に回して数え直しを 1 回だけ許す

- なぜこのゲームで:
  - 1 章は休符 → 登り → 章ボスで、それだけで起承転結がある（章の弧の強み）
  - 全編は日課として重い。「毎日戻る理由」を、15 分の器で作る
  - L11 一章体験（体験版は章 1）と同じ器で作れる。配信の頭に「今日の 1 本」として置ける

- 安っぽくならないための要点 / リスク:
  - 縁日と記録の置き場が二重にならないよう、高札の 1 枚に 2 本を並べる
  - 日付の境目は、既存の `dailySeedText`（UTC）に揃える
- 規模: M
- 議論で変わった点: 次の 4 点を足した。L05 縁日と並べる形にした
  - 前日の予告
  - 30 秒以内の死の救い
  - 本番中に他人の痕跡を隠すこと
  - 軍令との結び付け

### 手本影
- 種別: 新要素
- 領域: ux
- 一言: 開発者が記録した「型の手本」を、見取り → 写しの 2 拍で見せる。武器掛け・稽古場・初陣の 3 か所に出る。
- 仕組み:
  - 型 15 ごとに、手本を 1 本ずつ作る
    - 局面は短い（敵 2〜3 体）
    - 固定の seed で、御堂と同じく `createGame` する
    - 中身は開発者が記録した入力列（戦意の溜め方・放出の段・黄で割り込む・赤を受け流す）
  - 見せ方は、並走をやめて **見取り → 写し** の 2 拍にした（批評から）。手本の 6 秒を流した後、同じ局面が自分の番で始まる
  - 出る場所は 3 つ
    1. **武器掛け**: 型にカーソルを合わせると、手本が 5 秒の環で流れる。初見の人は、選ぶ前に「この型は何をすると強いか」を目で知る。そのまま Steam のストアの GIF にも使える
    2. **稽古場**: 見取り → 写しの台。慣れた人は、手本より速く・無傷でを狙う
    3. **初陣の先駆**（批評の派生案「先駆」から）: L11 初陣の手描きの階で、影が陣ごとに区切って先に戦って見せる。1 の陣はカウンター、2 の陣は受け流し → 処刑、3 の陣は大将討ち → 総崩れ。プレイヤーが陣の手前に着くと影が 4〜6 秒戦い、その後に自分の世界の陣が起きる。初陣を抜けたら影は消え、二度と出ない
  - 文字の説明は無い（説明は Tips ノートに置く原則）
  - CI のテストで「手本の入力を再生すると、今の版でも目標を達成する」を検査する。版を上げて手本が崩れたらテストが落ち、録り直すべき手本が分かる。型の戦意の作りが変わったことを知らせる検知器にもなる
- なぜこのゲームで:
  - S1 問 4（戦意 15 通りを初見にどう伝えるか）と S5 問 1（最初の 30 分を誰が導くか）に、UI の説明文なしで答える
  - 「同じ局面をもう一度」は決定性が無いと成立しない
  - 初陣は手描きなので、影の世界と自分の世界が完全に一致する
  - L09 型稽古との役割分担: 型稽古 = 敵の読み、手本影 = 自分の型の使い方
- 着想元: 格闘ゲームのコンボトライアルのお手本、武道の見取り稽古、参詣の先達。手本と自分の番を時間で分け、注意が割れないようにした
- 安っぽくならないための要点 / リスク:
  - 影に台詞・名札を付けない。チュートリアルの声にしない
  - 手本は少し遅め・余裕を持った手にする。上手すぎると「自分にはできない」になる
  - 先駆は、探索履歴が 0 件の時だけ出す。保存値は足さない
  - 開発者が上手く演じられない型は、入力を手で組んでよい
- 規模: M（先駆は L11 初陣の後に +S）
- 議論で変わった点: 並走を見取り → 写しの 2 拍に変え、武器掛けの 5 秒の環を最初の出口にした。批評の「先駆」を 3 か所目として取り込んだ。

### 二重記録
- 種別: 基盤
- 領域: platform
- 一言: 版を上げる作法を決め、記録に「版が変わっても見られる足跡」の層を足して、更新で記録を死なせない。
- 仕組み:
  - **1. 版の作法**（批評から。最も安い根本の手当て）
    - `REPLAY_VERSION` は、配布の版を切る時にだけ上げる。開発中は今の速さでよい
    - 競う場（一番勝負・御前試合）は「その週の版」に結び付け、配布の版の切り替えを週の境に揃える
    - `docs/AI_WORKFLOW.md` に 1 行足す
  - **2. 足跡**（先に入れる。M）
    - 入力列（今の `ReplayData`）の隣に、版に依らない足跡を書く。圧縮して 1 時間で数十 KB。中身は次の 2 つ
      - 4 フレームごとの位置・向き・動作の種類・生命の帯
      - 階・出口の選択・陣の決着・死因・辞世
    - 足跡で動くもの: L08 先達、L11 墨跡、死絵、辞世、L14 名場面帳の低精細版。版が上がっても生きる
    - 入力列は、`REPLAY_VERSION` と `BALANCE_HASH` が合う時だけ使う（再生・感想戦・活路）
  - **3. 再生の確かめ**（後段。Steam の板ができてから）
    - 他人の記録を取り込んだら、入力列を早送りする
    - 階ごとの状態ハッシュ（局面写し）と結果を照らす
    - 合う記録だけを競う板に載せる
  - 「人には不可能な頻度の入力」を疑う判定は捨てた。誤検知で上手い人を疑うと、競う場の信用が一番傷つく
- なぜこのゲームで:
  - 決定性があるので、改ざんの確かめをサーバ無しで各自の手元でできる
  - L05 果たし状・L11 棋譜棚が版の壁で日ごとに死ぬ問題を、作法と足跡の 2 段で救う
- 着想元: スピードランの動画による検証、TAS の入力ファイル。検証を中央でなく各クライアントの再生で行い、版を越える層を別に持つ形にした
- 安っぽくならないための要点 / リスク:
  - 足跡の形式は一度決めたら滅多に変えない（`v1` を切る。不変条件 8 の作法）
  - 足跡は描画専用で、state に書き戻さない（不変条件 1）
- 規模: 作法 S + 足跡 M。再生の確かめは後段で M
- 議論で変わった点: 版の作法を先頭に置いた。足跡と再生の確かめを別の段に分け、疑わしい入力の判定を捨てた。

### 得点撤去
- 種別: 整理・削減
- 領域: meta
- 一言: HUD・死亡画面・探索履歴から得点とコンボ倍率を外し、空いた所を「何が起きたか」で埋める。
- 仕組み:
  - `state.score`・`meta.bestScore` と、それを出す表示を外す（S5 3-2）。スコアを読んでいる実績・依頼・テストを先に洗い出す
    - 例: `meta/deathReport`・`ui/menuFocus`・`loot/profile`
  - 空いた所の埋め方
    - 探索履歴の行: 辞世（自動）と、到達の章・階
    - 死亡画面: 死因と予告の色、前回の到達との差。差は階の数だけで、点にしない
  - 番付（物差し × 流儀の表）は、Steam の板が入って他人の記録が並ぶまで作らない。自分の履歴だけで並べると、全部の欄で自分が 1 位になって意味が無いため
- なぜこのゲームで: 原則 8（単一指標を出さない）に反して残っている得点の片付けで、N = 1 で今すぐ効く。上の軍令・一番勝負・御前試合が、比べる物差しを場ごとに持つので、全体の点は要らない
- 着想元: スピードランのカテゴリ（Any% / 縛り）の考え。比べる場ごとに物差しを持ち、全体の点を持たない
- 安っぽくならないための要点 / リスク:
  - 「得点が無いと上達が見えない」の声には、感想戦・死絵・御前試合の刻で答える
  - 位の名（大関など）は GLOSSARY の「大」の扱いとぶつかる恐れがある。番付を作る時にユーザーに確かめる
- 規模: S〜M
- 議論で変わった点: 番付から得点の撤去だけを切り出して今すぐ採り、番付そのものは人口が付くまで凍結した。

### 詰陣
- 種別: 新要素
- 領域: encounter
- 一言: 稽古場で、手書きの陣の局面を「この陣をこう崩せ」と出題する。八陣の崩し方を 1 問ずつ体で覚える。
- 仕組み:
  - 局面写しからは切り出さない（批評から）。御堂と同じく、固定の seed と手書きの配置で `createGame` する。手書きするのは次の 4 つ
    - 陣形
    - 格
    - 群勢
    - 地形
  - 版に依らずに問題を作れ、他の陣・死神・長居の代償が混ざって条件が濁ることも無い
  - 章ごとに 3 問。各問は、陣形 1 つの崩し方を 1 つ教える。例は次のとおり
    - 鶴翼は翼の端から
    - 長蛇は頭を叩くと後ろが崩れる
    - 物見を先に討てば後詰が来ない
  - 条件は固定の表から選ぶ
    - 無傷で大将を討つ
    - 10 秒以内に敗走させる
    - 受け流しだけで止める
    - 地形の反応で 5 体
  - 解くと、Tips ノートに陣形の頁が 1 枚開く
  - 自分の解いた手順は、感想戦の帯で見返せる
  - プレイヤーの出題は捨てた
- 判断: 群勢・大将・後詰・物見・同時攻撃の上限という陣のルールを使い、最短の崩し方を考える。S2 問 2（陣と戦う理由）に、陣を崩す技術そのものを遊びにして答える
- なぜこのゲームで: 陣は他のアクションローグにほぼ無い単位で、決着の形が 3 つある（全滅・大将・敗走）。だから「詰め方」が複数ある。決定性で、問題は毎回同じ局面になる。L11 初陣・手本影の先駆の続きの「陣の稽古」になる
- 着想元: 詰将棋（出題者が詰みを保証する文化）、Into the Breach の完全情報の局面。リアルタイムアクションの局面を完全に再現し、読みと手の速さの両方を問う形にした
- 安っぽくならないための要点 / リスク:
  - 量産しない（章ごと 3 問の手作り）
  - 解けることを、開発の解の入力列のテストで保証する。手本影と同じ CI の検査に載せる
- 規模: M
- 議論で変わった点: 局面写しの切り出しとプレイヤーの出題を捨て、手書きの配置と稽古場の教材に変えた。規模を L から M に下げた。

### 軍令
- 種別: 拡張
- 領域: encounter
- 一言: 競う場の物差しを、陣の決着の仕方を指定する「軍令」として出し、地図の上の該当の陣に藍の旗を立てる。
- 仕組み:
  - 物差しを、陣の扱い方の判断を問う 6 つに絞る
    - 大将首: 大将を討って崩した陣の数
    - 追討: 敗走させた陣の兵を逃がさない（逃げ切られた数が少ないほど上）
    - 無血: 無傷で決着させた陣の数
    - 忍び: 陣を起こさずに降りた階の数
    - 一騎: 物見・後詰の合流より先に大将を討った数
    - 退き口: 起きた陣を背にして、死神より前に階段へ着いた階の数
  - 階に降りると、軍令に合う陣の上に小さな藍の旗が立つ。大将首の日は、大将付きの陣だけに立つ。藍は物見の視界の色と被らない色にする
  - 1 回の勝負に軍令は 1 つ。祝福・装備の数値には一切触れない
  - 一番勝負の日替わり、御前試合（ボス戦には一騎・無血の読み替え）、果たし状の物差しに共通で使う
- なぜこのゲームで:
  - 陣の 6 割が素通りされ、敗走の 42% が逃げ切る問題（S2 問 2・3）に、競う場の中でだけ「この陣と、この形で交わる理由」を与える。本編の釣り合いは動かさない
  - 陣・八陣・群勢・大将・物見・後詰という、他のアクションローグに無い単位を、そのまま競技の種目にする
  - 単一スコアを出さずに、日ごとに違う勝ち方を作る（原則 8）
- 着想元: 戦国の軍令状、Slay the Spire の Daily Climb の修飾子。修飾子は規則を変えるが、軍令は規則を変えず「何を手柄とするか」だけを変える
- 安っぽくならないための要点 / リスク:
  - 撃破数・処刑数のような数え上げの種目は入れない
  - 忍び・退き口は陣と戦わない種目なので、戦う種目と隔日にする
  - 旗の表示は競う場だけ。本編には出さない
  - L05 手柄の判定と同じ検出を読む。二重に数えない
- 規模: M（一番勝負と同時）
- 議論で変わった点: 批評の派生案から取り込み、元の番付の物差しの表をこれに置き換えた。「殿」を「退き口」にした（L02 と衝突）。

### 死絵
- 種別: 拡張
- 領域: meta
- 一言: 図鑑の敵の頁に、その敵に初めて倒された瞬間を、版画の調子の 1 枚絵と辞世で残す。
- 仕組み:
  - 初めてその敵に倒された時だけ、死の直前 1 秒の足跡を数値で残す。1 枚で数百バイト。中身は次のとおり
    - 自分・その敵・陣の仲間の位置と向き
    - 予告の線の形と色
    - 自分の装備の見た目
  - 図鑑の敵の頁を開くと、足跡から描画で 1 枚絵を組み直す
    - 色は墨・朱・藍の 3 色に落とし、版画の線で描く
    - 題は自動の辞世（「盾騎士・赤・後詰」）
  - 同じ敵に 3 回倒されて予告の図解が開くと、死絵の横に図解が並ぶ。「自分が死んだ形」と「本来の読み方」を見比べられる
  - 絵に陣形の輪郭（鶴翼の翼に挟まれた、など）が残る。「どの陣形のどの位置で死んだか」が読める
- なぜこのゲームで:
  - 図鑑の敵の頁が「地下 n 階から / 撃破 n / 図解」だけで痩せている（S5 3-4）。そこに、自分にしか無い 1 枚が入る
  - 描画は state を読むだけ（不変条件 1）なので、足跡から同じ画風で何度でも描き直せる。足跡の層なので、版の更新でも消えない
  - 比べない場で、自分の遺物の見た目が社会の層に出る。配信では「図鑑を開くと自分の死に様の画集になっている」が共感の種になる
- 着想元: 江戸の死絵（役者が亡くなると出た追悼の錦絵）。追悼の版画を、自分が倒れた瞬間の記録に移した。Souls の血痕は他人の死だが、こちらは自分の死の画集
- 安っぽくならないための要点 / リスク:
  - 図鑑の側の保存に足跡を足す。新しい保存キーの扱いをユーザーに確かめる
  - 画風の描き方を 1 つ決めて、全部の敵に当てる。敵ごとの手描きはしない。L07 墨・L14 版の画風に揃える
  - 死を嘲る調子にせず、追悼の静けさで描く
- 規模: M
- 議論で変わった点: 批評の派生案から取り込んだ。装備の見た目を絵に残し、「比べない場で遺物を見せる」役も持たせた。

### 辞世
- 種別: 新要素
- 領域: meta
- 一言: そのランで実際に起きた語だけで 3 語の題を自動で組み、探索の題として記録に残す。
- 仕組み:
  - 死んだ時に、記録から 3 語を組む。札は「誰に・何で・どこで」の 3 列から 1 つずつ取る
    - 誰に: 最後の被弾の敵名と精鋭の性質
    - 何で: 被弾の種類（`HurtKind`）・予告の色
    - どこで: 陣形の名・陣の語（背後・囲み・後詰）・地形
  - 例: 「盾騎士・赤・後詰」
  - 死亡画面では黙って表示するだけで、選ばせない（死亡画面の予算を守る）
  - 直したい人だけ、探索履歴の行から同じ札の中で差し替える。自由入力は無い
  - 出る場所は 3 つ
    - 探索履歴の行（得点撤去の後の空白を埋める）
    - 死絵の題
    - 墨跡・先達の上の小さな札（足跡の層）
- なぜこのゲームで:
  - 死因の記録（`killer`・`grudge`・`HurtKind`）と陣の語彙が既にある。そこから作るので、嘘が書けない
  - 熟語で名付ける原則と、墨淵・死ぬと墨に還る世界観に合う
- 着想元: 辞世の句、Dark Souls のメッセージ。Souls の定型文は嘘と冗談のための道具だが、こちらは「起きたことの題」に役目を移した。他人への伝言ではない
- 安っぽくならないための要点 / リスク:
  - L15 が「テンプレの文が透ける」として辞世を落とした。こちらは文を作らない。3 つの名詞を「・」で並べるだけにし、助詞と述語を持たせない
  - 札の語は GLOSSARY の表示名をそのまま使い、新しい語を作らない
- 規模: S
- 議論で変わった点: 3 語を選ばせるのをやめ、自動で組んで黙って表示する形にした。役目を「他人への伝言」から「自分の探索の題」に移した。

### 果たし状（L05 への差分）
- 種別: 拡張
- 領域: meta
- 一言: L05 の果たし状に、チャットへ貼れる短い札、軍令の物差し、配信の視聴者から挑む使い方を足す。
- 仕組み:
  - 束ね先は L05 の果たし状（seed・支度・装備の写し・版の文字列。影は 2 段目）。ここでは 3 つだけを足す
  - **2 層の札**（批評から）
    - 短札（20 字前後）: seed・流儀・縛り・軍令の 4 つ。配信のチャット（500 字前後の上限）に貼れる
    - 装備付きの本状: ファイルにする。Steam 版では板の添付
  - **軍令の物差し**: 1 通に 1 つを選ぶ。相手の得意を外す物差しを選ぶのが、書く側の判断になる（剣の友に、重打の持ち物で「大将首」を挑む）
  - **視聴者の果たし状**: 視聴者が短札をチャットに貼り、配信者が門前町の高札で受ける。配信の企画として最初から想定する
  - 返し状（結果の往復）は後回し。まず片道で遊べるようにする
- なぜこのゲームで:
  - 物差しを勝負ごとに決めるので、単一指標を持たずに比較が成立する（原則 8）
  - 本状では自分の永続の遺物を他人に貸して遊ばせる。永続装備のゲームの社会性として一番このゲームらしい
  - 人のいない門前町（S5 3-3）の高札に、他人の気配を貼る
- 着想元: 郵便将棋、Trackmania のゴースト交換。配信のチャットという狭い窓に合わせて札を 2 層にした
- 安っぽくならないための要点 / リスク:
  - 借り物の遺物は、受け手の倉庫に入らない
  - 依頼・仇・解放制・位階は効かない。図鑑は動く
- 規模: S（L05 の 1 段目の後に）
- 議論で変わった点: 本体を L05 に寄せ、差分だけにした。次の 3 点を変えた
  - 2 層の札と配信の使い方を足した
  - 返し状を後回しにした
  - 物差しを軍令に揃えた

### 新参
- 種別: 基盤
- 領域: meta
- 一言: 新しい階の主は、まず御前試合の週の主として全員の前に出て、読まれ・測られてから本編に入る。
- 仕組み:
  - ユーザーのメモ「全階層に固有のボス」と L02 家臣団（章ごとに家臣 3 人）を、発売後の更新の流れにする
  - 新しい主ができたら、1 週間は御前試合の主の間だけに出す（固定の配置・借り物・乱数なしの `pickMove`）。高札には「新参」の札
  - その週の記録を、実戦譜と詮議で測る
    - 自分の分（発売前）
    - Steam 版の板の上位の入力列（発売後）
  - 段階の進み方・抜け道・危ない間合いを見て、翌週の版で本編の主の抽選に入れる
  - 本編に入った主の図鑑の頁に、「新参の週」の日付が残る
- なぜこのゲームで:
  - 全階層の固有のボスを一度に作ると量産になり、質が落ちる。1 体ずつ、人の手で読まれてから本編に入れれば、「考え抜いて作り込む」と量の両方が立つ
  - 決定的な主の間のおかげで、全員が同じ戦いをする。手直しの判断に使える記録がそろう
  - 配信では「今週の新参を初見で倒す」が毎週の企画になり、更新告知の見出しにもなる
- 着想元: 格闘ゲームの新キャラの先行配信、MMO の試験サーバ。試験の場を別に立てず、本編と同じ sim の決定的な一室を試験場にした
- 安っぽくならないための要点 / リスク:
  - 週ごとに出すことを目的にしない。出すのは「できた時」で、週は枠にすぎない
  - 発売前は、ユーザー自身が 1 人で「新参の週」を回す。開発の段取りとしてそのまま使える
- 規模: L（家臣団・御前試合・詮議の後）
- 議論で変わった点: 批評の派生案から取り込み、詮議と実戦譜を判断の道具として結んだ。

## ユーザーに聞くこと

- **章の境の中断**（襷継ぎから残した問い）: 中断セーブを作らずに、Steam Deck と短時間のプレイをどう両立するか（S5 問 8）。休符の階（6・11・16）でだけ、入力列 + 局面写しで中断できるようにしてよいか。社会性の案に包まず、独立した問いとして渡す
- 死絵の足跡を、図鑑の側の保存に足してよいか
- 番付の位の名（大関など）を使うか。GLOSSARY の「大」の扱いとの兼ね合い

## 捨てた案と理由

| 案 | 理由 |
| --- | --- |
| 影法師 | 50〜70 分のランでは、道が分かれた 10 秒後に影は画面の外に消える。残るのは階段の手形と出口の選択で、L08 先達とほぼ同じ物になる。L13 と名前も衝突する。陣の交戦 / 素通りの旗（黒 / 白）だけを、先達へ渡す |
| 預け仇 | 友がこのゲームを持っていなければ動かない。見返りが名札付きの敵 1 体で、往復の手間に釣り合わない。仇の拡張は L13 宿敵の方が N = 1 で効く。「Steam の友達の板の整数に仇の種を書き、コード無しで流す」仕掛けは、Steamworks 導入の後に宿敵の外向けの版として残す |
| 衆怨 | 発売直後には、毎日の集計に意味が出る人数が無い。定時の集計と鍵の管理で、運営の作業が増える。「個人 → 友 → 全員」の 3 段は、人口が付いてから御前試合の週の選び方として戻す余地を残す |
| 襷継ぎ | 遊ぶ相手が揃わない。早送りの待ち・遺物の持ち主・中断セーブとの線引きと、決めごとが重い。自分への襷は中断セーブの言い換えになる。問いだけを「章の境の中断」として独立させた |
| 番付 | 自分の履歴だけで並べると、全部の欄で自分が 1 位になる。96 欄が空欄の表になる。得点の撤去だけを切り出して採り、物差しは軍令に置き換えた。Steam の板が入ってから再考する |
| 抄録 | L14 名場面帳と同じ物（名場面の印・決定的な再生での書き出し）。「場面の型を熟語の札で名付ける」部分だけを名場面帳へ渡す。「一網打尽」は `system/jin.ts` で使用中なので、札の名から外す |
| 読み譜（独立の画面として） | 480×270 の上下 2 段の帯は、配信の画質で潰れ、陣では帯が溢れる。ボス戦の「予告の色の帯 1 本 + 打鍵の点」に縮め、感想戦・御前試合の中の帯として吸収した。戦意の下段は手本影で見せる |
| 疑わしい入力の判定（二重記録の一部） | 誤検知で上手い人を疑うと、競う場の信用が一番傷つく。確かめは「再生して同じ結果になるか」だけにした |
| 詰陣のプレイヤー出題 | 解の添付を必須にしても、問題の面白さは保証されない。版のたびの作り直しも重い |
| 先駆（独立の案として） | 手本影の 3 か所目として統合した。名前が L08 先達と紛らわしい点も避けた |
