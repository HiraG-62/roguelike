# L09 UX・オンボーディング・可読性（改訂）

視点: Steam のレビューで「分かりにくい」「理不尽」「最初の 1 時間がつらい」と叩かれる理由。批評（初見のプレイヤー兼配信者の視点）を受けて改訂した。2026-10-02 のコードで追加に確かめた事実は次のとおり。

- 予備動作中の敵の体の点滅は、黄の間もずっと赤（`src/render/renderer.ts` 1620 行。`WINDUP_RED_ALPHA` 0.55 で `COLOR_TELEGRAPH` を重ね、コミットの前後を見ていない）。批評の指摘どおり
- 予告の線は 1 論理 px・不透明度 0.35（`src/data/balance/feel/TELEGRAPH.json`）
- パッドは右スティックが中立だと `aimScreen` が null になり、向きは移動方向（`src/core/input.ts` 616 行付近）
- 地形には「穴」（川・池・奈落。体は通れず、弾と視線は越える。`src/map/grid.ts`）があり、固定の断片を置く仕組み（`src/map/layout/` の prefab）もある。高低の段は無い
- ミニマップ（`src/render/minimap.ts`）は陣・大将を描いていない。右上の「スコア」は `src/render/renderer.ts` 3099 行で今も出ている

## この視点から見た今のゲームの課題（改訂）

1. **核の合図が体の上で逆を言っている**。線と「!」は黄なのに、プレイヤーが見る体は黄の間から赤く点滅する。どのオンボーディングを足しても、ここが直らない限り「黄なら殴れ」は嘘に見える
2. **教える器が 0 で、入口に意味の分からない選択が 4 枚続く**（町 → 井戸のジョブ・起点・縛り → 依頼）。最初の 1 撃まで遠い
3. **Tips 133 項目へ辿り着く道が無い**。「説明は UI でなく Tips」が「説明に辿り着けない」になっている
4. **死の理由が残らない**。画面外の射手・200 体の混戦で何に当たったかが分からず、死の演出も薄い
5. **見る条件を考えていない**。1 px・0.35 の線は配信の圧縮・Steam Deck・ストアの縮小画像でまず消える。読みのゲームを配信で売るなら致命的
6. **最初の 1 時間を測る物差しが無い**。初陣・開帳のような案の効き目を確かめられない
7. **パッドで引き撃ちができない**。銃の家系 8 種・書・投具が Deck で遊べない

### 黄赤一致
- 種別: 改善
- 領域: combat
- 一言: 予告の「黄 = 殴れる / 赤 = 確定」を、線・体・頭上の印・形の 4 つで食い違いなく言わせる。体の点滅は黄の間は黄、コミットの瞬間だけ赤く縁取る
- 仕組み:
  - 体の点滅（`renderer.ts` 1620 行）を、コミット前は `readyColor`（黄）で重ね、`attackCommitted` が真になった瞬間に赤の縁取りを 1 回だけ強く入れて、以後は赤で点滅させる
  - 線の形: 黄は破線、赤は実線 + 先端の返し 2 本。輪・扇・着地の予告にも同じ規則を当てる（L14 運筆予告・L11 濃淡予告と 1 つにまとめる）
  - 線の太さは最低 2 論理 px と暗い縁取り（下限の数は「目付」の測りで決める）
  - 描画だけの変更で、決定性・リプレイに触れない。`TELEGRAPH.json` に数を置く
- なぜこのゲームで: 応手（受け流し・カウンター・見切り）が気力・戦意・祝福の発火に換金される設計の入口が、この 2 色の読みしかない。今は体が「赤 = 避けろ」と言っているので、黄の間に殴る判断そのものが生まれていない。他の全案（初陣・柝・顔見世）の前提
- 着想元: Sekiro の危（赤い字は確定の印だけに使う）。色の意味を 1 つに絞り、さらに形でも二重に言う所を、全部の予告の段へ広げた
- 安っぽくならないための要点 / リスク: 体の黄の点滅が「状態異常（燃焼・帯電）の色」と紛れないかを確かめる。黄の重ねは不透明度を下げ、赤の縁取りだけを強くして、変わり目そのものを合図にする
- 規模: S
- 議論で変わった点: 批評の指摘（体の点滅が黄の間も赤）を受けて新設。旧「柝」から線の形を移し、最優先の S の修正として切り出した

### 初陣
- 種別: 新要素
- 領域: ux
- 一言: 初めての起動は町を通さず参道へ直接下ろし、手描きの地下 1 階で、文字を使わず 4 つの陣で黄・赤・見切り・大将を体で覚えさせる
- 仕組み:
  - 探索の回数が 0（`meta.runs`。新しい保存キーは不要）なら、タイトルの最初の項目を「降りる」にし、石段を下りる演出からそのまま地下 1 階へ。ジョブは見習い、起点・縛り・依頼は出さない（選択の画面を 1 枚も出さない）。2 回目以降は通常の生成
  - 地下 1 階は `src/map/layout/` の prefab の固定の断片で組む。乱数を引かないので誰の初回も同じになる
  - 陣 1「一騎」: 予備動作の長いスライム 1 体。黄の間に殴ると怯みとカウンター。黄→赤の変わり目で「柝」が鳴る最初の 1 回
  - 陣 2「盾」: 盾騎士 1 体。正面は通らず、赤の突きを受け流すと崩れる。受け流しのキーは石灯籠に刻んだキーの絵だけ（`keyLabel` で組む）。成功には附打（L14）の音
  - 陣 3「狙い」: 川（穴。弾は越え、体は通れない）の向こうに射手 2 体。回り込む細い橋は射線の下にあり、見切りのダッシュで抜けるしかない
  - 陣 4「鶴翼」: 7 体の小さな陣と大将。大将を倒すと群勢が敗走し、「全滅させなくてよい」が分かる
  - 階の主の後の出口は 2 本だけ（祝福 / 遺物）。片方の先の奈落の向こうに、章 1 の主の影だけを見せる（戦わない）
  - 初回の地下 1 階は死神を出さない
  - 目安: 起動から最初の 1 撃まで 60 秒、最初の陣まで 3 分（「初動計」で測る）
- なぜこのゲームで: 陣・群勢・大将・敗走は他のアクションローグに無い単位で、最初の 5 分で一度見せないと 200 体の地図が「避ける障害物」になる。文字を使わないので、英語版でもそのまま効く。`runMeta` の道に旗を 1 つ足せば決定性とリプレイを保てる
- 着想元: Hollow Knight の「王の道」、Celeste の序章（文字なしで地形が順番を教える）。教える対象を移動ではなく「予告の読み」と「陣の崩し方」にした
- 安っぽくならないための要点 / リスク: 吹き出し・矢印は一切出さない。陣は素通りできるようにして教習所にしない。固定の階は 2 回目以降遊ばれないので作り込みすぎない。QA の bot の経路を必ず通す。2 回目の探索が一番の離脱点になるので、「開帳」の 2 回目の中身と組で確かめる
- 規模: M
- 議論で変わった点: 町を飛ばして直接下ろす・目安の秒数・柝と附打の初回・主の影を批評から取り込み、陣 3 を高低の段（無かった）から川と橋に置き換えた。L11 初陣と統合する前提

### 柝
- 種別: 改善
- 領域: combat
- 一言: 自分に向いた攻撃が赤（確定）に変わった瞬間だけ、拍子木の「カン」を左右の定位付きで 1 打鳴らす。鳴らない赤は無視してよい、が耳で分かる
- 仕組み:
  - コミットの瞬間に、その攻撃の範囲（線・扇・輪）が自分に掛かるかを system の側で判定し、掛かるときだけ `pushSfx` で積む（不変条件 7 のまま。判定は step の中なので決定的）。定位は敵の位置から
  - 音程は 1 つ。役割で 3 段に分ける案は捨てた
  - 同時に赤くなる上限（0.3 秒に 3 つ）の中なので、多くても 3 打に収まる
  - 先に「鳴物帳」を置く: 情報を運ぶ音（柝・附打・死神の合図・陣の拍・放出の合図・瓶の空・気力の不足）を `src/audio/` の表 1 枚に並べ、音色の家（木を打ち合わせる / 板を叩く / 鐘 / 太鼓 / 鈴）と帯域を予約する。テストで「1 つの家に 2 つの意味が無い」「飾りの効果音が予約の家を使わない」を縛る。割り振りの初案は 柝 = 敵が確定 / 附打 = 自分の読みが当たった / 時鐘 = 死神の猶予 / 陣太鼓 = 陣の拍 / 鈴 = 放出できる
  - 設定に「柝の音」の音量を独立して置く
- なぜこのゲームで: 核の読みを目以外の感覚でも伝える。配信の視聴者も音で「来る」が分かり、読みのゲームが観戦のゲームになる。柝と附打は歌舞伎でも別の音なので「敵が確定した / 自分が読めた」の対が世界観に合う。効果音は合成なので、音色の家を表で管理しテストで守れる
- 着想元: Sekiro の危の音、歌舞伎の下座（場面ごとに楽器と意味が決まっていて、客は音で場面を聞き分ける）。一部の攻撃の特別な印ではなく、全部の攻撃の「自分に来る確定」だけに当てる時刻の合図にした
- 安っぽくならないための要点 / リスク: 「ビープ音っぽい」不満を繰り返さないよう、各家の最初の 1 音は耳で確かめてから表に載せる。命中音・受け流しの音と帯域を重ねない。L08 拍子木（死神）は時鐘へ寄せるよう統合で名寄せする
- 規模: M
- 議論で変わった点: 役割で音程を分ける案を捨て「自分に向いた赤だけ」に。判定は描画側ではなく system の `pushSfx` に置いた（批評の「描画側で判定」より不変条件 7 に沿う）。批評の新案「鳴物帳」を前段として取り込んだ。線の形は「黄赤一致」へ移した

### 顔見世
- 種別: 新要素
- 領域: encounter
- 一言: 初めて出会う敵の、最初の 3 回の攻撃だけ黄を長く・予告を太くし、足元に名を一度だけ筆で書く。どの敵にも初見殺しの一撃目を作らない
- 仕組み:
  - ランを始めるとき、図鑑にまだ載っていない敵の key の一覧を `runMeta` に入れる（リプレイに残る。空なら今と同じ）
  - その敵の個体は、その探索で最初の 3 回の攻撃だけ黄 ×1.3、線を太く。初めて画面に入ったとき、足元に名前を一度だけ筆で書く
  - 一度倒すと図鑑に載るので次の探索からは出ない。ボスは対象外。精鋭の修飾子は、組み合わせが初めてのときだけ名札を一度大きく出す
  - **土台「黄の伸び」**: 黄の時間を個体ごとに伸ばす係数を 1 か所にまとめ、出どころ（顔見世・目慣らし）を掛け合わせる。深層の下限（基準の 60%）との掛け順をここで 1 回だけ決める。同時に赤くなる上限の予測（`src/system/enemies.ts` の `telegraphCrowded`。予備動作の始まりで判定）にもこの伸びを通し、テストで「伸ばしても 0.3 秒に 3 つを超えない」を縛る
  - 今日の挑戦・デイリー・御堂では切る（同じ seed で人により難しさが変わるため）
- なぜこのゲームで: 敵 82 種・修飾子 21 種が深度 8 で出揃う。予告の図解は「3 回倒されたら開く」ので、一撃目の理不尽は救えない。プレイヤーごとの図鑑の埋まりを、決定性を保ったまま入力に使える
- 着想元: 歌舞伎の顔見世。Hollow Knight の「初見の敵は動きが分かる場所に置く」配置の工夫を、敵の側の振る舞いに移した
- 安っぽくならないための要点 / リスク: 3 回で足りるかは実プレイで決める。黄の伸びを上限の予測に通し忘れると 200 体の陣で赤が重なる
- 規模: S
- 議論で変わった点: 名を筆で書く見せ場、記録を競う場面で切る、土台「黄の伸び」と上限の予測への通し（批評の問い 5）を取り込んだ

### 留書
- 種別: 拡張
- 領域: ux
- 一言: 新しい仕組みに初めて触れたら、陣が終わった瞬間に用語の名だけを墨で書き留める。ポーズ 1 回でその Tips の項目へ飛べる
- 仕組み:
  - 初めての出来事（最初の共鳴の段・研鑽の数え・改鋳・反応・放出・芽…）を main.ts がイベント列から拾い、**交戦中は溜めておき**、陣が終わった（群勢の敗走・全滅・交戦の外へ出た）瞬間に右下へ「留 共鳴」のように名前だけを 3 秒出す。説明文は書かない
  - 1 階に 2 つまで。残りは次の階へ回す
  - ポーズを開くと「留書」の頁が先頭に来て、この探索で書き留めた用語が並ぶ。選ぶと Tips ノートのその項目が開く
  - Tips ノートでは未読の項目に墨の点。門前町の記録の蔵に Tips の台を置く（HANDOFF の積み残し）
  - 既読は meta のストアに持つ（step の外）。新しい保存キーはユーザーに確かめる
- なぜこのゲームで: 「説明は UI に書かず Tips に」を守ったまま、説明の在りかと学ぶ時機だけを指す。この視点の中で一番原則に忠実
- 着想元: Hades のコデックスの新着の印。触れた瞬間を拾う点と、ポーズから一手で飛べる点を足した
- 安っぽくならないための要点 / リスク: 通知の雨にしない（1 階 2 つ・交戦中は出さない）。「開帳」で開いていない層の用語は出さない
- 規模: M
- 議論で変わった点: 交戦中は溜めて陣の終わりにまとめて出す形にした（批評）

### 走馬灯
- 種別: 新要素
- 領域: ux
- 一言: 死亡画面で最期の 4 秒を半分の速さで見返し、致命の一撃の「黄 → 赤 → 命中」の帯と自分の入力の点を同じ時間軸に重ねる。理不尽な死に方のときだけ自動で流す
- 仕組み:
  - 写しの土台は L12 局面写しに任せる（10 秒ごとに GameState の写しを step の外で持ち、死の直前までを裏で再計算）
  - 既定では流さない。自動で流すのは次の 3 つのときだけ: 致命の一撃の主が画面外にいた / 被弾の 0.5 秒前まで、その敵の予告が画面に一度も出ていなかった / その敵に初めて倒された。それ以外は死亡画面に「見返す」を 1 つ置く
  - 見返しでは致命の敵の輪郭を光らせ予告を太く描き直し、画面下に時間軸の帯（黄・赤・命中の 3 色と、ダッシュ・受け流し・攻撃の入力の点）を敷く。「赤が明けて 0.08 秒後にダッシュした」が文字なしで見える
  - 死因の行（`meta/deathReport.ts`）の横に、その敵の図鑑の頁と状態異常の Tips への近道を置く。「この敵の型を稽古場へ掛ける」の 1 手もここに置く（稽古場の型の札は L01 / L05 型稽古の統合案へ）
  - 死の瞬間そのものの演出（今は白い粒 40 個とスロー）は L14 側の円相などと組む
- なぜこのゲームで: 決定性が初めてプレイヤーの道具になる。「理不尽だったか、自分が遅れたか」を言葉なしで示すのは「理不尽」レビューへの最良の答え
- 着想元: 格闘ゲームのリプレイ。ローグライクの死を、続きではなく見返しとして切り離した
- 安っぽくならないための要点 / リスク: 毎回流すと 3 回目から邪魔になるので条件付き。写しの重さ（敵 200 体）を `hitch:probe` で測る。地図の格子は変わる部分だけ写す。再計算の一致をテストで縛る
- 規模: M
- 議論で変わった点: 自動再生を条件付きにし、写しは L12 局面写し、「この場面を稽古」は L12 感想戦へ分けた（L → M）。L14 走馬灯と同名なので 1 案に統合する前提。時間軸の帯がこの案の独自の部分として残る

### 残照
- 種別: 改善
- 領域: platform
- 一言: パッドで右スティックを離しても照準を 0.6 秒だけ最後の向きに残し、照準の線を出す。Steam Deck の 1280x800 での見え方を先に決める
- 仕組み:
  - 右スティックを離してから 0.6 秒は最後の向きを保つ。移動を 90 度以上切り返したときだけ早めに移動方向へ戻す。後ろへ下がりながら前を撃てる
  - 照準は入力の側で決まり `aimScreen` に入るのでリプレイも同じ。敵へは寄せない（自動照準ではない）
  - パッド操作中は自分から照準の方向へ細い墨の線（得物の届く距離まで）。線はロジックが使う `screenToWorld(state.camera, …)` と同じ変換で描き、描画だけの揺れ（`main.ts` 1458 行）を足さない。見えている線と実際の向きをずらさないため
  - Deck は 1280x800 で、480x270 を横に合わせると 2.67 倍の非整数。バックバッファ 1920x1080 からの縮小で絵が滲まないかを、実機か同じ解像度の窓で先に確かめ、上下の余りの扱い（黒帯か章の様式の額か）はその後に決める
  - ジャイロの照準（L11 混成操作）と同じ設定の画面に置く。Tips の操作の項目はパッドのボタンの絵で組む（`padActionLabel`）
- なぜこのゲームで: 自動照準は禁止なので、パッドは手で狙う道具を十分に持つ必要がある。銃の家系・書・投具は引き撃ちが核。Deck での遊びやすさは返金の理由に直結する
- 着想元: Enter the Gungeon の照準の保持。保持の時間と切り返しの規則を「重い武器は止まる / 軽い武器は動ける」に合わせる前提にした
- 安っぽくならないための要点 / リスク: 保持が長いと意図しない向きに撃つ。0.6 秒は仮でパッドで決める
- 規模: M
- 議論で変わった点: 照準の線の座標変換の注意と、Deck の非整数倍の確認を額の絵より先にした（批評）

### 開帳
- 種別: 改善
- 領域: meta
- 一言: 封じるのは「メタの層の用語」で、ラン内のルール変更（見せ場）は 1 回目から出す。層は探索の回数と「手の出来事」で 1 段ずつ開き、開くたびに門前町の御開帳で見せる
- 仕組み:
  - 1 回目から出す: 祝福の札の幅（加護に限らない）。ただし札の文に未開の用語（共鳴・研鑽・真髄…。`keywords` から判定）が出る札は抽選から外す
  - 開くまで隠す: 共鳴の紋・誓約・縛り・流儀の選択・改鋳・御堂・スキル石の 2 枠目・依頼

  - 情報を運ぶ合図のうち、メタの層の物（共鳴の紋の音・放出の合図）はその層と一緒に開く。核の合図（黄赤一致・柝・被弾筋）は 1 回目から出す

### 目付
- 種別: 基盤
- 領域: presentation
- 一言: 「画面で一番目立つのは予告と自分」の序列を決まりにし、配信の圧縮・Steam Deck・ストアの縮小画像の 3 つの見る条件で、予告が読めるかを撮影の場面でテストする

  - 測り（批評の新案「遠目」を取り込む）: `pnpm run map:shot` に「予告の場面」（黄・赤の予告・敵の弾・自分を、章の様式 5 × 暗がり × 深みの変異の上に並べる固定の場面）を足し、撮った画像を 3 条件に通す
    1. 配信: 1280x720 へ縮小し、色差を 2x2 で平均（4:2:0）
    2. Deck: 1280x800 の倍率
    3. ストアの縮小画像: 460x215 程度
  - 通した後で、予告の画素と周りの床の**明るさの差**が下限を割らないか、黄と赤が明るさでも区別できるかを数で測る。`check` には入れず、絵を変えたときに回す
  - 色覚の 3 案（標準 / 赤と緑を避ける / 青と黄を避ける）と閃光を抑える切り替えは、形と音（黄赤一致・柝）が入った後の段にする
- なぜこのゲームで: 敵 200 体・地形の層 10・光と暗がり・密度 2 の絵と、情報が増えるほど予告が埋もれる。敵の絵の描き直しの前に決まりを置けば、描き直しの基準になる。決定的な場面を何度でも同じに撮れる `map:shot` があるので、見え方を「テスト」にできる
- 着想元: 剣道の目付、Hades の「敵の攻撃だけが赤」の徹底。映像の色の監修が劇場とスマホの両方で確かめる習慣を、インディーのアクションの売れ方を決める「配信の圧縮」へ向けた
- 安っぽくならないための要点 / リスク: 縛るのは予告と弾の色だけにし、絵の自由を縛りすぎない。下限の数は最初に人の目で決める（配信の画面を録って見る）。テストが通るのは必要条件で十分条件ではない。色覚の案は当事者の確認が要る
- 規模: M
- 議論で変わった点: 批評の新案「遠目」を測りとして取り込み、色相ではなく明るさの差を測る形にした。淡墨 → 濃墨の変わり目を合図にした。色覚は形と音の後へ下げた。L14 警色専有と統合する前提

### 絵解き
- 種別: 新要素
- 領域: ux
- 一言: 「手の形が変わる」札（改鋳・刻印符・左 / 右 / ダッシュの形を変える祝福）に限り、焦点の札を本物の step で 2 秒動かして見せる

- なぜこのゲームで: ルール変更の札は数値の比較で選べない。拠点の「決める前に手で確かめる」文化（武器小屋の試し打ち・社の誓約の試用）をラン内の 3 択へ延ばせるのは、決定的な step を持つこのゲームだから。札を足しても見本が自動で増える。題簽の帯で言って、小窓で見せる 2 段になる
- 着想元: Street Fighter 6 の技表の動画見本、Noita の杖の試し撃ち。作り置きの動画ではなく本体の step でその場で再生する
- 安っぽくならないための要点 / リスク: 小窓用の描き方が本番の絵とずれると嘘を教える。対象を絞り、静止の図で済む札は無理に動かさない
- 規模: L
- 議論で変わった点: 対象を手の形が変わる札に絞り、本番の renderer の流用をやめて小窓用の描き方を別に持つ形にした（批評）

## 捨てた案と理由

| 案 | 扱い | 理由 |
| --- | --- | --- |
| 型稽古 | 他レーンへ統合 | 同名が 3 案（L01・L05・L09）ある。効くのは 2〜10 時間の層で、最初の 1 時間には効かない。この視点からは「走馬灯から稽古場へ型を掛ける」入口だけを残し、木人の型の札そのものは L01 / L05 の統合案に任せる |
| 検分 | 縮めて他レーンへ | リアルタイムのゲームでポーズして盤面を読む人は少なく、配信者はほぼしない。陣の縁取りと大将の印は常に役立つミニマップ（今は陣を描いていない）へ移すのが筋で、遭遇の視点（L02）に渡す。L08 検分と名前も衝突する |
| 気色（型 15 の得物の細部） | 濃淡へ縮めて統合 | 背 23px・得物 10px 前後では「鎖の環が灯る」は 480x270 で読めず、配信では確実に消える。全型共通の放出の合図だけを濃淡へ移した |
| 傍点（独立案） | 題簽へ統合 | 札の画面で「何が変わるか」と「用語の在りか」は同じ場面の問題。パッドで語に止める操作は重いので左手のキー 1 つにした |
| 柝の役割別の音程 3 段 | 捨てた | 前衛 / 射手 / 爆発の音程を聞き分けて得をする場面が無く、覚える物が増えるだけ。「自分に向いた赤だけ鳴らす」の方が判断に効く |
| 開帳の「1 回目は加護だけ」 | 捨てた | 祝福の 3 択はこのゲームで一番ルールが変わる見せ場。封じるべきは用語で、見せ場ではない |
| 目慣らしの「慣れたら外す」 | 捨てた | プレイヤーの知らない所で難しくなるのは、補助の信頼を壊す |
| 走馬灯の「この場面を稽古」 | L12 感想戦へ | 見返しと遊び直しは別の題。分ければ走馬灯は M で済む |
| 墨跡の画面外の刻み | L01 殺気へ | 同じ物が L01 にある |
| 遠目（独立案） | 目付へ統合 | 見え方の決まりと、それを守らせる測りは 1 組でないと決まりが空文になる |
| 鳴物帳（独立案） | 柝の前段へ統合 | 最初に表へ載る音は柝と附打なので、柝と同じ作業で始めるのが速い |
| 16:10 の額の絵を先に作る | 後回し | 非整数倍の縮小で絵が滲むかを先に決めないと、額の寸法が決まらない |
