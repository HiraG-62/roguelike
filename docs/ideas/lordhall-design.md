# ボス階の専用の部屋（階の型 "lordHall"）の設計

作成日: 2026-10-01（未実装）。ユーザーの決定「ボス階（章ボス 5 / 10 / 15 / 20・最深の間 21・深みの 25〜）は、部屋 + 通路ではなく専用の部屋にする」を受けた設計。前提は `docs/ideas/map-gen-impl.md`（型 8 種・穴 `Tile.Pit`・L0a〜L7）と `docs/ideas/boss-impl.md`。

## 1. 結論

- ボス階は **入口の間 → 参道 → 前室（市の商人）→ 門の通路 → 主の間** の 1 本道で、部屋は 3 つ（`rooms = [入口, 前室, 主の間]`）。道中の戦闘（陣・長蛇・物見）は置かない。階段は今と同じで、撃破すると主の間の中央に出る
- 主の間は **手描きの文字の格子（TS の定数）を乱数なしで並べる**。章ボス 4 体はそれぞれ専用の形にし、最深の主と深みの回転の 5 体は共通の矩形を使う。**boss 側のコードは 1 行も変えない**。そのために「主の間の `rect` = 床の外接矩形（奇数 × 奇数）、中心 = 主の立つ所、四隅・1/4 点・中心 ± 4 の意味」という今の契約を、格子のほうで守る
- 生成で乱数を引かない（`chooseLayout` も引かない）。ただし旧生成器と陣の乱数の消費が無くなるので、`REPLAY_VERSION` は L5 と同じ版で 1 回上げる。実装は L8a（map 層・すぐ並行で始められる）と L8b（結線・L5 の取り込み後）の 2 レーン

## 3. 階の構成

```
[入口の間 7x7] ─参道 3─ [前室 15x9] ─門の通路 5─ [主の間 21x15（鏡の騎士は 21x19）]
```

- **入口の間**（部屋 0、`START_ROOM`）: 降りてきた位置。何も置かない
- **前室**（部屋 1。`FIRST_FIGHT_ROOM` の予約で normal のまま、敵なし）: 市の商人（章ボス階は `chapterMarket`、深度 21 と深みは `market`）。`frontRoomOrder` が自然に前室を選ぶ。台座 6 個 + 商人が置ける 15x9。敵がいないので `clearEmptyOpenRooms` が制圧済みにする。泉は置かない
- **主の間**（部屋 2 = 最後）: 入ると封鎖（既存）。撃破すると中央に階段、±4 に分岐の階段（既存）。深度 21 は中央の右 2 マスに地上への道（既存）
- **地図の大きさ**: 幅 = 余白 2 + 7 + 3 + 15 + 5 + 21 + 余白 2 = 55、高さ = 主の間の行数 + 余白 2 × 2（19 / 23）
- **並べ方**: 3 つの中段を同じ行に揃えて横に並べる。通路は幅 3 で `,`（どの部屋にも属さない床）

## 4. 主の間の形

文字: `#` 壁 / `.` 床（その部屋の所属）/ `@` 床（主の立つ所。1 つ）/ `,` 床（通路・桟道。どの部屋にも属さない）/ `_` 穴 `Tile.Pit` / `o` 柱（`Tile.Wall`。描画で柱の絵を出す余地として壁と分けて書く）/ `~` 床 + 浅い水（`shallow`。今回は使わず読み取りだけ用意し、「深みの主」の段で使う）。

下の格子は設計時にスクリプトで確かめた: 中心が `@`・中心 ±4 が床・主の体（2x2 の窓）で床に届く・スライム王の膨張が窪みの外の床すべてに届き窪みに安全な床が 5 マスずつ残る。

### 4-1. スライム王「苔の釜」（章 1、key `alcoves`）

四角い広間で、上下の壁と左右の壁から短い牙が出て四隅の窪みを縁取る。膨張（段階 3）は「隅の窪みの奥へ逃げる」が一目で分かる。跳躍・呑み込みは床が素直なので影と毒沼が読みやすい。窪みの奥には王の体が入らないが、着地の衝撃波（`shockRadius` 60px）は届くので籠もり続けられない。

### 4-5. 最深の間と深みの器（key `plain`）

21x15 の全面が床の矩形（中央に `@`）。門柱・陥没・`safeBounds`・骸骨卿・群れの母が矩形を前提にしているので、形で個性を出さず見た目（墨と朱・章 4 の変異）を描画の段で変える。陥没は 2 段（`ringTiles` 2）で 13x7 が残る。深みの回転の 5 体は、作り直しの段（「深みの主」）で `LORD_HALL_OF` に 1 行ずつ専用の間を足せば差し替わる。

## 5. 生成の方法とデータの置き場

**固定の手描きの格子を乱数なしで並べる。** ボスの技は部屋の形に結び付いているので、形が毎回同じだと「読み」を覚えられる。拠点のボスの間でも本番と同じ部屋で練習でき、テストでは全部の間を列挙して検査できる。却下: seed で揺らす案（読みを崩すだけ）、パラメータで組む案（個性が出にくく検査が組み合わせ爆発）。

- `src/map/layout/lordHallGrids.ts`: `LORD_HALL_GRIDS: Readonly<Record<LordHallKey, readonly string[]>>`、`LORD_ENTRY_GRID`（7x7）、`LORD_ANTE_GRID`（15x9）
- `src/map/layout/lordHall.ts`:

```ts
export type LordHallKey = "alcoves" | "pits" | "pillars" | "island" | "plain";
export const LORD_HALL_OF: Readonly<Record<string, LordHallKey>>;
export function lordHallKeyOf(bossKey: string): LordHallKey; // 表に無ければ "plain"
/** ボス階の地図。乱数を引かない。rooms = [入口, 前室, 主の間]、全部屋が roomTiles を持つ、layout = "lordHall"、階段はまだ置かない */
export function generateLordHallMap(bossKey: string): GameMap;
```

- `src/data/balance/world/LORD_HALL.json`（`_fields` 付き）: `margin 2`（外周の壁の厚さ）・`entryLength 3`（参道の長さ）・`gateLength 5`（門の通路の長さ。3 以上で前室の扉と主の間の扉を別タイルに）・`corridorWidth 3`（通路の幅、奇数）。ロジックは `data/tuning.ts` の re-export 経由で読む

## 8. ユーザーに聞くこと

1. **ボス階の道中の戦闘を無くしてよいか**（入口 → 前室 → 主の間で 1 分以内に主に着く）。推奨: 無くす。銭と遺物は前の 4 階で集め、章の山場を短く濃くする（今のボス階の陣の分の銭と経験が減る）
2. **前室に回復を置くか**。推奨: 置かない。章の市の瓶 2 本と降りたときの 35% 回復で備える。実プレイで厳しければ「呪いなしの泉（生命 50%）」を前室に足す

## 9. 不確かな点

- 穴の縁で止まった突進が激突（`hitX / hitY`）として立つか: L0b の取り込み後に確かめる。立たなければ浮島での「盾割れ」が減る（壊れはしない）
- 封鎖前の狙撃: 門の通路が中央の主へまっすぐ向くので、通路から寝ている主を撃てる。L8b のテストで、封鎖前に与えたダメージで主が起きる / 封鎖されるかを 1 件確かめる（`roomNoticed`）
- 前室の台座の置き場: `stockPlan("chapterMarket")` + 特典を全部付けた状態で `findStall` が null にならないかを L8b で見る
- 盗賊王の穴と bot: L7 の `crossesPit` より先に L8b が入ると QA の盗賊王の秒が伸びる。比べるのは L7 の後
