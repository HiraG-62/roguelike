## 0. この文書で使う新語

| 表記 | 意味 |
| --- | --- |
| 連動体 | 召喚スキルが出す味方の物体。**自分では攻撃しない**。プレイヤーの近接・射撃・ダッシュに合わせてだけ動く（ヴァンサバ禁止の担保） |
| 変身 | 一定秒のあいだ左右クリックの動作そのものを差し替える強化スキル。終了時に反動がある |
| 消費 | 敵の状態異常を取り除き、その量や種類を効果に変えること |
| 型替え符 | 発動の「型」（近接 / 射撃 / 設置 …）を変える上位の刻印符。リンクを 2 本使い、1 スロットに 1 枚まで |
| 連携 | スキル A の直後（時間）または A の設置物の上（空間）で B を撃つと、B が変化すること |
| 使い込み | スキル石の来歴。装備の来歴と同じく節目で芽（2 択）が出る |
| 相乗タグ | スキル・刻印符・装備の性質・祝福・状態異常に共通の、シナジーを語る語彙（6 章）。内部名は `SynergyTag` |
| 出す / 食う | ある要素が場や自分に相乗タグの状況を作ること / その状況があると効果が変わる・強まること。例: 雷撃は感電を出し、放電は感電を食う |

## 2. 刻印符 35 種

条件は `canAttach` の `excludesTags` / `requiresTags` / `excludesSkills` で書く。新しい条件の型は 2 つ必要。
- 要追加: `ModifierDef.requiresResource?: SkillResource`（マナ型だけ・CD 型だけ）
- 要追加: `ModifierDef.requiresApplies?: boolean`（`SkillDef.applies` を持つスキルだけ）
- 排他の組（例: 至近と遠当て）は要追加: `ModifierDef.excludesModifiers?: ModifierKey[]`。後から刺した方で古い方を押し出す

## 5. スキル石の使い込み（来歴と芽）

原則: スキル石は動詞でレベルを持たない。だから使い込みの結果は **数値の伸び** ではなく **形の分岐**（変容）にする。装備の来歴（`src/loot/provenance.ts`）と同じ「積み重ね → 節目 → 2 択 → 余白を使い切ると銘」の流れを流用する。

| # | 案 | 中身 | なぜ面白いか | コスト | 面白さ | 触るファイル |
| --- | --- | --- | --- | --- | --- | --- |
| P1 | 石の来歴 | 石ごとに数える: 発動数 / この石での撃破 / 1 発で同時に当てた最多数 / 付与した状態異常 / 成立させた連携 / マナ 20% 未満で撃った回数 / 溜め最大で撃った回数。要追加: `SkillStone.provenance` | 同じ石でも使い方の記録が残る | M | ★4 | `src/skills/types.ts`、`src/skills/persistence.ts`（欠けた欄は既定値で埋めるのでキーは v1 のまま） |

## 6. 相乗タグ（シナジーの共通語彙）

いまはスキル（`SkillTag`）、祝福（`BoonTag`）、装備の性質（`AffixDef.tags`）がそれぞれ別の語彙を持ち、「何が何を強くするか」を横断して語れない。そこで全要素に共通の **相乗タグ** を 1 つ置き、各要素が何を **出す** か・何を **食う** かを宣言する。数値を盛るための軸ではなく、組み合わせを見つけるための語彙にする。

## 最初に入れるべき 12 個

1. **伝染（#37）**: `applyStatus` で敵の状態異常を写すだけで、新しい型が要らない。既存の雷撃・鎖鎌・氷結地帯の付与が一気に群れ向けに化ける。
2. **綻び（#36）**: `StatusBag.effects` の種類数を数えて消すだけ。多色の状態異常ビルドに初めて明確な出口ができる。
3. **燃え種爆ぜ（#29）**: 燃焼の残量を読んで既存の爆発処理で撒ける。装備の燃焼性質と掛け算になる。
4. **五彩の礫（#40）**: `spawnBullet` の弾に `PlayerStats.resonance` の色で付与を切り替えるだけ。共鳴とスキルの初めての接点になる。
5. **満月の砲（#22）**: `fireBeam` をそのまま使い、コストを全量にするだけ。マナ満タンの価値を作る。
