# マップの一新（見た目と生成）

作成日: 2026-09-30
前提: `docs/DESIGN_PRINCIPLES.md`、`docs/ideas/graphics-design.md`・`graphics-style.md`・`core-synthesis.md`（4 章 陣）・`encounter-core.md`（1-4・6 章・10-3）・`run-arc.md`（1 章 章の構成）、`IDEAS.md` の「現状」、`src/map/{grid,generator,cave}.ts`、`src/data/tiles.ts`、`src/render/{renderer,renderMath,terrainUi,darkness,layers}.ts`、`src/data/sprites/dots.ts`、`src/data/balance/world/{CAVE,MAP_SIZE}.json` を読んだ。
今の実装の要点: 当たりも絵も 16px のマス（`TILE_SIZE`）。床・壁は Puny の 16px 素材（密度 1 = 1 ドットが画面 4px）を色だけ染めて 9 バイオームに使い回し、壁は 4 ビットの隣接（16 通り）、周囲が全部壁の岩盤は描かない（黒）。キャラは密度 2（1 ドット = 画面 2px）へ描き直しが進んでいる。生成は洞窟（セルオートマトン → 開けた所を塊として部屋にする）が既定、部屋 + L 字通路は一部。地形は床の 1〜3% に四角い塊で置かれ、半透明の単色か水面の素材で描く。マスを細かくする方式の技術比較は別の Agent が担当しているので、この文書は遊びと見た目に重心を置き、実現性はざっくり見積もる。
凡例: コスト S = 数時間 / M = 1〜2 日 / L = 数日以上。面白さ ★1〜5

見本ページ: `docs/ideas/previews/map-preview.html`（単体の HTML。ブラウザで開くと案を切り替えて見比べられる。公開版 https://claude.ai/artifact/8EegHYo5XTnbfeFsty9W9S）

## 0. 結論

- ブロック感の元は 4 つある。床と壁のドットがキャラの倍粗いこと（密度 1 と 2）、角が直角で洞窟の縁が 16px の階段になること、岩盤が真っ黒なこと、地形が四角い半透明のタイルなこと。マスの大きさそのものではない。**当たりの格子（16px）は変えず**、絵を密度 2 にして角を半マス（8px）で描けば、ロジックとリプレイを壊さずに見た目が一番大きく変わる
- 壁は天面・側面・縁の 3 面で描き、手前の縁がキャラにかぶるようにする（Enter the Gungeon / Nuclear Throne）。光のマップを全バイオームに敷き、光源と闇で奥行きを出す。**予告と弾は光の影響を受けない層に描いて読みやすさを守る**
- 章ごとに建築の様式を変える。苔の洞 → 地下寺院と坑道 → 霜と火の廃城 → 深みの異界 → 墨と朱の最深の間。バイオームは章の中の変奏にする
- 生成は次の 4 段で作り直す。骨組み（主の道・ループ・寄り道）→ 形の語彙（円・瓢箪・扇…）→ 断片（手で描いた型）→ 縁の崩し（今のセルオートマトン）。塊の形を測って陣形を選び、目印と導き灯で「迷う」を「選ぶ」に変える
- 技術の比較（E 章）も同じ結論: 論理 16px のまま描画だけ dual-grid + 密度 2 + チャンク焼き付け（方式 C）。当たりまで 8px にする案は決定性・QA・balance の全面やり直しで見返りが小さい
- 段取りは 見本 1 画面 → 見た目の土台（生成は不変）→ 光と置物 → 章のテーマ → 生成の形 → 断片と地形 → 読む楽しさ。前の 4 段は描画だけで済むので、リプレイの版を上げずに進められる

## 現状の診断（見た目と生成）

- **粒の不一致**: 床・壁は密度 1（`tiles.ts` の `TileSpriteDef.dots` 省略 = 1）、キャラは密度 2（`graphics-style.md` 1 章）。床の 1 ドットはキャラの 1 ドットの 4 倍の面積になる。同じ画面に 2 つの解像度が混ざっている
- **角が直角**: `punyWallCell` は 4 ビット（隣接 4 方向）なので内角が表せない。セルオートマトンの縁が 16px の階段のまま見える
- **壁に厚みが無い**: `wallStyle` は face / top / none の 3 値で、1 マスの中で完結している。周囲が全部壁なら描かない（`none`）ので、床が黒い穴の中に浮いて見える
- **バイオームが同じ石**: 9 バイオームは同じ Puny の石を LUT と色の重ね塗りで染めたもの（`BIOME_TILESET`）。形・模様・置物で違いが出ていない
- **地形が四角い**: `terrainUi.ts` はマスごとに単色 + 点 2〜4 個、または水面の素材を半透明で塗る。塊の縁がマスの形のまま
- **光が暗闇の階だけ**: `darkness.ts` は dark の階のマスク。ほかの階は全面が同じ明るさ
- **生成に意図が無い**: 洞窟は「開けた所を塊として拾う」、部屋型は「ばらまいて近い所と繋ぐ」。主の道・ループ・寄り道の区別が無い。面積は 3.5〜5 倍（`MAP_SIZE.json`）と広く、歩くだけの時間が長い（encounter-core 1-4: 最短の道の近くの敵は 9%）
- **戦闘に効く形が無い**: タイルは 4 種で、遮蔽・段差・壊せる物は通常の階に 0（encounter-core 1-4。溝・柵・柱・型紙 8・設置物は 6 章で提案済み・未実装）

## E. 技術の比較（architect の現状分析。2026-09-30）

A〜D と同じ結論に独立に着いた: **当たり・経路・生成は 16px のまま、描画だけを「dual-grid の自動タイル（頂点を囲む 4 マスで 16 通り）+ 密度 2 の地形の絵 + チャンク単位の焼き付け」にする**（方式 C）。dual-grid は表示の格子を論理の格子から半マスずらし、縁の絵が論理マスの境界の上に来るので、当たりとのずれは角の丸めの数 px に留まる。A-1 の「半マスの角」はこの方式で実現する。

### E-1. 数字で見た現状

- 画面は 30x16.9 マス、通常階は 182〜214 x 106〜125 マス。1 画面に映るのは面積の約 2.3%
- タイルの種類は 4（Wall / Floor / StairsDown / Fountain。`src/map/grid.ts:2-8`）。9 バイオームの床・壁は全部同じ Puny の石の色変換（`src/data/tiles.ts:188-199`）。章・深みで描画の分岐は無い（深みは HUD の文字だけ）
- 同じ seed の回廊と油の坑道は **完全に同じ地図**（`src/system/biomes.ts:101-111`。同じ生成器・同じ乱数の消費）
- 洞窟の階: 床 56〜76%、扉のタイル 627〜1,526 / 階、1 マスの出っ張り 69〜126 本、1 画面あたりの角 59〜74。回廊の階: 地図の 76〜78% が空白、通路は常に幅 2、木構造でループは偶然だけ
- 暗闇のマスクは 480x270（`src/render/darkness.ts:52-54`）なので縁が 4 画面 px の段になる。封鎖の扉はマスごとの柵で、洞窟では柵の階段になる
- ボス階は 96x56 の回廊で固定（章ボス 4 体とも同じ形の部屋）

### E-2. マスを細かくする方式の比較

世界の px（速度・半径・距離）は変えない前提。

| 方式 | 変わる範囲 | コスト | 危険 | 見た目 |
| --- | --- | --- | --- | --- |
| A. `TILE_SIZE` 16 → 8（論理も描画も） | `TILE_SIZE` を含む 46 ファイル 271 行、タイル添字 122 行、マス単位の balance 29 項目、テスト 35 + 地図依存 116 ファイル、拠点の ASCII | 大 | 高（リプレイの版・golden・QA の基準値の全面やり直し。延焼の広がりが半分、洞窟の穴や柱も半分の大きさになる） | 当たりも 8px の階段。実際は「16 で生成して 2 倍に拡大・角を削る」になり C とほぼ同じ |
| B. 16 → 4 | A と同じ | 特大 | 性能が成立しない（距離場 1 回 5〜7.5ms、1 step あたり約 3ms。今の step 全体は 0.45ms 前後） | 当たりまで滑らか |
| **C. 論理 16 + dual-grid + 密度 2 + チャンク焼き付け（推奨）** | render と `data/tiles.ts` と新しい絵だけ。state・乱数・リプレイ・QA は不変 | 中（本体は絵） | 低 | 縁の形を絵が決めるので階段が消える。曲線・岩肌・壁の高さ・影・地形の縁。キャラと同じ密度 |
| D. 論理 16 + 描画用の形を marching squares で手続き生成 | C と同じ | 中 | 中（角を削ると見えない壁、足すと当たりの無い壁の絵） | 滑らかだが質感は絵に劣る |

**C の描画コスト**: 床・影・壁の天面・手前の面・置物の 5 層を毎フレーム描くと約 3,000 回の `drawImage` になるので、32x32 マスのチャンクを密度 2 で 1 回だけ焼き（1024² で約 4MB、LRU 6〜9 枚）、画面には 2x2 枚だけ描く。焼き直しは描画側でチャンク内のタイルの簡易ハッシュを比べて判定する（state に手を入れない）。延焼などで変わる地形の層と封鎖の扉は焼かずに毎フレーム描く。

**C の実装の粒度**（implementer に渡す）:
- 新規 `src/render/dualGrid.ts`（純関数: `cornerMask(map, vx, vy, isSolid)` NW=1 / NE=2 / SW=4 / SE=8、`terrainCornerMask`。変種は `tileHash`、rng は使わない）
- 新規 `src/render/tileBake.ts`（`ChunkCache`、`chunkChecksum`、焼く順: 床 → 床への影 → 壁の天面 → 手前の面 → 置物）
- 最小の Edit: `renderer.ts` の `drawTiles`（新しい組があるバイオームだけ焼いたチャンクを描く分岐。今の経路は代替として残す）、`terrainUi.ts`（縁付き）、`data/tiles.ts`（`DualTileSet` の型とバイオーム → 組の表）、`darkness.ts`（マスクを `RENDER_SCALE` 倍に）、封鎖の扉を 1 本の帯（結界）として描く
- テスト: 16 通りの網羅・マップ外は壁扱い・対称、チェックサムの変化、全バイオームの組が 16 通りそろい密度 2、置物の散らしが座標だけで決まる
- 絵: 1 マス 32x32 ドット（密度 2）× 16 通り × 変種。今の Puny・Kenney は 16px・密度 1・4 近傍向けで流用できないので、自作（pixel-artist と `pnpm run sprite`）か手続き生成

### E-3. 生成を変える前の準備

`arena()`（`src/system/testHelpers.ts:26-35`）は深度 1 の生成地図を使うので、生成を変えるたびに無関係な戦闘テスト（`arena` を使うファイル 116）が落ちる。**先に `arena()` を固定の開けた地図（`hubMap.ts` のような ASCII）へ切り替える**。この切り替えも一度だけ基準がずれるので単独のコミットにする。

### E-4. 撮った画面

`pnpm run dev` の代わりに、`createGame(..., { startDepth })` と `buildFloor(state, kind)` を直接呼ぶ専用ページで 12 枚（拠点・深度 1 の洞窟・回廊・坑道・墓所・沼・氷窟・熔鉱炉・暗闇・草原・ボス階・深み）と全体図を撮った。画像はセッションの scratchpad にあり、リポジトリには入れていない。必要になったら同じ手順で撮り直す（D0 の見本と並べて比べる）。

## 今すぐ入れるべき 5 つ

1. **地図の密度 2（A1）**: ブロック感の最大の元を断てる。`TileSpriteDef.dots` と密度の仕組み（`src/data/sprites/dots.ts`、`imageAtlas.ts`）は既にあるので、描画の枠を変えずに絵だけ差し替えられる
2. **半マスの角と、地形のずらし格子（A2・A3）**: 洞窟の階段状の縁と四角い水たまりが消える。`wallMask`（`renderMath.ts`）を 8 近傍に広げ、地形の描き方を変えるだけなので、生成にもリプレイにも触れない
3. **壁の天面・側面・縁と根元の影（A7・A9・A10）**: 今の `wallStyle` の face / top / none を、3 面と闇の帯に広げる。部屋が「掘られた穴」になり、章の色が画面全体に乗る
4. **光のマップ（A18・A19）**: `darkness.ts` のマスク合成を、全バイオームの弱い暗がり + 光源に広げる。予告と弾は光を無視する層に置き、原則 3 を守る
5. **形の語彙で塊を作る（B5・B6）**: 円・瓢箪・扇などの距離場で塊を作り、今のセルオートマトンは縁の崩しに回す。出力は今の `roomTiles` の形のままなので、陣の配置（`jinSpawn.ts`）はそのまま使える。塊の分類で陣形の重みも変えられる

## やらないこと

- 論理解像度を 960x540 に上げる（UI 座標と `pixelText` が壊れる。`graphics-design.md` 3 章で却下済み）
- カメラのズーム（ピクセルの大きさが揺れ、ピクセル感が崩れる）
- 縁のアンチエイリアスやディザで滑らかにする（ピクセル感を失う。様式書でディザ禁止）
- 視線の外の敵を隠す（テレグラフの原則に反する。C3 は床を暗くするだけ）
