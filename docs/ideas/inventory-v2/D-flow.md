# 持ち物メニューの作り直し D: 紋（強さの流れを主役にする）

作成日: 2026-10-01
前提: `IDEAS.md` 現状・`docs/LOOT_DESIGN.md`（源と糧の共鳴・地金・芽・残響）・`docs/ideas/core-synthesis.md` 3-11（加護は 1 行動 2 枠）・`src/core/keywords.ts`（流れ〔keyword〕48）・`src/system/resonance.ts`（`countProfiles` / `resonanceSteps` は純関数）・前の案 `inventory-overhaul-ideas.md` の 0 章。今の画面も前の案（旅装）も「部位・頁で分けた一覧 + 1 品の詳細欄」が骨で、その骨ごと捨てる。
表記: 本文の「流れ」（keyword）は、表示では **系統**（個別は「燃焼系」のような **〜系**）と呼ぶ（2026-10-01 決定。`docs/GLOSSARY.md`）。この資料は決定前に書いたので「流れ」のまま残す。読むときは「燃焼の流れ」→「燃焼系」、「流れの源 / 糧」→「系統の源 / 糧」と読み替える。

---

## 1. 思想

**持ち物を並べない。自分の強さの「形」を 1 枚の紋として描き、持ち物はその紋の上の珠として、問いを立てたときだけ寄ってくる。**

- ごちゃつきの正体は「持っている物を全部並べ、選んだ 1 品の全部の性質を詳細欄に並べる」こと。どちらも *持ち物が主語* だから量が持ち物の数に比例して膨らむ
- 紋の主語は **流れ（keyword）**。ビルドで太い流れは多くても 3〜4 本しかなく、量が持ち物の数に比例しない。400 個持っても紋は 6 本の帯のまま
- 品の文章は「いま開いている流れに触れる性質の行」だけを出す（`AffixDef.keywords` で絞る）。燃焼の流れを見ているときに会心や生命の行は出ない。だから 1 品の説明が 20 行から 1〜2 行になる
- 遺物の地金は今の深度で決め直されるので、遺物ごとの差はほぼ性質 = 流れに宿る。紋は「差が出るところだけ」を描いている

## 2. 情報の予算（破ったら設計の誤り）

| 項目 | 上限 | 超えたらどこへ |
| --- | --- | --- |
| 文字の行 | 常時 **3 行**（見出し 1・焦点 1・操作案内 1）。焦点を広げて +2（計 5） | 1 品の全文は **書付**（詳しくキーで開く 1 品だけの頁）。仕組みの説明は Tips |
| 流れの帯 | 段の立った流れ **4 本** + 伏流 **2 本** | 5 本目以降は「流れを選ぶ」の盤（48 の丸印だけの格子） |

| 候補 | **5** 枚 | 送り（↑↓ / ホイール）で次の 5 枚。件数「3/11」は見出しに |

| 色 | 流れの色 4 + 墨 + 焦点の白金 | 5 色の分類（紅蒼翠金冥）は書付の中だけ |
| 下の台 | 身 6・加護の帯 5 区画・系譜 4 | 系譜 5 本目以降は「＋n」 |

| 用語 | 意味 |
| --- | --- |
| 紋 | 持ち物メニューの家。段の立った流れと伏流を帯で描き、出どころを珠で付けた 1 枚の図 |

| 書付 | 1 品（遺物・スキル石・祝福）の全文の頁。性質・地金・来歴・計算式。開くのは詳しくキーだけ |

## 3. 図の文法（全場面で同じ）

- **帯 = 流れ**。左から右へ流れる。左岸に **源**（出す出どころ）、右岸に **糧**（食う出どころ）、帯の上に **強め**。帯の太さ = 段（2 / 4 / 6px）、流れの速さ = 段（描画だけ。`renderMath.ts` の座標ハッシュと時刻で揺らし、`state.rng` は使わない）。伏流は点線
- **丸印 = 流れ**（`KEYWORD_DEFS.glyph` と色）、**角枠 = 行動**（左 / 右 / ダッシュ / スキル / 奥義）。ダッシュの流れと行動のダッシュは形で分ける
- **珠 = 出どころ**。遺物は部位の印、スキル石は菱形、祝福は系譜の色の小札、流儀・型・改鋳・誓約は二重丸。名前は珠に焦点が来たときだけ出る
- **問いは 2 つの入口だけ**: 「流れを選ぶ」（何が起きているか）と「行動を選ぶ」（何を押しているか）。選ぶとその問いに関わる珠だけが寄り、他は墨に沈む
- **比べる = 紋が動く**。候補に焦点を当てると帯が太る（▲・光る）/ 細る（▼・ひび）/ 伏流が立つ / 帯が消える。単一の強さの数は出さない

## 6. 捨てるもの・諦めるもの

| 捨てる | 失うもの | それでも成り立つ理由 |
| --- | --- | --- |
| 倉庫の一覧と並べ替え 8 軸 | 400 個を眺め、名前や揺らぎで並べて探す遊び | 入口は流れ・部位・新着の 3 つに限る。どれも候補は 5 枚ずつ。眺める遊びは図鑑と書付に任せる |
| 常設の詳細欄 | 1 品の全部の性質を一目で読むこと | 開いた流れに触れる行だけを出し、全文は書付（1 キー）へ。読む量を自分で選ぶ |
| 数値の横並び比較 | 「防御力 +12 → +18」を並べて見ること | 地金は今の深度で決め直すので遺物ごとの差は小さい。差は ▲▼ 2 つまで、数字は書付の見開きで |
| 流れに関わらない強さ | 地金・ステータス・防御は紋に描かれない | 中央（見出しの流儀・型）を決定すると体の頁（5 ステータスと出どころ・計算式）が書付の形で開く。紋は「伸ばす方向」を描く物と割り切る |
| 拠点で祝福込みの姿 | 拠点の紋は祝福が無いぶん帯が細く伏流が多い | 拠点の紋は「土台」で、伏流が多いこと自体が「ラン中に祝福で立てる流れ」の地図になる（Tips で説明） |
| 流れ 48 の常時表示 | 6 本以外は開かないと見えない | 段の立つ流れはビルドで 3〜4 本。新しい方向は「流れを選ぶ」の盤（丸印だけの 8×6）から引く |
| 慣れた操作 | 部位 → 一覧 → 品、という順の引き方 | 身の部位印を決定すれば部位から引ける（候補の形は同じ）。問いの入口が増えるだけで、部位の引き方は消えない |

設計上の危険: 紋の帯は `boonRun.resonance` と出どころの写しから作るので、出どころごとの内訳が要る。要追加: `system/resonance.ts` に出どころ付きの数え（今の `resonanceSources` は匿名の profile を返す）。試着は `countProfiles` + `resonanceSteps` に仮の出どころ列を渡す純関数で、state を変えない（決定性に触れない）。

## 7. 前の案（旅装）との決定的な違い

1. **主語が違う**: 旅装は「持ち物を 1 枚に畳んだ一覧」（部位・行動・ステータス・共鳴の帯を全部並べる）。紋は「流れの図」で、持ち物は問いに答える珠としてだけ現れる。画面の量が持ち物の数に比例しない
2. **頁と詳細欄が無い**: 旅装は 4 頁 + 252px の詳細欄。紋は 1 枚の図を 紋 → 流れ → 書付 と潜るだけで、品の文章は開いた流れに触れる行だけ（1〜2 行）に絞る
3. **比べ方と倉庫の引き方が逆**: 旅装は倉庫の一覧を巡って試着し、差を文章の「入れ替えると」で読む。紋は流れの欠け（「＋」）から倉庫の候補 5 枚を引き寄せ、差は帯が太る・ひびが入るで見る
