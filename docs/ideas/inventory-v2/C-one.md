# 持ち物メニューの作り直し C 案: 見台（けんだい）— 一つずつ見る

作成日: 2026-10-01
前提: `IDEAS.md` の「現状」、`docs/LOOT_DESIGN.md`、`docs/ideas/core-synthesis.md`、前の案 `docs/ideas/inventory-overhaul-ideas.md` の 0 章（原因 6 つ）、`docs/DESIGN_PRINCIPLES.md`、`CLAUDE.md` 不変条件 5・11・12。今の画面は 5 タブ × 「左に一覧・右に 164px の詳細欄」、前の案は旅装（全体 1 枚）+ 3 頁。どちらも「並べて全部見せる」発想。
表記: 本文の「流れ」（keyword）は、表示では **系統**（個別は「燃焼系」のような **〜系**）と呼ぶ（2026-10-01 決定。`docs/GLOSSARY.md`）。この資料は決定前に書いたので「流れ」のまま残す。読むときは「燃焼の流れ」→「燃焼系」、「流れの源 / 糧」→「系統の源 / 糧」と読み替える。

---

## 1. 思想

**「見台に載るのは、いつも 1 つだけ」**。見台は本を 1 冊だけ開いて載せる台。メニューを開くと、遺物・スキル・祝福・流れのどれか 1 つが画面の真ん中に大きく載り、それ以外は左右の「影」（前後の物のシルエット）と「位置の点」だけになる。

ごちゃごちゃの根は「どの画面も、一覧と詳細と関係を同時に置く」ことにある。見台は一覧を **文字で並べない**。並びは「繰る」動き（←→）と影で体に覚えさせ、全体像が要るときだけ画面を引いて **文字の無い点の絵（俯瞰・全景）** に切り替える。こうすると 1 画面の文字は 7 行前後に落ちる（今の装備タブは 30 行超）。比べる時だけ 2 枚目が隣に来て、しかも **違うところしか書かない**。

## 2. 情報の予算

### 2-1. 1 画面の上限

| 画面 | 文字の行（BODY 以上） | SMALL の行 | アイコン | 数字 | 備考 |
| --- | --- | --- | --- | --- | --- |
| 札（主役 1 枚） | 7 | 0 | 12 | 4 | 棚の名 1・名前 1・本文 4・操作 1 |
| 比べる（2 枚） | 9 | 0 | 14 | 6 | 本文は差だけ。各札 3 行まで |
| 俯瞰（棚を引いた点の絵） | 2 | 0 | 12 + 点の絵 | 1 | 点は 1 つの絵として数える |
| 全景（ビルドの絵） | 4 | 0 | 16 + 糸 | 3 | 流れの名は最大 3 |
| 3 択（祝福・芽） | 7 | 2 | 12 | 2 | 脇の 2 枚は名前だけ（SMALL） |

決まり:
- **本文に SMALL（8px）を使わない**。SMALL は影の名・3 択の脇の札・俯瞰のカーソル名だけ
- **画面の見出し・タブ・枠の名前を置かない**。棚の名は上帯の 1 つだけ（「装備」「スキル」…既存の用語）
- 銭・鍵・瓶・生命・気力はメニューに出さない（HUD にある。開いても HUD の上帯は透けて残す）

### 2-2. 溢れた情報の行き先

| 溢れたもの | 行き先 |
| --- | --- |
| 性質が 5 つ以上 | 4 行目を「ほか 2」にして **裏**（札を裏返した面。最大 8 行）へ。並びは種類の固定順（誓約 → 名のある性質 → 条件の族 → 変換）で、強さ順にはしない |
| 地金・揺らぎ・発見深度・来歴の数え・余白・銘 | 遺物の裏 |
| 計算式（原則 11）・段ごとの威力・怯み値 | **行動の札の裏**（その 1 つの行動の式だけ。全行動の表は作らない） |
| ステータスの出どころ・体の性能・耐性 | 体の札の裏 |
| 仕組みの説明（共鳴とは・研鑽とは） | `src/meta/tips.ts`（Tips ノート）。UI には書かない |
| 一覧・全体像 | 俯瞰（棚の点の絵）と全景（ビルドの絵）。どちらも文字はほぼ無し |
| 単一の強さ・総合の差 | どこにも出さない（原則 8） |

## 3. 骨組みと操作

### 3-1. 棚と札

画面の中身は **棚**（縦に並ぶ持ち物の種類）× **札**（棚の中の 1 物）の 2 軸だけ。

| 棚 | 札の並び | 寄ると（決定） |
| --- | --- | --- |
| 共鳴 | 段の立った流れ → あと 1 つの流れ（流れの札） | 源・糧の出どころの札へ |
| 装備 | 右手 / 頭 / 体 / 足 / 指輪 / 首飾り / 体の札（ステータス） | その部位の倉庫の棚へ |
| スキル | スロット 1〜4 | 符の穴へ / 石の在庫の棚へ |
| 祝福（ラン中のみ） | 行動の札 5（左 / 右 / ダッシュ / スキル / 奥義。加護が乗る）→ 常時の札（摂理・研鑽・真髄・芯・呪い付き） | 加護の札へ |

拠点では祝福の棚が消え、装備から潜る「倉庫」の棚が主になる。

### 3-2. 動詞（7 つ。キーは `core/input.ts` の `keyLabel` で表示）

| 動詞 | 既定（キー / パッド / マウス） | 中身 |
| --- | --- | --- |
| 繰る | ←→ / 十字左右・LB RB / ホイール・影のクリック | 同じ棚の前後の札へ。押し続けると加速（影が流れる） |
| 棚を替える | ↑↓ / 十字上下 | 別の棚へ。札は棚ごとに前の位置を覚える |
| 決定 | Enter / A / 主役のクリック | 寄る・付ける・持ち上げる / 置く。取り返しのつかない操作は長押し |
| 比べる | Shift 押している間 / Y 押している間 / 右クリック押している間 | 隣にもう 1 枚（3-3） |
| 裏返す | F / X / 主役のダブルクリック | 札の裏（溢れた情報）を見る。もう一度で表 |
| 引く / 寄る | Tab / LT RT / Ctrl+ホイール | 札 ⇄ 俯瞰 ⇄ 全景の 3 段 |
| 戻る | Esc / B / 右クリック | 1 段上へ。最上段で閉じる |

### 3-3. 比べる（2 枚目が来る唯一の場面）

- 比べる相手は自動で決まる: 倉庫の遺物 → 同じ部位の装備中 / 石 → 同じスロットの石 / 祝福の加護 → 乗る先の行動の札 / 持ち上げ中の符 → 置き先の穴
- **同じものは書かない**: 両方にある性質は「同じ 2」の 1 行に畳む。左（今）には失う性質だけを朱の − で、右（候補）には得る性質だけを金の + で、各 3 行まで
- 2 枚の間の下に **共鳴の変化** を最大 2 つ（「燃焼の流れ 2→3」「出血の流れ 1→0」）。地金とステータスの差は数字を出さず、変わる行動の印だけを ▲▼ で点す（詳しくは裏）
- 純関数の見積もりで state は変えない（決定の時だけ今の `loadoutDirty` → `captureLoadout` の経路）

### 3-4. 持ち上げて置く（符・注ぎ・移し）

2 つの物を結ぶ操作は全部「持ち上げる → 繰る → 置く」。持ち上げた物は画面の左上に 48px の小札で浮いたまま付いてくる（Balatro の札を摘んでいる感じ）。これが「もう 1 つ」の 2 番目の形。

## 6. 捨てるもの・諦めるもの

| 捨てる | 痛み | それでも成り立つ理由 |
| --- | --- | --- |
| 名前の一覧を目で走査する | 倉庫を「名前のリスト」で眺められない | このゲームは単一の強さを出さないので、一覧の並びで良し悪しは読めない。判断は常に「自分の今の物と比べてどうか」の 2 物比較で、見台はそこに最短で行く。眺めたいときは俯瞰で流れの島と色を見る |
| 全ステータス・性能の総覧 | 防御・耐性・到達を 1 画面で見られない | 原則 11 でステータスは行動ごとにしか意味がない。体の札の裏と行動の札の裏で、その 1 つの式として読む |
| 3 つ以上の同時比較 | 倉庫の候補 3 本を並べられない | 比べる相手は常に装備中（自動）。候補どうしは繰って影を見ながら 1 本ずつ当てる |
| マウスのホバーで瞬時に詳細 | 手数が少し増える | 影のクリックとホイールで繰れる。繰るは押し続けで加速し、絵が大きいので止める場所を絵で拾える |
| 共鳴の全 40 流れの表 | 「枯れている流れ」を一覧で探せない | 共鳴の棚は段の立った流れとあと 1 つだけ。枯れた流れは全景の糸が無いことで分かる |
| 前の案の灯（流れを灯す）・跳び・旅装 | 関係を辿る道具が減る | 全景の糸が関係の絵そのもの。流れの札から出どころへ寄るのが辿りの代わり |

一番大きい諦めは **速さより静けさを取る** こと。上級者の大量整理は俯瞰 + がらくたの一括でしのぐ。

## 7. 前の案（旅装）との決定的な違い

1. **家が無い**。旅装は「全体を 1 枚に並べた家」から潜る。見台は開くと 1 物が載り、全体は文字の一覧ではなく絵（俯瞰・全景）で、寄る / 引くの 3 段のズームで行き来する
2. **比べるのは差だけ**。旅装の「入れ替えると」は流れ・共鳴・行動・体・失う / 得る性質の全項目を並べた。見台は同じものを畳み、失う / 得る 3 行と共鳴の変化 2 つだけ。数字の差は裏へ
3. **本文の文字は 12px 以上だけ・1 画面 7 行**。旅装は 8px と 12px を詰めて 480px に多くを収める設計だった。見台は SMALL を本文に使わず、行数の上限で溢れを裏・俯瞰・Tips へ追い出す
