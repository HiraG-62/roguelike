# ラン構造・バリエーション・メタ進行 アイデア集

作成日: 2026-09-23
前提: 現状は「部屋 + 2 幅 L 字通路（`generateRoomsAndCorridors`）」「部屋ロック → 全滅 → 解放」「最後の部屋に階段」「敵 3 種（chaser / shooter / charger）」「永続装備（stash）」。

凡例: **コスト** S = 半日以内 / M = 1〜3 日 / L = 1 週間以上。**面白さ** ★1〜5。**触るファイル** は主なもの（新規は「新規」と明記）。

## 基本方針: 永続装備とラン内要素の住み分け

| 層 | 寿命 | 役割 | 例 |
| --- | --- | --- | --- |
| 永続装備（loot） | ラン跨ぎ | 「自分のビルドの土台」。数値と遊び方の方向性 | +projectiles、Glass Cannon |
| ラン内の祝福/呪い | 1 ラン | 「今回だけの変化球」。数値より **ルール変更** を優先 | 「ダッシュ終点に爆発」「部屋クリアで HP 全快だが最大 HP -10%」 |
| フロア修飾 | 1 フロア | 「今この階の癖」 | 暗闇、溶岩、崩落 |

原則: **ラン内要素は数値の上積みではなく、装備との掛け算を生むトリガー/ルールにする**。数値は装備側に任せ、ラン内は「装備のタグに反応する」形（例: 祝福「burn 中の敵を倒すと炎の輪」）にすると、同じ装備でも毎ラン違う遊びになる。ラン内要素は `PlayerStats` と別の `RunModifiers` に持ち、`computeStats(equipment)` の後に `applyRunModifiers(stats, run)` で畳み込む。

## 今すぐ入れるべき 5 つ

1. **部屋の種類（`RoomKind` 導入 + 宝物庫 / ミニボス / チャレンジ / 泉）** — コスト S〜M。今は全部屋が同じ戦闘で単調になりやすい。`RoomState` に kind を足すだけで、以降の祭壇・商人・秘密部屋の土台になり投資効率が最も高い。
2. **エリート修飾子（Explosive / Reflective / Shielded / Hasted / Linked）** — コスト S。敵 3 種のままでも組み合わせで戦闘の種類が数倍になる。既存 behavior に被せるだけなので安い。
3. **祝福 3 択（ルール変更系 Boon）** — コスト M。IDEAS.md の「アップグレード 3 択」を、永続装備と衝突しない「装備タグに反応するルール変更」として実装する。ランごとの差分を生む核。
4. **敵 4 種追加（shield knight / bomber goblin / laser eye / golem）** — コスト S〜M。すべて「テレグラフを読んで避け、隙を殴る」コンセプトに直結し、ダッシュ・近接・射撃・弾斬りそれぞれに役割を与える。
5. **追跡者（Stalker）+ 最初のボス King Slime** — コスト S + M。追跡者は少量のコードで「進め」という緊張を生み、ボスは 5 階という短い区切りのゴールを作る。ランに山場ができ、章ループの雛形になる。
