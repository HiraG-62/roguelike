作成日: 2026-09-24
前提: `docs/DESIGN_PRINCIPLES.md` / `IDEAS.md`「現状」/ `docs/ideas/README.md` / `docs/ideas/action-feel.md` / `docs/ideas/run-structure.md`（6 章メタ進行）/ `docs/LOOT_DESIGN.md` / `docs/GLOSSARY.md` と、`src/system/player.ts`・`src/loot/bases.ts`・`src/loot/affixes.ts`（IMPLICITS）・`src/loot/profile.ts`・`src/skills/persistence.ts`・`src/ui/title.ts`・`src/audio/sfxNames.ts` を読んだ。
今の実装の要点: 近接は `PLAYER.melee` の 3 段（箱型の当たり判定）+ ダッシュ攻撃の 1 種だけで、武器ベース 7 種 / 銃ベース 6 種は implicit の数値（攻撃速度・リーチ・弾数…）しか変えない。ラン外の永続は装備（`roguelike.profile.v1`、`meta` は runs / bestDepth / totalKills / bestScore / history 20 件）・スキル石・残響だけで、タイトル画面から直接ランに入る。
凡例: コスト S = 数時間 / M = 1〜2 日 / L = 数日以上。面白さ ★1〜5

## 0. この文書で使う新語（`docs/GLOSSARY.md` に未登録。採用時に足す）

| 武器種 | moveset | 武器スロットのベースが決める通常攻撃（左クリック）の型。段数・当たり判定の形・ダッシュ攻撃・溜め・マナ回収の傾向をまとめたもの |

| 住人 | resident | 拠点に住み着く NPC。設備の担い手で、強さは与えない |
| 図鑑 | codex | 見た・起きたものの記録（敵 / 遺物 / 祝福 / 反応） |
| 反応 | reaction | 状態異常の相互作用（燃焼 × 冷気 = 蒸発 など）。既存の仕組みに表示名を与えるだけ |

| 語り | tell | 遺物の来歴を住人に語る行為。語られた遺物に節目が 1 つ増える |

原則の確認: 武器種・射撃の型は **横並び（sidegrade）** で、上位互換を作らない。永続の報酬は「選択肢・表現・記録が増える」ものに限り、与ダメや HP の永続インフレは入れない。

## 1. 武器種（通常攻撃の型）12 種

> **実装済み（2026-09-24）**: 1-1 剣 / 1-2 大剣（3 段階の溜め）/ 1-3 双剣（5 段）/ 1-4 槍（穂先）/ 1-5 鎌（表示名「大鎌」、引き寄せ）/ 1-6 拳甲（表示名「拳」、ベース「手甲」、投げ）/ 1-7 鞭（先端）に加え、鉈（全段で壁叩きつけ）と棍（範囲・マナ回収）、1-11 杖（左で射撃・右で杖打ち）。剣以外は 4〜5 段、全武器種に左右の組み合わせのコンボ派生 2〜3 本・多段ヒット・踏み込み・残像（memo 20260924-1）。定義は `src/data/weapons.ts`（案の `movesets.ts` ではなく武器種と射撃の型を 1 ファイルに）、数値は tuning の `WEAPON`。1-8 戦鎚は鉈の型を割り当てた。1-9・1-10・1-12 は未実装

設計: 要追加 `BaseItemDef.moveset: MovesetKey`（`src/loot/bases.ts`）。型の定義は新規 `src/data/movesets.ts`（`MovesetDef { steps; dashAttack; charge?; manaMul; attackMoveMul }`）、数値は tuning の `MOVESET`。今の `PLAYER.melee` は `MOVESET.sword` に移す。当たり判定の形は要追加 `MeleeStep.shape: "box" | "arc" | "line" | "ring" | "cone"`（`meleeBox` を形ごとの判定に分ける）。溜めは要追加 `FrameInput.attackHeld` と `Player.attack.chargeTime`。既存ベースの割り当て: 短剣・小剣・長剣 → 剣、大剣 → 大剣、双剣 → 双剣、槍 → 槍、戦鎚 → 戦鎚。残りは新ベース。

## 最初に入れるべき 12 個

1. **武器種の枠と剣の移植（1-1）**: `PLAYER.melee` を `MovesetDef` に移し、`BaseItemDef.moveset` と当たり判定の形を足す。以後の武器種はデータを足すだけになる土台。
2. **大剣（1-2）**: 既存の大剣ベースに型を与えるだけ。溜め攻撃の入力（`attackHeld`）も同時に作れ、弓・銃剣・蓄光銃が流用できる。
3. **槍と双剣（1-4・1-3）**: 既存ベースの implicit（リーチ・攻撃速度）を型に格上げする。穂先と手数という正反対の手触りで横並びを示せる。
4. **鎌（1-5）**: 引き寄せは既存のノックバックの符号を反転するだけ。範囲スキルとバーストの価値を上げ、「集めて刈る」という新しい動詞になる。
5. **散弾・貫通・跳弾（2-3・2-4・2-6）**: 既存の銃ベースに割り当てるだけで、`tryShoot` の分岐で済む。跳弾は洞窟フロアと噛み合う。
6. **状態異常の見た目と死に方（7-2〜7-6）**: `statusUi.ts` に集中して入り、13 種の状態異常と反応が画面で読めるようになる。反応図鑑の前提。
7. **反応図鑑（4-5）**: `statusEffects.ts` の相互作用に記録を 1 行ずつ足すだけ。「？ × 冷気」の空欄がシナジー探しの最強の動機になる。
8. **依頼の最小形（5 章から 8 種）**: 拠点なしでもラン開始時の 3 択で始められる。撃破・怯み・状態異常の既存イベントを数えるだけ。
9. **敵図鑑と知識（4-2・4-8）**: 撃破数は `killsByEnemy` と同じ集計で取れる。予告の長さを変えずに読みやすさだけを育て、テレグラフ原則を守る。
10. **訓練場（3-4）**: 拠点の最小形。`createGame` を木人だけのフロアで回し、単一指標を出さずに武器種を試せる。武器種を増やすほど価値が上がる。
11. **遺物の光柱と響きの音（7-13・8-5）**: 描画と音の定義だけで、拾う前から遺物の色が伝わる。響き・共鳴の仕組みを体で覚えられる。
12. **封鎖で打楽器が入る曲（8-12）**: 既存の `roomLock` / `roomClear` の音を起点に層を足す。部屋ごとの山場を音楽でも作れる。
