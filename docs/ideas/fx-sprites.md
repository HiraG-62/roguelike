# エフェクトのスプライト化（高精細ドット絵・モーション専用）

作成日: 2026-09-25
状態: 基盤と剣（縦切り）を実装。他の武器・スキルは同じ手順で順に足す

## 1. 目的と決めたこと（ユーザーの判断）

- 攻撃・スキル・パーティクルなど、エフェクトをすべて手続きの図形から **専用のドット絵スプライト** に置き換える。汎用の使い回しで済ませず、武器・モーション・スキルごとに作り込む
- **描画の密度は 2 倍（960x540 相当）**。ゲームの座標（当たり判定・距離・ロジック・リプレイ）は 480x270 のまま変えない
- キャラ・タイル・UI の描き直しは **段階的に** 進める。途中はエフェクトだけ 2 倍の密度になり、ドットの粗さが混ざる
- 絵は **生成スクリプトで PNG に焼く**（`scripts/fx/`）。形・動き・色の段をコードで組み、1 枚ずつ目で確かめて詰める
- 進め方は **1 武器で縦に作り切る**（剣）。基準が固まってから横に広げる

## 2. 密度 2 倍の仕組み

- canvas の実ピクセルは、すでに「論理 1px = `pixelRatio` 実 px」（`renderMath.ts` の `computeViewScale`）。ウィンドウが 960x540 以上なら `pixelRatio` ≥ 2 になる
- エフェクトの絵は **絵の 1 ドット = 論理 0.5px**（`FX_ART_SCALE = 2`）。`drawImage` の描き先の大きさを絵の半分にして置くだけで、全体の作り替えは要らない
- 置く位置は 0.5px 単位に丸める（`snapHalf`）。絵のドットが実ピクセルの格子に乗る
- `pixelRatio` < 2 の小さなウィンドウでは、絵は最近傍で縮んで粗くなる（許容）

## 3. 生成器（`scripts/fx/`）

依存なし（Node 標準の `zlib` だけ）。生成物はコミットし、ビルド時には生成しない。**1 武器種 = 1 ファイル**で完結させ、武器種ごとに並列で作れるようにしてある（共有ファイルへの登録は要らない）。

| ファイル | 役割 |
| --- | --- |
| `png.mjs` | RGBA の PNG を書き出す・寸法を読む |
| `raster.mjs` | 1 枚の絵（段の番号の格子）を作る道具: 超標本化の塗り・段の量子化・順序ディザ・孤立ドットの掃除・座標ハッシュのばらつき |
| `shapes.mjs` | 形の部品: 三日月・レンズ形の斬線・弧 / 直線の速度線・輪・刃片・光点 |
| `motifs.mjs` | 複数の武器で使う時間割: 弧の斬撃（`arcSlash`）と、そのシートの作り方（`arcSheet`）。方向の数 `DIRS` |
| `pack.mjs` | 余白を切り詰めた全フレームを棚詰めで 1 枚に並べる |
| `sheets/<武器種>.mjs` | 武器種ごとのモーションの絵と、モーション → シートの表（`export const ATLAS = { key, sheets, fx }`。ファイル名 = key） |
| `gen.mjs` | `sheets/` を自動で集めて描き、`public/assets/fx/<key>.png` と `src/data/fx/<key>.gen.json`（寸法・矩形・表）、束ねる `src/data/fxSheets.gen.ts` を書く。`--atlas <key>` でその武器種だけ、`--only <シート> --preview <dir>` で確認用 PNG だけ、`--check` で最新か確かめる |

### 3.1 色は「段」で持ち、配色は実行時に差し替える

- PNG には色ではなく **段の番号**（1〜7。暗 → 明）を灰色で書く（R = G = B = 段 × 32）
- 実行時に **配色（ramp）** で段を色へ写す（`render/fxRamps.ts`）。既定の鋼（物理）と属性 6 種の 7 段の配色を持つ。属性が乗った剣は、同じ絵が炎や氷の色になる
- 配色はシートと配色の組ごとに初回だけ作ってキャッシュする（毎フレームの合成はしない）
- 段の使い方: 7 = 白い芯、6〜5 = 明部、4〜3 = 本体、2 = 縁の暗部、1 = 最暗の散り（煤・影）

### 3.2 方向は事前に描く（回転しない）

- ドット絵を任意角で回すとジャギーが崩れるので、**方向ごとに生成器で描き直す**（数式で描くので、どの角度でもドットが整う）
- 既定は 24 方向（15° 刻み、誤差 ±7.5°）。向きの無い絵（受け流しの閃光・巴）は 1 方向
- **振りの左右（時計回り / 反時計回り）は描き分けない**。反時計回りの角 θ の絵 = 時計回りの角 −θ の絵の上下反転。24 方向は −θ でも同じ組に乗るので、反転してもドットがずれない

### 3.3 詰め込みと原点

- 各フレームは不透明なドットの外接矩形に切り詰め、原点（pivot。絵の中の「振りの中心」や「当たり判定の中心」）からのずれを一覧に持つ
- 一覧（`src/data/fx/<key>.gen.json` を `fxSheets.gen.ts` が束ねる）: シートごとに `atlas`・`frames`（フレーム数）・`dirs`（方向数）・`active`・矩形の表 `[x, y, w, h, ox, oy]`（`dir * frames + frame` の順）と、武器種のモーションの表 `fx`
- テスト（`render/fxSprites.test.ts`）が一覧と PNG の寸法・矩形のはみ出し・件数と、表のある武器種が振りのモーション（左の段・ダッシュ・右の振り・派生・溜め）をすべて持つことを検査する

## 4. 実行時（`render/fxSprites.ts`）

- 装備中の武器種のアトラスだけを読み込み（`FxSpriteBank.focus`。失敗・未読み込みは今までの手続きの描画にフォールバック）、配色ごとのフレームを初めて描くときに作る
- `FxSpriteBank.draw(ctx, sheet, frame, x, y, angle, opts)`: 角を最寄りの方向に丸め、反時計回りは上下反転で引き、論理座標の 0.5px 格子に置く
- モーションの key（`fxMotions.ts` の `motionKey`）: ダッシュ攻撃 `dash` → 派生 `branch:<key>` → 溜め攻撃 `charge` → 右の段 `r:<key>` → 左の段 `l:<段>`（`player.ts` の `stepDef` と同じ順）。右の段の構え・投げ・溜め、杖の詠唱は対象外（手続きの描画）
- 時刻は `state.time` から数える（ヒットストップで止まる）。`state` は読むだけ、`state.rng` も使わない（不変条件 1〜3）
- 当たり判定の大きさ（`meleeReachMul` などで伸びる）と絵の基準の大きさが違うときは、描き先を比で拡縮する（基準から ±15% 以内なら拡縮しない＝ドットを崩さない）

## 7. 分かっている代償

- メモリ: 1 武器種のアトラスは展開後およそ 40MB。実行時は装備中の武器種のアトラスだけを読み、持ち替えたら前の分を捨てる（`FxSpriteBank.focus`）。持ち替えた直後の数フレームは読み込み中で、今までの手続きの描画になる
- 当たり判定が大きく伸びた装備（±15% 超）では絵を拡縮するので、ドットがわずかに崩れる。必要になったら大きさの段（大・特大）を生成する
- 描き直すまでは、キャラ（24px）とエフェクト（2 倍密度）でドットの粗さが違う
