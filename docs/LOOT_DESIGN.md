# ハクスラ装備システム 設計メモ（響き・揺らぎ・来歴）

目的: ローグライク（ランごとのランダムフロア・パーマデス）に、**永続する装備ドロップ** を融合する。
「同じアイテムが 2 つ出る方が珍しい」レベルの無限バリエーションを目指す。
PoE 由来の骨格（prefix / suffix・tier・rarity・Chaos / Exalt 型の通貨）は 2026-09 に撤去し、
docs/ideas/loot-identity.md の推奨案「揺らぎ・来歴」に置き換えた。段取り 7d（2026-09-30）で、色の配合の共鳴を「源と糧の共鳴」に置き換え、性質・誓約・名のある遺物・残響を絞り直した（`docs/ideas/relics-7d-plan.md`）。

## 設計哲学: 「ゴール装備」を作らない

ハクスラやモンハンにある「これを作れば最強」というテンプレ（BiS）を潰す。各プレイヤーが自分だけの最強を追い、しかもそれらに優劣が付かない状態を目指す。そのための仕組み:

1. **トレードオフ**: 強い性質ほど代償を持つ（例: +melee damage / -attack speed、+projectiles / -damage per projectile）。純粋な上位互換を作らない
2. **逓減（ソフトキャップ）**: 同じ数値を積むほど伸びが鈍る（`computeStats` で +100% を超えた分は sqrt 圧縮など）。1 種類を盛るより組み合わせる方が強い
3. **誓約（旧キーストーン）**: 遊び方そのものを変える大型改造（例: 硝子の砲 = ダメージ 2 倍 / 最大生命 1/4、瞬歩 = ダッシュがテレポート化して着地で爆発するが無敵なし、虚心 = コンボが加算されず、当てずにいた後の 1 撃が大きな倍、不殺 = 怯んでいない敵は倒しきれない）。系統ごとの排他があり、同時に成立しない組み合わせがある
4. **トリガー文法**: `trigger × condition × effect` の組み合わせで性質を生成する（例: "見切り時 → 次の 3 ヒットが燃える"、"コンボ 10 以上のとき → 5 ヒットごとに衝撃波"）。固定リストではなく文法なので組み合わせは事実上無限。性質の大半は「条件の族」（条件が代償）か「行動」（何かが起きる）で、無条件の数値だけの性質は作らない（数値は地金）
5. **シナジーの網**: 元素・コンボ・ダッシュ・射撃・近接がタグで相互作用し（burn は attack speed で伸びる、chill は shatter を可能にする、shock は弾数で連鎖が増える…）、局所最適が無数にある
6. **比較不能な多次元**: アイテムスコアや DPS 数値を UI に出さない。ツールチップは「何ができるか」を語る
7. **源と糧の共鳴**（追加）: 同じ語（燃焼・近接など）を起こす出どころ（源）と、その語を条件に強くなる出どころ（糧）がそろうと、その語に段が立つ。数えるのは遺物だけでなくスキル石・祝福・流儀・武器の型・改鋳・誓約なので、装備だけで最適解は決まらない。色は共鳴に関わらない
8. **揺らぎと反転**（追加）: 深層の遺物は「強い」のではなく「荒い」。最上振れを狙うと反転の危険を背負う
9. **来歴の分岐**（追加）: 性質が増えるのは使い込んだ末の芽吹きだけ。芽は 2 択で、捨てた枝は戻らない

## 原則

- アイテムは **ランを跨いで永続**。拾った瞬間に stash（localStorage）へ保存される。死んでも失わない
- 装備は次のランの開始時に `computeStats(equipment)` で `PlayerStats` に畳み込まれ、ゲームロジックはその数値だけを見る
- 生成は **純関数 + seedable RNG**。同じ seed / 深度なら同じアイテム。芽の候補も `item.seed + 節目` から決まり、`state.rng` を消費しない
- データ駆動: 性質とベースは `src/loot/affixes.ts` / `src/loot/bases.ts` に列挙し、追加が容易であること
- 型は `src/loot/types.ts` に集約。旧フィールド（`AffixRoll.kind` / `tier`）は旧セーブ互換のため optional で残す
- 性質・転じは `AffixDef.keywords`（共鳴の数えに使う語。出す / 食う / 強める）を必ず持つ。名のある遺物は `UniqueDef.keywords`

## 用語

| 用語 | 内部名 | 意味 |
| --- | --- | --- |
| 遺物 | `Item` | 装備アイテム全般 |
| 性質 | `AffixRoll`（旧 affix） | アイテムに宿る 1 つの性質。表の性質 / トリガー文法 / 変換 / 誓約 |
| 色 | `TraitColor` | 紅 crimson / 蒼 azure / 翠 jade / 金 gold / 冥 umbra。性質・遺物の分類（効果は決めない） |
| 期待値 | `nominal` | 発見深度で決まる、その性質の標準的な強さ |
| 揺らぎ | `flux` | 期待値からの相対的なずれ。`value = nominal × (1 + flux)` |
| 反転 | `inverted` | flux < -1 で値が負になった性質。色は冥。共鳴の数えには入らない |
| 余白 | `margin` | まだ芽吹ける数 |
| 来歴 | `provenance` | 装備中に起きた出来事の記録 |
| 節目 | `MILESTONES` | 来歴の閾値。到達で芽が出る |
| 芽 | `budOffer` / `buds` | 節目で出る 2 択の成長。選ばなかった方は消える |
| 銘 | `inscription` | 余白を使い切ったアイテムに来歴から刻まれる名前 |
| 共鳴 | `ResonanceStep`（`boonRun.resonance`） | 同じ語の源と糧がそろうと立つ段。語ごとに独立（`system/resonance.ts`） |
| 誓約 | `ks_`（旧 keystone） | 冥色の、遊び方を変える性質（20 種） |
| 名のある遺物 | `namedKey`（旧 unique） | 固有の効果を持つ遺物 18 種（`loot/named.ts`）。性質は固定で、値は小さく揺らぐ |
| 残響 | `EchoWallet` | 分解で得る色ごとの素材（紅響 / 蒼響 / 翠響 / 金響 / 冥響）。操作は 5 つ |

## スロット（右手・左手・頭・体・足・指輪・首飾り）

| slot | ベース例 | 役割 |
| --- | --- | --- |
| weapon | dagger / shortsword / longsword / greatsword / spear | 近接の基礎ダメージ・速度・リーチ |
| gun | pistol / smg / rifle / shotgun | 射撃の基礎ダメージ・連射・弾数・貫通 |
| head（頭） | hood / leatherCap / ironHelm / circlet / maskedVisor ほか | 体の性質を引く（`affixes.ts` の `SLOT_ALIAS`） |
| armor（体） | cloth / leather / chain / plate | 生命・防御力・被ダメ軽減 |
| boots（足） | sandals / boots / greaves | 移動速度・ダッシュ |
| ring | ring 系 | 何でも（クリティカル、元素、吸血…） |
| amulet | amulet 系 | 何でも（ユーティリティ寄り） |

**地金**（`Item.innate`、`loot/innate.ts`）: 性質とは別に、どの装備にも既定で宿るステータス・防御力・属性耐性の層。深度で大きくなりやすい予算（点）をランダムに決め、それを「項目数」と「値」に配るので、値も項目数も両方多い遺物は出にくい。防具は防御力が必ず付き（体は高め・指輪と首飾りは低め）、部位ごとに出やすいステータスがある（頭 = 筋力・技巧 / 体 = 体力 / 足 = 技巧・体力 / 指輪 = 精神 / 首飾り = 霊力）。武器はその武器種の主参照のステータスが出やすい。段取り 7d で「無条件の数値だけの性質」（近接ダメージ・最大生命・攻撃速度・気力の各種など）はここへ移した（性質の行は `INNATE_LINE_DEFS` に残し、抽選には出さない）。余白・来歴・クラフトの対象外。数値は `src/data/balance/loot/INNATE/`。借り物・初期武器（plain）と旧セーブの遺物には付かない

ベースは `implicit`（固定の暗黙補正 + ロール幅）と **色の傾き**（`colors.ts` の `BASE_LEAN`。生成時にその色の性質が 2 倍選ばれやすい）を持つ。implicit は色を持たず、共鳴の数えにも入らない。

## 色（分類）と源と糧の共鳴（`src/loot/colors.ts` / `src/system/resonance.ts`）

### 5 色は分類

紅 / 蒼 / 翠 / 金 / 冥は性質・遺物の分類で、効果は決めない（段取り 7d で、色の配合で発現する共鳴・三和音・星座・陰画・拮抗を廃止）。使い道は 遺物の色の帯（`itemColorBar`）・金床の色（`dominantTraitColor` = 装備の性質の色で最も多い色）・残響の色・生成時の偏り（ベースの傾き `BASE_LEAN`）・彩痕の 5 色。

| 色 | 担う性質 |
| --- | --- |
| 紅 | 近接・与ダメージ・炎 |
| 蒼 | 射撃・機動・冷気・気力 |
| 翠 | 生存・回復 |
| 金 | 奥義・コンボ・会心・雷 |
| 冥 | 誓約・呪い（重い代償）・反転した性質 |

性質の色は定義の `color`、無ければ tags から決める（`colorFromTags`）。tag `mana` は他の tag より優先して蒼。トリガー文法は効果と起点から決める（`triggerColor`）。生成時に 10% で **異色**（既定と別の色）になる。

### 源と糧の共鳴

語（`core/keywords.ts` の `Keyword`。燃焼・近接・ダッシュ・瀕死など）ごとに、その語を出す出どころ（源）と食う出どころ（糧）、強める出どころ（強め）を数え、そろった語に段を立てる。

| 出どころ（それぞれ 1 と数える） | 語の出所 |
| --- | --- |
| 遺物（装備 1 部位） | 性質・転じの `AffixDef.keywords`、誓約の性質は `KEYSTONE_FACTS`、トリガーの性質は起点・効果、名のある遺物は `UniqueDef.keywords`。地金・implicit は数えない |
| スキル石（スロット 1 つ） | `skillKeywords`（ラン内の刻印符込み） |
| 祝福（1 枚） | `BoonDef.keywords` |
| 流儀 | `JobDef.keywords` |
| 武器の型 | `FormDef.keywords`（今の武器種の型） |
| 改鋳（1 つ） | `ReforgeDef.keywords`（持ち替えた型の改鋳は数えない） |
| ラン内の誓約（起点・祭壇・闇市） | `keystoneKeywords` |

- 出どころ 1 つにつき、語ごと・動詞ごとに最大 1 と数える（同じ遺物の性質が 2 つ燃焼を出しても源 1）。素手の起点で装備が封じられている間の遺物は数えない
- 段（`resonanceStepOf`）: 源 `RESONANCE.minSources`（2）以上かつ糧 `minSinks`（2）以上で 1 段。源 + 糧の合計が `stepEvery`（3）増えるごと、強め 1 つごと（`amplifyStep`）に +1 段。上限 `maxSteps`（3）
- 効果（`resonanceModifiers` / `applyResonanceStats`）: 語ごとに倍（1 語 1 出所 `resonance:<語>`。`more = 1 + (stepMul − 1) × 段`、1.15 / 1.30 / 1.45）。倍を掛けるタグは `KEYWORD_TAG`（burn → fire、melee → melee、stagger → vsStaggered など。脆弱・撃破・瀕死・被弾など対応するタグの無い語は与ダメ全部）。倍の無い語（ダッシュ・見切り・気力・回復・障壁）は `KEYWORD_STAT` で stats に足す（量は `RESONANCE.statPerStep`）
- 数えない語（`RESONANCE_EXCLUDED`）: 5 色・反転・無属性
- 数え直し: `refreshResonance(state)` が `boonRun.resonance` を作り直す。`applyStats`（装備・祝福・改鋳・階の移動）と、ラン内の刻印符の付け外し（`system/skills.ts`）から呼ぶ
- 読む側: 彩刻・色解き・彩りは「共鳴している状態異常の語の色」（`resonantHue`。紅 = 燃焼 / 蒼 = 冷気 / 翠 = 毒 / 金 = 感電 / 冥 = 脆弱。無ければ `state.rng`）、彩痕の被ダメ増（`hueResonates`）、部屋「共鳴炉」（何かが共鳴していれば報酬増）、HUD の「共鳴 燃焼 2・感電 1」（`resonanceSummary`）、流れタブの「共鳴中: 燃焼 2 段（源 3・糧 2・強め 1）」、纏い（共鳴している語の色）
- 数値は `src/data/balance/loot/RESONANCE.json`（`data/tuning.ts` の `RESONANCE`）。共鳴専用の戦闘コードは無い

## 揺らぎ（`src/loot/flux.ts`）

- **期待値**: 性質の期待値曲線（旧 tier 表を「深度 → 幅の中央」の点列として読んだもの）を深度で線形補間する。最後の点より深いときは **最後の区間の傾きで線形に伸ばす**（深度 26・30 の頭打ちを外す。最後の点の値は下回らない。`nominalAt`）。点列そのものは触らない
- **強さの係数**（2026-09-24、memo「序盤から装備が強すぎて 5 層くらいまでヌルゲー化する」）: 生成時の期待値に `FLUX.globalScale`（0.8）× `depthScale(深度)`（深度 1: 0.75 → 深度 5: 0.85 → 深度 10 以降: 1 を線形補間）を掛ける。深度 1 で 0.6、深度 5 で 0.68、深度 10 以降で 0.8。`affixes.ts` の点列は触らず、係数だけで全体を締める（`flux.ts` の `powerScaleAt` / `scaledNominalAt`、`generator.ts` の `rollTableTrait` / `rollTriggerTrait`）。変換の性質は割合なので掛けない。既に拾った遺物の値は変わらない
- **揺らぎ**: σ = min(0.12 + 0.05 × 深度, 1.0) ×（1 + 0.1 × boost）。flux は三角分布（-0.4σ, 0, +0.8σ）で、下限は -0.4。値は期待値の 0.6〜1.8 倍に収まる（下振れを狭め、上に長い。旧: -1.3σ / +1.5σ / 下限 -0.9）。下振れが消えたぶん平均は少し上がる（三角分布の平均は +0.13σ）ので、相殺するなら `globalScale`（0.8）で行う（つまみ。決めるのは QA）。数値は `src/data/balance/loot/FLUX.json`（`data/tuning.ts` の `FLUX`）
- **反転**: 発見深度 13 以降、表の性質（変換・トリガー以外）が 4% + 1%/深度（上限 15%）で反転する。|値| は期待値の 20〜90%、色は冥
- **性質の数**: 期待値 min(1 + 0.12 × 深度, 3.5) + 三角分布（半幅は 1 → 2 へ深度で広がる）を 0〜5 に収める
- **余白**: 5 - 性質の数（+ 揺らぎ -1..0）を 1〜4 に収める。性質が少ない遺物ほど育てる余地が大きい
- **中身**: 各性質は 25% でトリガー文法、外れたら 10% で変換（1 アイテム 1 つまで）、それ以外は表から。性質 3 以上なら 8% で 1 つを誓約に置き換える
- **見た目の分類**（旧 rarity のキーを流用。格付けではない）: 反転あり → `unique`「反転あり」、|flux| の最大が 0.21 以上 → `rare`「荒」、0.07 以上 → `magic`「揺」、それ未満 → `normal`「静」（`FLUX.class`。flux の幅を狭めたとき、静・揺・荒の割合が変わらないよう境界も縮めた。旧 0.15 / 0.45）

## 来歴と芽（`src/loot/provenance.ts`）

- `recordProvenance(state, event)` を combat / floor から呼び、**装備中の全アイテム** の来歴を進める（撃破〔敵種別・ボス〕/ 見切り / 被弾 / 部屋制圧 / 階層踏破 / 最深）
- 節目（表の順に判定）: 撃破 50 / 見切り 20 / 被弾 40 / ボス 1 / 階層 10 / 部屋 25 / 撃破 200 / 見切り 60 / 被弾 150 / ボス 3 / 階層 30 / 撃破 500 / 怯ませた 100・400 / カウンター 30・120 / スキル発動 300・1200 / 精鋭撃破 30 / 殲滅 20 / 盾騎士撃破 30 / 爆弾ゴブリン撃破 40 / 弱点を突いた 150・600 / 耐性に阻まれた 150 / 地形の上の撃破 60・250 / 得意武器での撃破 150・600 / 溜めの命中 100 / 派生の命中 150 / 帰還 1（`MILESTONES`）
- 余白が 1 以上で提示中の芽が無ければ、到達済み・未提示の最初の節目で **芽（2 択）** を出す。片方は節目の色、もう片方は反対色（紅↔蒼、翠↔金、冥→翠）。候補は `item.seed + 節目` から決まる純関数
- 過去に出た候補の key（選ばなかった方を含む）は二度と出ない
- **目覚め**: 節目の一部は芽の片方を、名指しした性質にする（`MilestoneDef.awakening`。例: 階層踏破 10 → 残り火）。目覚め専用の性質は段取り 7d で無くなり、残る性質だけを名指しする。節目の key は変えない（到達済みの遺物に芽が出直さない）。印章指輪は来歴を 2 倍で積む
- 芽は `Item.budOffer` に保存され（ランを跨いで残る）、装備中のものは `state.pendingBud` に載る。UI が表示し、`chooseBud(state, index)`（`src/system/loot.ts`）で選ぶ。選ぶと性質が `origin: "bud"` で加わり、余白が 1 減り、stats を畳み込み直す
- 余白が 0 になると来歴から **銘** を刻む（`names.ts` の `engraveName`）。最も目立つ来歴が名詞、2 番目が修飾（例:「見切りのスライム喰らい」「王殺しの不屈」）

## クラフト（残響。`src/loot/crafting.ts`）

原則: **ランダムに性質を足す操作は無い**。性質が増える経路は芽だけ。

| 操作 | 素材 | 中身 |
| --- | --- | --- |
| 砕く | なし | 遺物を分解し、性質 1 つにつきその色の残響を 1 得る（性質が無ければベースの傾きの色を 1） |
| 注ぎ | なし | 遺物を捧げ、来歴の半分（切り捨て、最深は深い方）を同じ部位の別の遺物へ注ぐ。捧げた遺物は消える。届いた節目の芽はその場で出る |
| 移し | 冥響 3 | 銘か芽吹いた性質 1 つを、同じ部位の別の遺物へ移す。元の遺物は消え、受け手の余白を 1 使う |
| 呼び戻し | 冥響 5 | 過去の芽で選ばなかった方を取り直し、選んでいた方を失う（`BudChoice.recalled`）。1 つの遺物に 1 回 |
| 煽り | 冥響 2 | 揺らぎを σ × 1.2 で引き直す。反転の危険がある（最低 10%） |

段取り 7d で 12 → 5 に絞った（廃止: 染め・鎮め・削ぎ・転調・脱色・鍛え直し・張り）。性質の色や余白を作り替える操作は無く、性質が増える経路は芽だけ。`Item.reforged` と `AffixRoll.colorless` / `tensed` は旧セーブの読み込みのために型に残す（読み捨て）。

乱数は専用 RNG（`item.id + クラフト回数`）で決定的。通貨不足・成立しない操作は拒否し、何も消費しない。
残響とクラフト回数は `roguelike.craft.v1`（version 2）に保存する。

## 名前（`src/loot/names.ts`）

- 銘があれば銘
- 名のある遺物は固有名
- それ以外は「{最も多い色の形容}{ベース名}」（例「紅を帯びた長剣」）。性質が無ければベース名

## 段取り 7d の性質・転じ・誓約・名のある遺物（`docs/ideas/relics-7d-plan.md`）

- **件数**: 性質 212 → 71（条件の族 25・行動 43・来歴 3）/ 転じ 12 + 属性の変換 6 / 誓約 37 → 20（系統 7）/ 名のある遺物 76 → 18 / 残響の操作 12 → 5。旧セーブの遺物は `loot/migrate.ts` の `LEGACY_AFFIX_MAP` / `LEGACY_UNIQUE_MAP` で写す（下の「旧セーブの移行」）
- **条件の族**（25。`AffixTag` の `condition`）: 「怯み中の敵へ」「瀕死の間」「終撃の与ダメージ」「応手の後 2 秒」のように、条件そのものが代償なので代償の欄を持たない。`apply` は `s.modifiers` に Modifier を足すか、条件付きの欄（`increased.vsStaggered` など）を動かす。owner は `{ kind: "item", key }`。見本は `purse`（懐）

- **来歴**（3）: 若木・歴戦・古傷。装備全体・その遺物の来歴で値が育つ（`loot/traitContext.ts`）

## PlayerStats（派生値）

`types.ts` の `PlayerStats` と `DEFAULT_STATS` を参照。ゲームロジック側は **必ず** `state.stats` を通して読む。
`computeStats` の順序: 誓約の排他 → 地金・implicit・性質の段階適用（flat → scale → convert）→ 名のある遺物の固有（`applyNamedRelics`）→ ソフトキャップ → 誓約 → 整数化・クランプ。源と糧の共鳴は装備の外（スキル石・祝福・流儀・型・改鋳）も数えるので、ここではなく `applyStats` が畳む（`system/resonance.ts`）。

## ドロップ（`src/system/loot.ts`）

- 方針（2026-09-24）: 「たくさん倒しても出ない、強敵を倒すと出る」。通常敵と部屋制圧を絞り、精鋭・ボス・巣窟の主・宝物庫・試練は据え置く
- 敵撃破: 敵ごとの `dropChance`（3〜30%）+ 深度 × 0.5% に、通常敵は深度別の倍率 `LOOT_DROP.mobDropMulByDepth`、徘徊・増援（`roomIndex = ROAMING_ROOM`）はさらに `roamingDropMul` ×0.5 を掛ける。エリートは `eliteDropMul` ×0.35（追加抽選にも効く）。ボス・巣窟の主（確定）は掛けない

| 深度 | 1 | 2 | 3 | 4 以降 |
| --- | --- | --- | --- | --- |
| 通常敵の倍率 | ×0.1 | ×0.12 | ×0.15 | ×0.2 |
| 部屋制圧で報酬が出る確率（`roomClearChanceByDepth`、旧: 必ず 1 個） | 10% | 12% | 15% | 20% |

- 階層到達の報酬は `depthArrivalChance` 35%（旧: 必ず 1 個）
- 経緯（QA 0.0.7α → 再調整）: 開放型フロアで塊の制圧と撃破の回数が増え、1 run の拾得数が前回（80b26cf）比 1.5〜2.6 倍になった。撃破あたりの落下は 4〜7%、徘徊・増援の撃破は全撃破の 1〜2 割で主因ではなく、通常敵・エリート・部屋制圧・階層到達を一律に絞って 6 装備合計で前回比 67% にした
- 特別な報酬（共鳴炉・増援の撃退・狂月）は `dropBonusReward` で必ず 1 個（呼び出し側の差し替えは統合待ち。差し替えるまでは部屋制圧と同じ確率）
- 宝物庫・試練・ボスは boost（揺らぎの増幅）が大きく、荒い遺物や名のある遺物が出やすい
- 生成深度 = depth + rng(0..2)
- 格付けの抽選は無い。深さが期待値・揺らぎ幅・性質の数を決める
- 床のアイテムは光柱 + 名前ラベル。触れると即 stash へ（ログとフローティングテキストは最も多い色）

## 旧セーブの移行

アイテムとクラフト通貨はそれぞれ別キーで、別の場所で移行する。どちらも冪等（新形式ならフィールドを補うだけ）。

**アイテム**（`src/loot/migrate.ts`）: `loadProfile`（`src/loot/profile.ts`）がアイテム単位で旧形式（`provenance` を持たない）を検出し、`migrateItem` で変換する。プロフィールのキー `roguelike.profile.v1` と version 1 は据え置き。

- tier → 揺らぎ: T1 +0.4 / T2 +0.2 / T3 0 / T4 -0.1 / T5 -0.2 / T6 -0.3。期待値は |value| / (1 + flux) で逆算（値は変えない）
- 負の値（旧 Corrupt）→ 反転（冥）。腐敗の印は捨てる
- 旧 rarity → 余白: normal 4 / magic 3 / rare 2 / unique 1
- 旧 rare の 2 語名は銘として残す。旧 unique は固有名から名のある遺物の key を引く
- `lifeOnHit`（旧: 命中ごとの固定回復）は与ダメの % に換算する（×1.5、`LEGACY_LIFE_ON_HIT_PCT_PER_FLAT`）。新形式で固定値だった頃のアイテムは印が無く見分けられないため、値をそのまま % として読む（旧曲線 1〜5 と新曲線 2〜8% の幅はほぼ重なる）

- 段取り 7d の写し（`applyRelicMigration`。どちらの形式も最後に通す。冪等で、セーブのキーは v1 のまま）: 消えた性質・誓約は消して余白 +1（近い性質へ写すものは写し先の期待値で取り直す。`LEGACY_AFFIX_MAP`）。消えた名のある遺物は写し先が同じ部位・ベースの 8 つだけ新しい名のある遺物に写し（`LEGACY_UNIQUE_MAP`）、残りは `namedKey` を外して普通の遺物にし、旧い固有名は銘に写す。図鑑の遺物の記録と依頼の報酬（名のある遺物）も同じ表で写す。実績「名のある遺物 25 種」は閾値を 18 に

**クラフト通貨**（`src/loot/crafting.ts` の `convertLegacyWallet` / `src/loot/craftingStore.ts`）: `roguelike.craft.v1` の version 1（旧通貨 dust / shard / essence / relic）を読み込み時に残響へ換算する。1 / 2 / 4 / 8 点として合計し、5 色へ均等に配る（余りは色の並び順に 1 ずつ）。旧クラフト API（`craft` / `CRAFT_OPS` / `Wallet`）は撤去済みで、この換算だけが移行のために残る。version を 2 に上げて保存し直すと旧 wallet は消える

## UI（担当: src/ui・src/render）

- 表示情報は `describeItem(item)`（名前・副題・一言・色の帯・性質の行〔色・反転・芽・揺らぎ段階〕・余白・来歴の年表・銘）を使う。共鳴は装備画面の紋（`ui/crest.ts`）と HUD が出す
- 装備画面の装束（`ui/attire.ts`）と候補（`ui/candidates.ts`）: 6 部位と腰の石から着る物を選び、倉庫の候補を 5 枚ずつ並べる。全文は書付（`ui/sheet.ts` / `render/sheetUi.ts`）が `describeItem` をそのまま行にする（名前 → 銘 → 副題 → 一言 → 固有 → 性質 → 余白 → 誓約の競合 → 来歴。`render/itemTips.ts`）。遺物 1 つの色の帯（`lootUiParts.ts`）を札の左端に出す。誓約の競合があれば先頭に警告を出す
- 芽（`render/budUi.ts`）: 戦闘中は右下に一定秒数だけ 2 択カードを出し、以後は点滅アイコンだけに切り替える。装備画面では芽のある部位の候補の先頭に並ぶ「芽吹き」の 2 択の札（`ui/candidates.ts`）。提示は `state.pendingBud`、選択は `chooseBud(state, index)`
- 鍛冶の手続き（`ui/forge.ts`）: 役割（対象 → 操作 → 性質〔・色 / 移し先〕→ 実行）を書付の下端（`ui/sheet.ts`）と拠点の金床の構え（`ui/anvil.ts`）が使う。注ぎ・煽り・移し・呼び戻しは装備中の遺物にも使え、砕くのは倉庫の遺物だけ（長押し）。実行するまで何も消費しない。クラフト本体は `craftEcho` / `applyEchoResult` / `ECHO_OPS` / `ECHO_LABEL` / `ECHO_OP_LABEL`
- 装備画面の共通部品は `render/lootUiParts.ts`（色の定数・性質の行・枠）に集約
